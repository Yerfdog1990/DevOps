# Git Complete Reference & Cheat Sheet

## 1. Getting Started

```bash
git init                        # Initialize a new local repository
git clone <url>                 # Clone an existing remote repository (full copy)
```

---

## 2. Configuring Git

```bash
git config user.name 'Your Name'                    # Set username (local repo)
git config user.email 'you@email.com'               # Set email (local repo)
git config --global user.name 'Your Name'           # Set username (all repos)
git config --global user.email 'you@email'          # Set email (all repos)
git config --global alias.st status                 # Create alias: git st = git status
git config --global alias.glog "log --graph --oneline"  # Create alias: git glog
git config --system core.editor vim                 # Set default editor for all users
git config --global --edit                          # Open global config in text editor
man git-config                                      # See all possible config options
```

### Important Config Files

| File | Scope |
|---|---|
| `.git/config` | Local — applies to current repo only |
| `~/.gitconfig` | Global — applies to all repos on this machine |
| `.gitignore` | List of files/patterns Git should ignore |

---

## 3. Staging — Preparing to Commit

```bash
git add <file>              # Stage a specific file
git add .                   # Stage ALL untracked and modified files
git add -p                  # Interactively choose which parts of a file to stage
git mv <old> <new>          # Move or rename a file (Git-aware)
git rm <file>               # Delete a file and stage the deletion
git rm --cached <file>      # Tell Git to stop tracking a file (without deleting it)
git reset <file>            # Unstage a specific file (keep changes)
git reset                   # Unstage everything (keep changes)
git status                  # Show what is staged, unstaged, and untracked
```

---

## 4. Making Commits

```bash
git commit                      # Open text editor to write commit message
git commit -m 'message'         # Commit with inline message
git commit -am 'message'        # Stage all modified files AND commit in one step
git commit --amend              # Edit last commit message or add a forgotten file
```

> `git commit -am` only stages **tracked modified** files — it won't stage brand new (untracked) files. Use `git add` first for those.

---

## 5. Branching

```bash
git branch                          # List all local branches (* = current)
git branch --sort=-committerdate    # List branches by most recently committed
git switch <name>                   # Switch to a branch (modern)
git checkout <name>                 # Switch to a branch (classic)
git switch -c <name>                # Create AND switch to a new branch (modern)
git checkout -b <name>              # Create AND switch to a new branch (classic)
git branch -d <name>                # Delete a branch (safe — must be merged first)
git branch -D <name>                # Force delete a branch (even if not merged)
```

---

## 6. Ways to Reference a Commit

Anywhere a command accepts `<commit>`, you can use any of these:

| Reference | Example | Meaning |
|---|---|---|
| Branch name | `main` | Latest commit on that branch |
| Tag name | `v0.1` | The commit tagged as v0.1 |
| Commit ID | `3e887ab` | That specific commit |
| Remote branch | `origin/main` | Latest commit on remote main |
| HEAD | `HEAD` | Your current commit |
| Relative | `HEAD~3` or `HEAD^^^` | 3 commits before current |

## 7. Viewing Differences — `git diff`

```bash
git diff                        # Show unstaged changes only
git diff --staged               # Show staged changes only (same as --cached)
git diff HEAD                   # Show ALL staged and unstaged changes combined

git show <commit>               # Show diff between a commit and its parent
git diff <commit1> <commit2>    # Compare two commits
git diff <commit> <file>        # Show how a file changed since a specific commit
git diff <commit> --stat        # Summary of what files changed (not the full diff)
git show <commit> --stat        # Same summary from a single commit
```

---

## 8. Discarding Changes (Rollback)

```bash
# Before staging
git restore <file>                          # Discard unstaged changes to one file
git checkout <file>                         # Same (classic alternative)

# Staged + unstaged (full file rollback)
git restore --staged --worktree <file>      # Discard ALL changes to one file
git checkout HEAD <file>                    # Same (classic alternative)

# All staged and unstaged
git reset --hard                            # Discard ALL changes in working tree

# Move branch tip to a specific commit (staging area resets, working dir unchanged)
git reset <commit>                          # Move branch pointer back, keep files
git reset --hard <commit>                   # Move branch pointer back, delete all changes after it

# Untracked files
git clean -n                                # Preview which untracked files would be removed
git clean -f                                # Actually delete untracked files
git clean -fd                               # Delete untracked files AND directories
git clean -fx                               # Delete untracked AND ignored files

# Stash changes temporarily
git stash                                   # Save staged + unstaged changes for later
```

> `git clean -n` is a dry run — always preview before using `-f` to avoid deleting files you need.
> `git reset <commit>` moves the branch pointer backward and resets the staging area, but leaves your working files unchanged — useful for re-staging only what you want.

## 9. Edit History (Advanced)

```bash
git reset HEAD^                     # Undo the most recent commit (keep changes)
git rebase -i HEAD~6                # Squash the last 5 commits into one (interactive)
git commit --amend                  # Edit last commit message or add forgotten file
```

### Squashing Commits with Interactive Rebase

```bash
git rebase -i HEAD~6
# Opens editor showing last 5 commits
# Change "pick" to "fixup" for commits you want to merge into the previous one
# Save and quit (:wq)
```

### Undo a Failed Rebase

```bash
git reflog BRANCHNAME               # Find the right commit ID in the reflog
git reset --hard <commit>           # Reset to that commit
```

## 10. Code Archaeology — Exploring History

```bash
git log main                            # Show commit history of main branch
git log --graph main                    # Show history as a visual ASCII graph
git log --oneline                       # Compact one-line history
git log -5                              # Limit to last 5 commits (replace 5 with any number)
git log --stat                          # Show which files changed and how many lines
git log -p                              # Show full diff of every commit
git log --author="<pattern>"            # Search commits by a specific author
git log --grep="<pattern>"              # Search commits by message text
git log <since>..<until>               # Show commits between two refs (branch, tag, hash)
git log -- <file>                       # Show commits that modified a specific file
git log --follow <file>                 # Same, even if the file was renamed
git log --graph --decorate              # Graph view with branch/tag names shown
git log -G "banana"                     # Find every commit that added or removed "banana"
git blame <file>                        # Show who last changed each line of a file
```

### `git reflog` — The Safety Net

```bash
git reflog                              # Show ALL changes to HEAD (including resets, rebases)
git reflog BRANCHNAME                   # Show reflog for a specific branch
```

`git reflog` records every time HEAD moves — including `git reset`, `git rebase`, `git checkout`. If you accidentally reset to the wrong commit or lose commits after a bad rebase, the reflog lets you find the commit hash and recover:

```bash
git reflog
# abc1234 HEAD@{0}: reset: moving to HEAD~1
# def5678 HEAD@{1}: commit: Add login feature   ← the commit you want to recover

git reset --hard def5678    # Recover it
```

> The reflog is only local — it's not pushed to GitHub. It's your personal undo history for Git operations themselves.

## 11. Combining Branches

### `git merge` — Merge and Keep History

```bash
git switch main
git merge banana
```

```
Before:          After:
A─B─C            A─B─C─◇
    └─D─E             └─D─E─┘
```

Creates a **merge commit** that joins both histories. The original commits from both branches are preserved.

---

### `git rebase` — Replay Commits on Top

```bash
git switch banana
git rebase main
```

```
Before:          After:
A─B─C            A─B─C─D'─E'
    └─D─E
```

Replays `banana`'s commits on top of `main`. History is **rewritten** — creates new commits (`D'`, `E'`). Produces a cleaner, linear history.

> ⚠️ Never rebase commits that have already been pushed to a shared remote.

---

### `git merge --squash` — Squash All Branch Commits into One

```bash
git switch main
git merge --squash banana
git commit -m "Add banana feature"
```

Takes all commits from `banana` and squashes them into a **single new commit** on `main`. Clean history, but loses individual commit granularity.

---

### Fast-Forward Merge (When Branch is Ahead)

```bash
git switch main
git merge banana
```

```
Before: A─B─C─D─E  (banana is ahead of main)
After:  A─B─C─D─E  (main pointer simply moves forward)
```

No merge commit needed — just moves the branch pointer forward.

---

### `git cherry-pick` — Copy One Commit to Current Branch

```bash
git cherry-pick <commit>
```

```
Before:          After:
A─B─C            A─B─C─D'
    └─D─E
```

Copies just one specific commit onto your current branch. Useful for pulling in a hotfix without merging an entire branch.

---

## 12. Restoring an Old Version of a File

```bash
git checkout <commit> <file>                # Get file version from a specific commit
git restore <file> --source <commit>        # Modern alternative
```

This restores the file to how it was at that commit — without changing anything else. The restored version is automatically staged.

## 13. Working with Remotes

```bash
git remote add <name> <url>         # Link a remote repository (name is usually "origin")
git remote -v                       # List all remotes and their URLs
```

### Pushing

```bash
git push origin main                # Push main branch to remote origin
git push                            # Push current branch to its tracking branch
git push -u origin <name>           # Push a new branch and set upstream tracking
git push origin --all               # Push ALL local branches to the remote
git push --force-with-lease         # Force push (safer — won't overwrite others' changes)
git push --force                    # Force push ⚠️ — overwrites remote, no safety check
git push --tags                     # Push all tags
git push --follow-tags              # Push commits and all annotated tags
```

> Use `--force-with-lease` instead of `--force` — it checks that no one else has pushed since your last pull, preventing accidental overwrites.

### Pulling & Fetching

```bash
git fetch origin main               # Download changes but don't apply to local branches
git pull                            # Fetch and merge into current branch
git pull origin main                # Fetch from origin and merge main into current branch
git pull --rebase                   # Fetch and rebase instead of merge
```

| Command | What it does |
|---|---|
| `git fetch` | Downloads changes — your branches stay unchanged |
| `git pull` | Downloads + merges changes into your current branch |
| `git pull --rebase` | Downloads + replays your commits on top |

## 14. Tags

```bash
git tag                             # List all tags
git tag v1.0.0                      # Create lightweight tag on current commit
git tag -a v1.0.0 -m "Release"      # Create annotated tag on current commit
git tag -a v1.0.0 <hash> -m "msg"   # Create annotated tag on specific commit
git show v1.0.0                     # Show tag details
git push origin v1.0.0              # Push a single tag
git push --tags                     # Push all tags
git tag -d v1.0.0                   # Delete a local tag
git push origin --delete v1.0.0     # Delete a remote tag
```

---

## 15. `git stash` — Save Work Without Committing

```bash
git stash                   # Save all staged and unstaged changes temporarily
git stash list              # See all stashed states
git stash pop               # Re-apply the most recent stash and remove it
git stash apply             # Re-apply the most recent stash (keep it in stash list)
git stash drop              # Delete the most recent stash
```

Useful when you need to quickly switch to another branch but aren't ready to commit your current work.

## 17. Key Takeaways

- `git add -p` is powerful — lets you stage only specific parts of a file (hunks), giving you cleaner, more focused commits.
- `git commit -am` is a shortcut but only works for already-tracked files — new files still need `git add` first.
- `git commit --amend` lets you fix the last commit's message or add a forgotten file — only use before pushing.
- `git log --graph --oneline` gives a compact visual of your branch history — great for understanding where branches diverged.
- `git blame <file>` shows who last modified each line — invaluable for understanding code changes and tracking bugs.
- `git log -G "text"` searches commit diffs — finds exactly when a piece of text was added or removed.
- `git stash` is your emergency save button — use it to temporarily set aside changes without committing.
- Use `git fetch` before `git pull` if you want to see what's changed on the remote before merging it.
- `git push --force-with-lease` is safer than `--force` — it aborts if someone else has pushed since your last pull.
- `git rebase` creates a cleaner linear history than `git merge`, but never rebase shared/pushed commits.
- `git merge --squash` collapses an entire feature branch into one clean commit on main — useful for keeping main's history tidy.
- `git cherry-pick` is a surgical tool — copy exactly one commit onto your branch without merging everything else.
- `git reflog` is your ultimate safety net — it records every time HEAD moves, so even after a bad `reset` or `rebase` you can find and recover lost commits.
- `git clean -n` before `git clean -f` — always preview what will be deleted. Untracked files removed by `git clean` cannot be recovered.
- `git log --author`, `--grep`, and `-G` are powerful search filters — use them to hunt down when a bug was introduced or who wrote a specific piece of code.
- `git reset <commit>` (without `--hard`) moves the branch pointer back but leaves your files untouched — useful when you want to re-examine and re-stage your changes before recommitting.
