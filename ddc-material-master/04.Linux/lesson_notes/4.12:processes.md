# Linux Processes

## 1. What is a Process?

A **process** is any running program on the Linux system. Every command you run, every service that starts, every background task — all of these are processes.

Key facts:
- Every process has a unique **Process ID (PID)**
- Processes can be in different **states**: running, sleeping, stopped, or zombie
- The very first process (PID 1) is `systemd` (modern Linux) or `init` (older/Ubuntu systems) — it starts and manages all other processes

---

## 2. Process States

| State | Symbol | Meaning |
|---|---|---|
| Running | `R` | Actively using the CPU |
| Sleeping | `S` | Waiting for something (most processes are in this state) |
| Stopped | `T` | Paused, can be resumed |
| Zombie | `Z` | Finished but still has an entry in the process table |

> Most processes appear "sleeping" at any given moment — this is normal. The OS wakes them up when needed.

---

## 3. `top` — Live Process Monitor

`top` is like the **Task Manager** in Windows. It shows a real-time, dynamically updating view of all processes sorted by CPU usage.

```bash
top
```

### Header Information

```
top - 10:00:01 up 9 min, 1 user, load average: 0.00, 0.01, 0.05
Tasks: 117 total,   1 running, 116 sleeping,   0 stopped,   0 zombie
%Cpu(s): 0.0 us
MiB Mem:    486.0 total,   100.0 used,    35.0 free
```

| Field | Meaning |
|---|---|
| `up 9 min` | System uptime |
| `1 user` | Number of logged-in users |
| `load average: 0.00, 0.01, 0.05` | CPU wait time: current / last 5 min / last 15 min |
| `117 total` | Total number of processes (tasks) |
| `1 running` | Processes actively using CPU right now |
| `116 sleeping` | Processes waiting (idle) — this is normal |
| `0 zombie` | Dead processes with remaining process table entries |

### Load Average Explained
Load average represents how many processes are **waiting for CPU time**. Three values shown:
- **First value** — current minute average
- **Second value** — last 5 minutes average
- **Third value** — last 15 minutes average

If load average consistently exceeds the number of CPU cores, the system is under pressure.

### Process Columns in `top`

| Column | Meaning |
|---|---|
| `PID` | Process ID |
| `USER` | User running the process |
| `S` | State (R=running, S=sleeping, Z=zombie) |
| `%CPU` | CPU usage percentage |
| `%MEM` | RAM usage percentage |
| `COMMAND` | Process name |

### `top` Controls
| Key | Action |
|---|---|
| `q` | Quit top |

## 4. `ps aux` — Snapshot of All Processes

`ps aux` takes a **static snapshot** of all running processes (unlike `top` which is dynamic). The output is printed to the screen and the command quits.

```bash
ps aux
```

### Key Columns

| Column | Meaning |
|---|---|
| `PID` | Process ID |
| `USER` | User running the process |
| `%CPU` | CPU usage |
| `%MEM` | Memory usage |
| `STAT` | Process state (S=sleeping, R=running, Z=zombie) |
| `COMMAND` | Process name / command |

### Notable Observations

- **PID 1** is always `systemd` (or `init`) — the first process, parent of all others
- Processes shown in **`[square brackets]`** are kernel threads
- When a service like `httpd` is running, you'll see **multiple `httpd` processes** — one parent and several child worker processes

---

## 5. `ps -ef` — Process List with Parent Info

`ps -ef` shows all processes with their **parent-child relationships**, but without CPU/RAM utilization.

```bash
ps -ef
```

### Key Columns

| Column | Meaning |
|---|---|
| `PID` | Process ID |
| `PPID` | **Parent Process ID** — which process started this one |
| `UID` | User running the process |
| `CMD` | Command/process name |

### Understanding Parent-Child Relationships (Forking)

```
PID 1     systemd  (PPID: 0 — started at boot, parent is now dead)
  └── PID 1420  httpd   (PPID: 1)        ← parent httpd process
        ├── PID 1421  httpd   (PPID: 1420)  ← child worker
        ├── PID 1422  httpd   (PPID: 1420)  ← child worker
        └── PID 1423  httpd   (PPID: 1420)  ← child worker
```

The process of a parent creating child processes is called **forking**.

### Comparison: `ps aux` vs `ps -ef`

| Feature | `ps aux` | `ps -ef` |
|---|---|---|
| Shows CPU/RAM usage | ✅ Yes | ❌ No |
| Shows parent PID (PPID) | ❌ No | ✅ Yes |
| Use case | Resource usage | Process hierarchy |

## 6. Finding a Specific Process

Combine `ps` with `grep` to find a specific process:

```bash
ps -ef | grep httpd
```

This also shows the `grep` command itself as a result. To exclude it:

```bash
ps -ef | grep httpd | grep -v grep
```

Get only the PIDs using `awk`:
```bash
ps -ef | grep httpd | grep -v grep | awk '{print $2}'
```

`awk '{print $2}'` extracts the **second column** (the PID column) from each line.

## 7. `kill` — Stopping a Process

When you don't have `systemctl` for a service, or need to stop a specific process directly, use `kill`.

### Find the Process First
```bash
ps -ef | grep httpd | grep -v grep
# Example output:
# root  1420  1  httpd
# root  1421  1420  httpd
# root  1422  1420  httpd
```

### Graceful Kill (Default)
```bash
kill 1420           # Sends SIGTERM — politely asks the process to close
```

This is not as harsh as it sounds. It sends a **SIGTERM signal** — a polite request asking the process to finish its work and shut down cleanly. The parent process will also clean up its child processes.

### Forceful Kill (`-9`)
```bash
kill -9 1420        # Sends SIGKILL — forcefully terminates immediately
```

Use `-9` when a process is unresponsive and won't stop with a normal `kill`. The downside: the process is terminated instantly without cleanup, so **child processes may be left behind as orphans**.

### When to Use Each

| Signal | Command | Behavior |
|---|---|---|
| SIGTERM (default) | `kill <PID>` | Polite shutdown — process cleans up children |
| SIGKILL | `kill -9 <PID>` | Forced shutdown — no cleanup, may leave orphans |

---

## 8. Killing Multiple Processes with `xargs`

When you use `kill -9` on a parent process, child processes become **orphans** and need to be killed separately. Instead of killing them one by one, pipe the PID list to `xargs kill -9`:

```bash
ps -ef | grep httpd | grep -v grep | awk '{print $2}' | xargs kill -9
```

### How This Pipeline Works

```
ps -ef              → List all processes
| grep httpd        → Filter only httpd lines
| grep -v grep      → Remove the grep process from results
| awk '{print $2}'  → Extract just the PID (column 2)
| xargs kill -9     → Pass each PID as an argument to kill -9
```

`xargs` takes each line of input and passes it as an argument to the command that follows — in this case, `kill -9`.

> This is a very powerful trick for bulk-killing all instances of a process.

---

## 9. Orphan and Zombie Processes

### Orphan Processes
- Occur when a **parent process is killed** (especially with `-9`) before its children
- Child processes are left without a parent — they become **orphans**
- Modern Linux systems automatically **re-adopt orphans under PID 1 (systemd)**
- Orphans still **consume system resources** — clean them up

### Zombie Processes
- Occur when a process **finishes** but its entry **remains in the process table**
- Identifiable by state `Z` in `ps aux` output
- Do **not** consume CPU or RAM, but occupy a process table slot
- Also visible in `top` header: `0 zombie`

```bash
ps aux | grep Z     # Find zombie processes
```

**How to clear zombies:**
- **Best way:** Reboot the machine
- **Alternative:** Kill the zombie's parent process — this forces the system to clean up the zombie entry

## 10. Quick Reference Summary

| Command | What it does |
|---|---|
| `top` | Live dynamic view of all processes (like Task Manager) |
| `q` | Quit from `top` |
| `ps aux` | Snapshot of all processes with CPU/RAM usage |
| `ps -ef` | Snapshot of all processes with parent PID (PPID) |
| `ps -ef \| grep httpd` | Find a specific process by name |
| `ps -ef \| grep httpd \| grep -v grep` | Find process, exclude the grep itself |
| `ps -ef \| grep httpd \| grep -v grep \| awk '{print $2}'` | Get only the PIDs |
| `kill <PID>` | Gracefully stop a process (SIGTERM) |
| `kill -9 <PID>` | Forcefully kill a process (SIGKILL) |
| `... \| xargs kill -9` | Kill all PIDs from a filtered list |
| `free -m` | View RAM and swap usage |

---

## 11. Key Takeaways

- Every running program is a process with a unique **PID**.
- **PID 1** (`systemd` or `init`) is the first process — it is the ancestor of all other processes.
- Most processes are in a **sleeping** state at any given time — this is completely normal.
- `top` shows live, dynamic process info. `ps aux` and `ps -ef` show a static snapshot.
- `ps aux` gives CPU/RAM usage; `ps -ef` gives parent-child relationships (PPID).
- Load average shows CPU wait time across 1, 5, and 15 minute windows.
- Use `kill <PID>` for a graceful shutdown; `kill -9 <PID>` only when the process won't respond.
- `kill -9` on a parent leaves children as **orphans** — use the full pipeline with `xargs kill -9` to clean them all up at once.
- **Orphan processes** still consume resources; **zombie processes** don't consume resources but occupy process table entries.
- The best way to clear zombie processes is to **reboot** the machine.
- Combine `ps`, `grep`, `grep -v grep`, `awk`, and `xargs` for powerful process filtering and bulk operations — this is a core sysadmin skill.
