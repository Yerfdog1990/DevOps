# Linux Users and Groups

## 1. Why Users and Groups Exist

In Linux, **users and groups control access to files and resources**. Since everything in Linux is a file, access control is essentially file-level security.

- Every file is **owned by a user** and associated with a **group**
- Permissions determine what that user and group can do with the file
- Every user has a unique **User ID (UID)**

---

## 2. The Three Types of Users

### Root User
The superuser — has complete control over the entire system.

| Property | Value |
|---|---|
| Username | `root` |
| UID | `0` |
| GID | `0` |
| Home directory | `/root` |
| Login shell | `/bin/bash` |

### Regular Users
Normal human users created for logging in and working on the system.

| Property | Value |
|---|---|
| Example | `vagrant`, `ansible`, `imran` |
| UID | `1000+` |
| GID | `1000+` |
| Home directory | `/home/username` |
| Login shell | `/bin/bash` |

### Service / System Users
Created automatically when services are installed (e.g. FTP, SSH, Apache). These are **not for human login** — they run background processes.

| Property | Value |
|---|---|
| Examples | `sshd`, `ftp`, `apache` |
| UID | `1` to `999` |
| GID | `1` to `999` |
| Home directory | `/var`, `/etc`, or none |
| Login shell | `/sbin/nologin` or `/bin/false` |

> The `nologin` or `false` shell prevents anyone from getting a command shell as these users, even if they obtain access. These accounts typically have no password set.

## 3. Important User and Group Files

### `/etc/passwd` — User Information

Stores information about every user on the system.

```bash
cat /etc/passwd
head -1 /etc/passwd         # View root user entry
grep vagrant /etc/passwd    # View a specific user's entry
```

**Format — 7 colon-separated columns:**
```
username:x:UID:GID:comment:home_dir:login_shell
```

**Example entries:**
```
root:x:0:0:root:/root:/bin/bash
vagrant:x:1000:1000:vagrant:/home/vagrant:/bin/bash
sshd:x:74:74:SSH daemon:/var/empty/sshd:/sbin/nologin
```

| Column | Meaning |
|---|---|
| 1 | Username |
| 2 | `x` — password stored in `/etc/shadow` |
| 3 | User ID (UID) |
| 4 | Primary Group ID (GID) |
| 5 | Comment / description |
| 6 | Home directory |
| 7 | Login shell |

### `/etc/shadow` — Encrypted Passwords

Stores encrypted passwords and account expiry information. Not directly readable by regular users.

### `/etc/group` — Group Information

Stores group membership information.

```bash
cat /etc/group
grep vagrant /etc/group
grep devops /etc/group
```

**Format:**
```
groupname:x:GID:user1,user2,...
```

**Example:**
```
devops:x:1001:ansible,jenkins,aws
vagrant:x:1000:vagrant
```

| Column | Meaning |
|---|---|
| 1 | Group name |
| 2 | Password (rarely used) |
| 3 | Group ID (GID) |
| 4 | Comma-separated list of users in this group |

---

## 4. Primary vs. Supplementary Groups

- **Primary group** — the default group assigned when a user is created. Usually the same name as the user. Set with `-g`.
- **Supplementary (secondary) groups** — additional groups a user belongs to. Set with `-aG`.

```bash
id ansible
# uid=1001(ansible) gid=1001(ansible) groups=1001(ansible),1002(devops)
```

## 5. User Management Commands

### `useradd` — Create a New User
```bash
useradd ansible         # Create user named ansible
useradd jenkins         # Create user named jenkins
useradd aws             # Create user named aws
```

When a user is created:
- A home directory `/home/username` is created automatically
- A **primary group** with the same name is created automatically
- An entry is added to `/etc/passwd` and `/etc/group`

Verify:
```bash
tail -4 /etc/passwd             # See the 4 most recently added users
tail -4 /etc/group              # Confirm groups were created
id ansible                      # Show UID, GID, and group memberships
```

### `passwd` — Set or Reset a Password
```bash
passwd ansible          # Set password for ansible (run as root)
passwd aws              # Set password for aws
passwd jenkins          # Set password for jenkins
```

- Only **root** can set or reset another user's password
- A user with no password set cannot log in from outside

### `userdel` — Delete a User
```bash
userdel aws                     # Delete the user (home directory remains)
userdel -r jenkins              # Delete user AND their home directory
rm -rf /home/aws                # Manually remove leftover home directory if needed
```

> Always use `-r` or manually clean up home directories after deletion to avoid orphaned files.

---

## 6. Group Management Commands

### `groupadd` — Create a Group
```bash
groupadd devops         # Create a group named devops
```

### `groupdel` — Delete a Group
```bash
groupdel devops         # Delete the devops group
```

---

## 7. Adding Users to Groups

### Method 1 — `usermod` Command (Recommended)
```bash
usermod -aG devops ansible      # Add ansible to devops group (supplementary)
```

| Option | Meaning |
|---|---|
| `-aG` | Append to Supplementary/secondary group |
| `-g` | Change primary group (use carefully) |

> Always use `-aG` (not just `-G`) to **append** to existing groups. Using `-G` alone replaces all current supplementary groups.

Verify:
```bash
id ansible                      # Check group memberships
grep devops /etc/group          # See who is in the devops group
```

### Method 2 — Edit `/etc/group` Directly
Open the file with vim and manually add usernames (comma-separated) after the GID:

```bash
vim /etc/group
```

Find the group line and edit:
```
devops:x:1002:ansible,jenkins,aws
```

Verify:
```bash
id aws                          # Confirm aws is now in devops group
```

## 8. Switching Between Users

### Root Switching to Any User (No Password Needed)
```bash
su - ansible            # Switch to ansible user — no password required when done as root
```

> The `-` in `su -` loads the target user's full environment (home dir, shell settings).

### Regular User Switching to Another User (Password Required)
```bash
su - aws                # Must know aws user's password
su - jenkins            # Must know jenkins user's password
```

```bash
exit                    # Return to previous user
```

## 9. Useful Informational Commands

### `id` — Show User and Group Info
```bash
id                      # Info about current user
id ansible              # Info about a specific user
# Output: uid=1001(ansible) gid=1001(ansible) groups=1001(ansible),1002(devops)
```

### `who` — Currently Logged-In Users
```bash
who                     # Shows who is currently logged in and when
```

### `last` — Login History
```bash
last                    # Shows recent login history with timestamps
```

### `whoami` — Current Username
```bash
whoami                  # Prints the name of the currently active user
```

### `lsof -u` — List Open Files by User
```bash
lsof -u ansible         # List all files currently opened by ansible user
```

> Install if not available: `yum install lsof -y`
>
> Useful before deleting a user — check if they have active sessions or open files first.

## 10. Practical Workflow — Creating Users and a Shared Group

```bash
# Step 1: Create users
useradd ansible
useradd jenkins
useradd aws

# Step 2: Set passwords
passwd ansible
passwd jenkins
passwd aws

# Step 3: Create a shared group
groupadd devops

# Step 4: Add all users to the group
usermod -aG devops ansible
usermod -aG devops jenkins
usermod -aG devops aws

# Step 5: Verify
id ansible
grep devops /etc/group

# Step 6: Clean up (delete users and groups)
userdel -r jenkins
userdel -r ansible
userdel aws
rm -rf /home/aws
groupdel devops
```

## 11. Quick Reference Summary

| Command | What it does |
|---|---|
| `useradd username` | Create a new user |
| `passwd username` | Set or reset a user's password |
| `userdel username` | Delete a user (keeps home dir) |
| `userdel -r username` | Delete a user and their home directory |
| `groupadd groupname` | Create a new group |
| `groupdel groupname` | Delete a group |
| `usermod -aG group user` | Add user to a supplementary group |
| `id username` | Show UID, GID, and group memberships |
| `who` | Show currently logged-in users |
| `last` | Show login history |
| `whoami` | Show current username |
| `lsof -u username` | List files opened by a user |
| `su - username` | Switch to another user |
| `exit` | Return to previous user |
| `grep user /etc/passwd` | View user info from passwd file |
| `grep group /etc/group` | View group info from group file |
| `tail -4 /etc/passwd` | View most recently added users |

## 12. Key Takeaways

- Linux has **three user types**: root (UID 0), regular users (UID 1000+), and system/service users (UID 1–999).
- Service users exist to run background processes — they have `nologin` shells and no passwords, preventing shell access.
- `/etc/passwd` stores user info; `/etc/shadow` stores encrypted passwords; `/etc/group` stores group memberships.
- When a user is created with `useradd`, a **primary group of the same name** is automatically created.
- Use `usermod -aG` (not just `-G`) to add users to supplementary groups without removing existing memberships.
- You can add users to a group either with `usermod -aG` or by directly editing `/etc/group` with vim.
- Root can switch to any user with `su -` without a password. Regular users must know the target user's password.
- Always check open files with `lsof -u` before deleting a user.
- Use `userdel -r` to delete a user and their home directory together; or clean up manually with `rm -rf /home/username`.
- The real power of users and groups becomes clear when combined with **file permissions** and **sudo** — covered next.
