# Linux File Permissions

## 1. What are File Permissions?

Every file and directory in Linux has:
- An **owner** (a user)
- A **group** owner
- **Permission bits** that control what each entity can do with the file

Permissions enforce security by ensuring only the right users can read, modify, or execute files.

---

## 2. Reading `ls -l` Output

The `ls -l` command shows full permission details for each file.

```bash
ls -l
# -rw-------. 1 root root  1234 May 10 anaconda-ks.cfg
# drwxr-xr-x. 2 root root  4096 May 10 devopsdir
```

### Breaking Down Each Part

```
-  rw-  r--  r--   root  root   anaconda-ks.cfg
^   ^    ^    ^      ^     ^          ^
|   |    |    |      |     |          |
|   |    |    |      |     |          └── Filename
|   |    |    |      |     └──────────── Group owner
|   |    |    |      └────────────────── User (owner)
|   |    |    └───────────────────────── Others' permissions
|   |    └────────────────────────────── Group's permissions
|   └─────────────────────────────────── Owner's permissions
└─────────────────────────────────────── File type
```

### File Type (First Character)

| Character | Type |
|---|---|
| `-` | Regular file |
| `d` | Directory |
| `l` | Link |

### Permission Characters

| Character | Meaning |
|---|---|
| `r` | Read |
| `w` | Write |
| `x` | Execute |
| `-` | Permission not granted |

---

## 3. The Three Permission Groups

Permissions are defined for three entities — in this order:

```
[user/owner] [group] [others]
    rwx         r-x     r-x
```

| Entity | Who it applies to |
|---|---|
| **User (u)** | The file's owner |
| **Group (g)** | Users who belong to the file's group |
| **Others (o)** | Everyone else |

---

## 4. What r, w, x Mean for Files vs Directories

| Permission | On a File | On a Directory |
|---|---|---|
| `r` (read) | Can read/view file contents | Can `ls` — list contents of the directory |
| `w` (write) | Can edit or modify the file | Can create, rename, or delete files inside |
| `x` (execute) | Can run the file as a program | Can `cd` into the directory |

> For a directory, **execute (`x`) is required just to enter it** with `cd`. Without it, access is denied even if you have read permission.

---

## 5. Real Examples from `ls -l`

```
-rw-------  root  root   anaconda-ks.cfg
```
- Owner `root`: read + write
- Group `root`: no permissions
- Others: no permissions

```
drwxr-xr-x  root  root   devopsdir
```
- Owner `root`: read + write + execute (full access)
- Group `root`: read + execute (can list and enter, cannot write)
- Others: read + execute (can list and enter, cannot write)

> For link files, permissions shown are for the link itself, not the actual file it points to.

## 6. Changing Ownership — `chown`

`chown` changes the user and/or group owner of a file or directory.

### Syntax — Colon vs Dot Notation

Both of these are valid and do exactly the same thing:

```bash
chown aws:devops /opt/devopsdir       # Colon notation  ← more common
chown aws.devops /opt/devopsdir       # Dot notation    ← also works
```

Use either — the colon (`:`) is more widely used and easier to read.

### All Forms

```bash
chown ansible /opt/devopsdir                    # Change user owner only
chown ansible:devops /opt/devopsdir             # Change user AND group (colon)
chown ansible.devops /opt/devopsdir             # Change user AND group (dot)
chown -R ansible:devops /opt/devopsdir          # Recursive — applies to all files inside
```

### Real Example from the Terminal

Verify `ansible` user's group membership first:
```bash
[root@localhost /]# id ansible
uid=1001(ansible) gid=1001(ansible) groups=1001(ansible),1004(devops)
```

Before `chown` — directory is owned by `root:root`:
```bash
[root@localhost /]# ls -ld /opt/devopsdir/
drwxr-xr-x. 2 root root 6 May 10 22:34 /opt/devopsdir/
```

Run `chown` to transfer ownership to `ansible` user and `devops` group:
```bash
[root@localhost /]# chown ansible:devops /opt/devopsdir/
```

After `chown` — ownership is now `ansible:devops`:
```bash
[root@localhost /]# ls -ld /opt/devopsdir/
drwxr-xr-x. 2 ansible devops 6 May 10 22:34 /opt/devopsdir/
```

Notice the permissions (`drwxr-xr-x`) haven't changed yet — `chown` only changes **who owns** the file, not what they can do with it. That's `chmod`'s job.

> **Caution with `-R`:** Applying recursive ownership change to a directory with hundreds of files is hard to roll back. Only use `-R` when you are sure.

## 7. Changing Permissions — `chmod`

`chmod` changes the permission bits on a file or directory. There are two methods.

---

### Method 1 — Symbolic Method

Uses letters and symbols to add or remove permissions.

**Syntax:**
```bash
chmod [who][+/-][permission] file
```

| Symbol | Meaning |
|---|---|
| `u` | User (owner) |
| `g` | Group |
| `o` | Others |
| `a` | All (user + group + others) |
| `+` | Add permission |
| `-` | Remove permission |
| `r` | Read |
| `w` | Write |
| `x` | Execute |

**Examples:**
```bash
chmod o-x /opt/devopsdir        # Remove execute from others
chmod o-r /opt/devopsdir        # Remove read from others
chmod g+w /opt/devopsdir        # Add write to group
chmod u+x script.sh             # Add execute to owner
chmod a+r file.txt              # Add read for everyone
```

You can chain multiple changes:
```bash
chmod o-rx /opt/devopsdir       # Remove read AND execute from others at once
```

### Step-by-Step Real Terminal Walkthrough

Starting point after `chown ansible:devops` — permissions are `drwxr-xr-x`:
```
drwxr-xr-x. 2 ansible devops 6 May 10 22:34 /opt/devopsdir/
   ^^^  ^^^  ^^^
   rwx  r-x  r-x
  user group others
```

**Step 1 — Remove execute (`x`) from others:**
```bash
[root@localhost /]# chmod o-x /opt/devopsdir/
[root@localhost /]# ls -ld /opt/devopsdir/
drwxr-xr--. 2 ansible devops 6 May 10 22:34 /opt/devopsdir/
```
Others changed from `r-x` → `r--`. Others can still list contents (`r`) but can no longer `cd` into the directory (`x` removed).

**Step 2 — Add write (`w`) to group:**
```bash
[root@localhost /]# chmod g+w /opt/devopsdir/
[root@localhost /]# ls -ld /opt/devopsdir/
drwxrwxr--. 2 ansible devops 6 May 10 22:34 /opt/devopsdir/
```
Group changed from `r-x` → `rwx`. The devops group now has full access.

**Step 3 — Remove read (`r`) from others:**
```bash
[root@localhost /]# chmod o-r /opt/devopsdir/
[root@localhost /]# ls -ld /opt/devopsdir/
drwxrwx---. 2 ansible devops 6 May 10 22:34 /opt/devopsdir/
```
Others changed from `r--` → `---`. Others now have **zero permissions**.

Final result: `drwxrwx---`
- `rwx` — owner `ansible`: full access
- `rwx` — group `devops`: full access
- `---` — others: no access at all

### What `x` Means on a Directory — Proven by Testing

After setting `drwxrwx---`, switching to `miles` (who is not in the devops group, so falls under "others"):

```bash
[root@localhost /]# su - miles

[miles@localhost ~]$ ls /opt/devopsdir/
ls: cannot open directory '/opt/devopsdir/': Permission denied

[miles@localhost ~]$ cd /opt/devopsdir/
-bash: cd: /opt/devopsdir/: Permission denied

[miles@localhost ~]$ touch /opt/devopsdir/text.md
touch: cannot touch '/opt/devopsdir/text.md': Permission denied
```

`miles` is blocked from everything — listing (`r`), entering (`x`), and creating files (`w`) — because others have `---`.

Now switching to `aws` (who is in the `devops` group):

```bash
[aws@localhost ~]$ id aws
uid=1003(aws) gid=1003(aws) groups=1003(aws),1004(devops)

[aws@localhost ~]$ ls -ld /opt/devopsdir/
drwxrwx---. 2 ansible devops 22 May 10 23:39 /opt/devopsdir/

[aws@localhost ~]$ cd /opt/devopsdir/         # Works — group has x
[aws@localhost devopsdir]$ ls /opt/devopsdir/ # Works — group has r
file.txt

[aws@localhost devopsdir]$ touch /opt/devopsdir/myfile.txt  # Works — group has w
```

`aws` can do everything because the `devops` group has `rwx`.

### Method 2 — Numeric (Octal) Method

Uses a 3-digit number to set permissions for all three entities (user, group, others) **all at once** — faster than making individual symbolic changes.

**Permission Values:**

| Number | Permissions   |
| ------ | ------------- |
| 7      | `rwx` = 4+2+1 |
| 6      | `rw-` = 4+2   |
| 5      | `r-x` = 4+1   |
| 4      | `r--`         |
| 3      | `-wx` = 2+1   |
| 2      | `-w-`         |
| 1      | `--x`         |
| 0      | `---`         |


Add the values together to get the digit for each entity:

| Combination | Calculation | Result | Symbolic |
|---|---|---|---|
| Read + Write + Execute | 4+2+1 | `7` | `rwx` |
| Read + Write | 4+2 | `6` | `rw-` |
| Read + Execute | 4+1 | `5` | `r-x` |
| Read only | 4+0+0 | `4` | `r--` |
| No permission | 0 | `0` | `---` |

**Syntax:**
```bash
chmod [user_digit][group_digit][others_digit] /path
```

Each digit = the sum of permissions for that entity.

### Worked Examples

```bash
chmod 770 /opt/devopsdir
```
```
7 → 4+2+1 = rwx  (user:  full access)
7 → 4+2+1 = rwx  (group: full access)
0 → 0     = ---  (others: no access)
Result: drwxrwx---
```

```bash
chmod 640 /etc/myconfig.conf
```
```
6 → 4+2 = rw-  (user:  read + write)
4 → 4   = r--  (group: read only)
0 → 0   = ---  (others: no access)
Result: -rw-r-----
```

```bash
chmod 754 /opt/script.sh
```
```
7 → 4+2+1 = rwx  (user:  full access)
5 → 4+1   = r-x  (group: read + execute)
4 → 4     = r--  (others: read only)
Result: -rwxr-xr--
```

```bash
chmod 755 /opt/webdir
```
```
7 → 4+2+1 = rwx  (user:  full)
5 → 4+1   = r-x  (group: read + enter)
5 → 4+1   = r-x  (others: read + enter)
Result: drwxr-xr-x  ← common for public web directories
```

```bash
chmod 600 /home/user/.ssh/id_rsa      # Private key — owner only, no one else
chmod 777 /tmp/sharedfile             # Full access for everyone (use sparingly)
chmod 000 /opt/locked                 # No access for anyone
```

Apply recursively to all files inside a directory:
```bash
chmod -R 770 /opt/devopsdir
```

## 8. Common Permission Combinations

| Numeric | Symbolic | Meaning |
|---|---|---|
| `777` | `rwxrwxrwx` | Full access for everyone |
| `755` | `rwxr-xr-x` | Owner: full; Group+Others: read+execute |
| `750` | `rwxr-x---` | Owner: full; Group: read+execute; Others: none |
| `770` | `rwxrwx---` | Owner+Group: full; Others: none |
| `700` | `rwx------` | Owner only — full; Group+Others: none |
| `644` | `rw-r--r--` | Owner: read+write; Group+Others: read only |
| `640` | `rw-r-----` | Owner: read+write; Group: read; Others: none |
| `600` | `rw-------` | Owner: read+write only; no one else |

## 9. Full Practical Example

### Scenario: Create a shared directory for the devops team

```bash
# Step 1: Create users and group
useradd ansible
useradd jenkins
useradd aws
useradd miles                       # This user will NOT be in devops group
groupadd devops

# Step 2: Add ansible, jenkins, aws to devops group
vim /etc/group                      # Add users manually
# devops:x:1002:ansible,jenkins,aws

# Step 3: Create the shared directory
mkdir /opt/devopsdir

# Step 4: Change ownership to ansible user and devops group
chown ansible:devops /opt/devopsdir

# Step 5: Set permissions — full for owner and group, none for others
chmod 770 /opt/devopsdir

# Verify
ls -ld /opt/devopsdir
# drwxrwx--- ansible devops /opt/devopsdir
```

### Testing Access

**As `miles` (not in devops group — "others"):**
```bash
su - miles
ls /opt/devopsdir           # Permission denied
cd /opt/devopsdir           # Permission denied
touch /opt/devopsdir/test   # Permission denied
```

**As `aws` (member of devops group):**
```bash
su - aws
ls /opt/devopsdir           # Works — group has read
cd /opt/devopsdir           # Works — group has execute
touch /opt/devopsdir/file   # Works — group has write
```

This demonstrates how **ownership and permissions work together** to give the right access to the right users.

## 10. Quick Reference Summary

| Command | What it does |
|---|---|
| `ls -l` | Long listing showing permissions and ownership |
| `ls -ld /path` | Show permissions of a directory itself (not its contents) |
| `chown user file` | Change user owner of a file |
| `chown user:group file` | Change user and group owner |
| `chown -R user:group dir` | Change ownership recursively |
| `chmod o-x file` | Remove execute from others |
| `chmod g+w file` | Add write to group |
| `chmod 770 file` | Set rwx for user+group, none for others |
| `chmod 755 file` | rwx for user, r-x for group and others |
| `chmod 640 file` | rw for user, r for group, none for others |
| `chmod -R 770 dir` | Apply permissions recursively |

---

## 11. Key Takeaways

- Every file has an **owner (user)**, a **group**, and permissions for **others**.
- Permission bits are split into three groups of three: `[user][group][others]`, each being `rwx`.
- For directories: `r` = can list contents, `w` = can create/delete inside, `x` = can enter with `cd`.
- `chown` changes **who owns** the file. `chmod` changes **what they can do** with it.
- **Symbolic method** (`chmod g+w`) — best for making one targeted change.
- **Numeric method** (`chmod 770`) — best for setting all permissions at once quickly.
- Know your numeric values: `r=4`, `w=2`, `x=1`. Add them together: `7=rwx`, `6=rw-`, `5=r-x`, `4=r--`.
- Always use `ls -ld` to check a directory's own permissions (not `ls -l`, which shows what's inside).
- Use `-R` for recursive operations cautiously — it affects every file inside and is hard to reverse.
- Ownership + permissions together form the complete security model for files in Linux.
