# File Types in Linux

## 1. Everything is a File

In Linux, **everything is treated as a file** — not just documents and folders, but also:

- Your keyboard
- Your mouse
- Your hard disk
- Your terminal/SSH session (tty)
- Network sockets

This is a core Linux philosophy. Different types of files are handled by different commands, so it's important to know what type of file you're dealing with.

---

## 2. Identifying File Types with `ls -l`

The `ls -l` (long listing) command shows detailed information about files, including type.

```bash
ls -l
```

The **very first character** of each line tells you the file type:

```
-rw-r--r-- 1 root root  123 May 10 10:00 myfile.txt
drwxr-xr-x 2 root root 4096 May 10 09:00 mydir/
lrwxrwxrwx 1 root root   15 May 10 11:00 cmds -> /opt/dev/file.txt
```

| First Character | File Type |
|---|---|
| `-` | Regular file (text or binary) |
| `d` | Directory |
| `l` | Link (symbolic/soft link) |
| `c` | Character device file |
| `b` | Block device file |
| `s` | Socket file |
| `p` | Pipe file |

---

## 3. File Types in Detail

### `-` Regular File
The most common type. Can be either a text file or a binary file.

```bash
ls -l /root          # Shows - for regular files
```

Use the `file` command to determine what kind of regular file it is:

```bash
file /etc/hostname        # ASCII text
file /bin/yum             # Python script (still a text file)
file /bin/pwd             # ELF 64-bit LSB executable (binary)
```

- **Text files** — human-readable, editable with vim. Examples: config files, scripts.
- **Binary files** — compiled programs, not human-readable. Example: `/bin/pwd` is a compiled C program.

---

### `d` Directory
A directory is also a file in Linux. Confirmed by the `d` at the start of its `ls -l` entry.

```bash
file mydir/        # Returns: directory
```

---

### `l` Link File (Symbolic / Soft Link)
A link is like a desktop shortcut — it points to another file. The link itself is not the data; it just references where the real file is.

```bash
ls -l
# lrwxrwxrwx 1 root root 15 May 10 11:00 cmds -> /opt/dev/ops/devops/test/commands.txt
```

The `->` shows what the link points to.

**Dead link:** If the original file is moved or deleted, the link becomes a *dead link* — it blinks or highlights differently in the terminal to warn you.

---

### `c` Character Device File
Found in `/dev`. Represents devices that transmit data **character by character** (stream-based).

Examples:
- Keyboard (`/dev/tty`)
- Terminal sessions (tty = the shell you're working in)

```bash
ls -l /dev        # Shows c for character device files
```

---

### `b` Block Device File
Found in `/dev`. Represents devices that read/write data in **blocks** (chunk-based).

Examples:
- Hard disks (`/dev/sda`)
- USB drives

```bash
ls -l /dev/sda    # Shows b for block device
```

---

### `s` Socket File
Used for **inter-process communication** over a network or locally. You won't usually interact with these directly.

---

### `p` Pipe File
Used for **passing data between processes**. Like sockets, these are managed by the OS and rarely manipulated directly.

---

## 4. The `file` Command

The `file` command inspects a file and tells you exactly what it contains, regardless of its extension.

```bash
file /etc/hostname          # ASCII text
file /bin/pwd               # ELF 64-bit LSB executable, x86-64
file /bin/yum               # Python script, ASCII text executable
file /root                  # directory
file cmds                   # symbolic link to /opt/.../commands.txt
```

> Extensions mean nothing in Linux. A file named `data.txt` could be a binary. Always use `file` if you're unsure.

---

## 5. Creating Symbolic Links

### `ln -s` — Create a Soft Link

Useful when a file is buried deep in a directory structure and you want quick access from your home directory.

**Syntax:**
```bash
ln -s <original file path> <link name>
```

**Example:**
```bash
# Create deep directory structure
mkdir -p /opt/dev/ops/devops/test

# Create a file inside it
vim /opt/dev/ops/devops/test/commands.txt

# Create a soft link in home directory pointing to that file
ln -s /opt/dev/ops/devops/test/commands.txt cmds

# Now access the file via the link
cat cmds        # Shows content of the original file
```

> `mkdir -p` creates the entire directory path in one go, even if parent directories don't exist yet. Without `-p`, it will error if a parent dir is missing.

---

### Removing a Link

```bash
rm cmds           # Remove using rm (original file is untouched)
unlink cmds       # Alternative command to remove a link
```

> Removing a link never deletes the original file.

---

### Dead Links

If the original file is moved or deleted, the link becomes a **dead link** and will blink or appear highlighted in the terminal.

```bash
mv /opt/dev/ops/devops/test/commands.txt /tmp/     # Move original
ls -l                                               # Link appears dead (blinking)

mv /tmp/commands.txt /opt/dev/ops/devops/test/     # Move it back
ls -l                                               # Link is live again
```

## 6. Useful `ls` Options

| Command | What it does |
|---|---|
| `ls -l` | Long listing — shows file type, permissions, size, timestamp |
| `ls -lt` | Sort by **timestamp** — newest files first |
| `ls -ltr` | Sort by timestamp, **reversed** — oldest first, newest last |
| `ls -ltr /etc` | Long listing of `/etc`, sorted by time (oldest → newest) |

> `ls -ltr` is especially useful in directories with many files (like `/etc`) to quickly see what was changed most recently.

---

## 7. Changing the Hostname

The hostname is stored as a plain text file at `/etc/hostname`. You can edit it directly with vim.

```bash
vim /etc/hostname
# Change to: centos.devops.in
# Save with :wq
```

Apply and verify:
```bash
hostname                    # Shows the new hostname immediately
# Log out (Ctrl+D or exit) and log back in to see it reflected in the prompt
```

> This is a good example of the Linux philosophy: system configuration is just a text file. Edit it, save it, done.

---

## 8. `history` Command

Shows all previously executed commands for the current user.

```bash
history              # History of current user (e.g. vagrant)
sudo -i
history              # History of root user (separate from vagrant's history)
```

Each user has their own command history.

---

## 9. Quick Reference Summary

| Command | What it does |
|---|---|
| `ls -l` | Long listing showing file types and details |
| `ls -lt` | Sort by timestamp, newest first |
| `ls -ltr` | Sort by timestamp, oldest first (newest at bottom) |
| `file <path>` | Identify what type/content a file has |
| `ln -s <dest> <name>` | Create a symbolic (soft) link |
| `rm <link>` | Remove a link (original file untouched) |
| `unlink <link>` | Alternative to remove a link |
| `mkdir -p <path>` | Create nested directories in one command |
| `hostname` | Show or verify the current hostname |
| `history` | View command history of current user |

---

## 10. Key Takeaways

- Everything in Linux is a file — directories, devices, sessions, and sockets all included.
- The **first character** of `ls -l` output identifies the file type: `-` file, `d` dir, `l` link, `c` character, `b` block, `s` socket, `p` pipe.
- Use the `file` command to determine exactly what a file contains — don't rely on extensions.
- Symbolic links are like shortcuts. They go **dead** if the original file is moved or deleted.
- `ln -s` takes the **original file path first**, then the **link name**.
- `mkdir -p` is essential for creating deep directory trees in one command.
- `ls -ltr` is a practical habit for checking which files were recently modified (newest at the bottom).
- System configuration in Linux is usually just a plain text file — edit it with vim and you're done.
