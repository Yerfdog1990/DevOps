# Linux Services

## 1. What is a Service?

A **service** is a program that runs in the background to perform a specific function — like serving web pages, handling SSH connections, or managing a database. When you install a package like `httpd` (Apache web server), it comes with a **service** that you can start, stop, restart, and manage.

Running a service means there are **processes running in the background**. Managing a service = managing those processes.

Services in Linux are managed by the `systemctl` command, which interfaces with **systemd** — the system and service manager in modern Linux.

---

## 2. Installing a Service Package

Services are installed just like any other package. `httpd` (Apache) is a common example:

```bash
yum install httpd -y        # Install the httpd web service
```

Once installed, the package automatically creates:
- The service binary
- A **systemd unit file** — used by `systemctl` to know how to start, stop, and manage the service

---

## 3. Core `systemctl` Commands

All service management is done through `systemctl`:

```bash
systemctl <action> <service_name>
```

### Start a Service
```bash
systemctl start httpd           # Start the service immediately
```

### Stop a Service
```bash
systemctl stop httpd            # Stop the running service
```

### Restart a Service
```bash
systemctl restart httpd         # Stop then start again — used after config changes
```

### Reload a Service
```bash
systemctl reload httpd          # Reload config without fully restarting the service
```

> Use `reload` when possible — it applies config changes with less disruption than a full `restart`. Not all services support it.

### Check Status
```bash
systemctl status httpd
```

Output when **inactive (stopped)**:
```
● httpd.service - The Apache HTTP Server
   Loaded: loaded (/usr/lib/systemd/system/httpd.service)
   Active: inactive (dead)
```

Output when **active (running)**:
```
● httpd.service - The Apache HTTP Server
   Loaded: loaded (/usr/lib/systemd/system/httpd.service)
   Active: active (running) since ...
 Main PID: 1234 (httpd)
```

The **Main PID** shown is the process ID of the running service — more on this in the Processes lecture.

## 4. Start vs Enable — A Critical Distinction

This is one of the most important concepts in service management:

| Command | What it does | Survives reboot? |
|---|---|---|
| `systemctl start httpd` | Starts the service **right now** | ❌ No — stops on reboot |
| `systemctl enable httpd` | Configures service to **auto-start at boot** | ✅ Yes |
| `systemctl enable --now httpd` | Enables AND starts simultaneously | ✅ Yes |

### The Reboot Test

**Before reboot:**
```bash
systemctl start httpd
systemctl status httpd
# Active: active (running) ✓
```

**Reboot the VM:**
```bash
reboot          # or: vagrant reload (from host machine)
```

**After reboot:**
```bash
systemctl status httpd
# Active: inactive (dead)   ← did NOT survive the reboot
```

### Fix — Enable the Service
```bash
systemctl enable httpd      # Auto-start at boot from now on
systemctl start httpd       # Also start it right now for this session
```

> **Always do both** when setting up a permanent service. `enable` alone doesn't start it right now; `start` alone doesn't survive reboots.

## 5. Quick Status Check Commands

For a fast yes/no check without the full status output:

### `is-active` — Is it currently running?
```bash
systemctl is-active httpd
# Returns: active   OR   inactive
```

### `is-enabled` — Will it start at boot?
```bash
systemctl is-enabled httpd
# Returns: enabled   OR   disabled
```

> These are especially useful inside **bash scripts** where you need to check a service state programmatically.

## 6. Full `systemctl` Command Reference

| Command | What it does |
|---|---|
| `systemctl start <service>` | Start the service now |
| `systemctl stop <service>` | Stop the service |
| `systemctl restart <service>` | Stop and start (apply config changes) |
| `systemctl reload <service>` | Reload config without full restart |
| `systemctl status <service>` | Show detailed status and recent logs |
| `systemctl enable <service>` | Auto-start at boot |
| `systemctl disable <service>` | Disable auto-start at boot |
| `systemctl enable --now <service>` | Enable and start immediately |
| `systemctl is-active <service>` | Quick check: running? |
| `systemctl is-enabled <service>` | Quick check: enabled at boot? |

## 7. How `systemctl` Works — Service Unit Files

Every managed service has a **systemd unit file** that tells `systemctl` exactly how to start, stop, and reload it. This file is created automatically when you install a package via `yum`/`dnf`.

For `httpd`, the unit file is at:
```
/usr/lib/systemd/system/httpd.service
```

When the service is enabled, a symlink appears at:
```
/etc/systemd/system/multi-user.target.wants/httpd.service
```

### Inside the Unit File

```ini
[Unit]
Description=The Apache HTTP Server

[Service]
ExecStart=/usr/sbin/httpd $OPTIONS -DFOREGROUND   ← runs this to START
ExecStop=/bin/kill -WINCH ${MAINPID}              ← runs this to STOP
ExecReload=/usr/sbin/httpd $OPTIONS -k graceful   ← runs this to RELOAD

[Install]
WantedBy=multi-user.target
```

When you run `systemctl start httpd`, it reads this file and runs the `ExecStart` command. When you run `systemctl stop httpd`, it runs `ExecStop`.

> For packages installed via `yum`/`dnf`, these unit files are created automatically. For software installed from a tarball (manual download), you may need to create your own — covered later in the course.

## 8. The SSH Service — Always Keep Running

SSH is itself a service (`sshd`). Every `vagrant ssh` connection goes through it:

```bash
systemctl status sshd
# Active: active (running)   ← must be running for remote access
```

If `sshd` were stopped, you would lose SSH access to the machine entirely. On remote production servers, always ensure `sshd` is both started and enabled.

## 9. Practical Workflow — Setting Up a Service

```bash
# Step 1: Install the package
yum install httpd -y

# Step 2: Start the service immediately
systemctl start httpd

# Step 3: Enable auto-start at boot
systemctl enable httpd

# Step 4: Verify both states
systemctl is-active httpd       # active
systemctl is-enabled httpd      # enabled

# Step 5: Edit a config file
vim /etc/httpd/conf/httpd.conf

# Step 6: Apply the change
systemctl restart httpd         # full restart
# OR
systemctl reload httpd          # gentler reload (if supported)

# Step 7: Confirm it's still running
systemctl status httpd
```

---

## 10. Key Takeaways

- A service is a managed background process controlled by `systemctl` and systemd.
- Installing a package with `yum`/`dnf` automatically creates the systemd unit file — no manual setup needed for packaged software.
- **`start` ≠ `enable`** — this is critical. Start runs the service now; enable makes it survive reboots. You almost always need to do both.
- Use `reload` instead of `restart` when supported — it's less disruptive.
- `is-active` and `is-enabled` return a single word — useful for scripting.
- `systemctl` reads a unit file (`.service`) to know the exact commands for starting, stopping, and reloading a service.
- `sshd` is a service too — if it stops or is disabled on a remote server, you lose access. Always keep it enabled and running.
- You can write your own unit files for custom applications — covered later in the course.
