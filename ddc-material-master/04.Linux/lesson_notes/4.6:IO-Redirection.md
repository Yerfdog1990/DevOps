# I/O Redirection in Linux

## 1. What is I/O Redirection?

By default, when you run a command in Linux:
- **Input** comes from the keyboard
- **Output** goes to the screen (monitor)
- **Errors** also go to the screen

**Redirection** lets you change these defaults — sending output to a file instead of the screen, or suppressing errors entirely. This is a foundational skill for scripting and system administration.

---

## 2. Standard Streams

Every Linux process has three standard streams:

| Stream | Number | Default Device | Symbol |
|---|---|---|---|
| Standard Input (stdin) | `0` | Keyboard | `<` |
| Standard Output (stdout) | `1` | Screen | `>` or `1>` |
| Standard Error (stderr) | `2` | Screen | `2>` |

---

## 3. Output Redirection — `>`

Redirects the output of a command **to a file** instead of the screen.

```bash
uptime > /tmp/sysinfo.txt       # Output of uptime goes to the file, not the screen
ls > /tmp/sysinfo.txt           # Output of ls goes to the file
```

### Important Behavior
- If the file **does not exist** → it is created automatically.
- If the file **already exists** → its content is **overwritten**.

```bash
uptime > /tmp/sysinfo.txt       # Creates file (or overwrites if it exists)
ls > /tmp/sysinfo.txt           # Overwrites the previous content
```

---

## 4. Append Redirection — `>>`

Use `>>` to **add to** an existing file without overwriting it.

```bash
uptime >> /tmp/sysinfo.txt      # Appends uptime output to the file
free -m >> /tmp/sysinfo.txt     # Appends memory info below it
```

### Building a System Info File (Practical Example)

```bash
date > /tmp/sysinfo.txt             # Start fresh with the date
echo "####" >> /tmp/sysinfo.txt     # Add a separator
uptime >> /tmp/sysinfo.txt          # Append uptime
echo "####" >> /tmp/sysinfo.txt
free -m >> /tmp/sysinfo.txt         # Append RAM usage
echo "####" >> /tmp/sysinfo.txt
df -h >> /tmp/sysinfo.txt           # Append disk usage
echo "####" >> /tmp/sysinfo.txt
```

**Result in the file:**
```
Mon May 11 10:00:00 UTC 2026
####
 10:00:01 up 13 min, 1 user, load average: 0.00
####
              total   used   free  available
Mem:            486    100     35        369
####
Filesystem      Size  Used Avail  Use% Mounted on
/dev/sda1        50G  1.5G   49G    3% /
####
```

> This technique is the foundation of **bash scripting** — collecting command outputs into log files automatically.

### Useful Commands for Redirection Examples

| Command | What it shows |
|---|---|
| `uptime` | How long the system has been running |
| `free -m` | RAM and swap usage in megabytes |
| `df -h` | Disk partition sizes and usage |
| `date` | Current date and time |
| `echo "text"` | Prints any text to screen (or to a file) |

---

## 5. `/dev/null` — The Black Hole

`/dev/null` is a special file that **discards everything written to it**. It's like a black hole — nothing comes back out.

### Suppress Output (Don't Show, Don't Save)
```bash
yum install vim -y > /dev/null      # Run the command silently, discard all output
```

### Wipe a File's Content
```bash
cat /dev/null > /tmp/sysinfo.txt    # Redirect "nothing" into the file → file is now empty
```

> `cat /dev/null` outputs nothing. Redirecting nothing to a file empties it instantly — a clean and fast way to clear a file without deleting it.

---

## 6. Error Redirection — `2>`

Errors are **separate from regular output**. They use stream number `2`.

```bash
free -m > /dev/null                 # Output suppressed, but errors still show on screen
freeeeee > /dev/null                # Error: "command not found" still appears
```

To redirect errors to a file:
```bash
freeeeee 2> /tmp/error.log          # Redirect error to a log file (screen stays clean)
cat /tmp/error.log                  # View the error that was captured
```

---

## 7. Redirect Both Output and Errors — `&>`

Use `&>` to redirect **all output** (both stdout and stderr) to the same file.

```bash
command &> /tmp/all_output.log      # Both normal output AND errors go to this file
```

This is how background processes and services generate their **log files** in `/var/log` — they redirect both output and errors to a designated file while running silently.

### Summary of Redirection Symbols

| Symbol | Meaning |
|---|---|
| `>` | Redirect stdout to file (overwrite) |
| `>>` | Redirect stdout to file (append) |
| `2>` | Redirect stderr to file |
| `2>>` | Redirect stderr to file (append) |
| `&>` | Redirect both stdout and stderr to file |
| `> /dev/null` | Discard stdout |
| `2> /dev/null` | Discard stderr |
| `&> /dev/null` | Discard all output |

## 8. Piping — `|`

A **pipe** (`|`) takes the **output of one command** and feeds it as **input to the next command**. It chains commands together, each processing the result of the previous one.

```
command1 | command2 | command3 ...
```

---

### `wc -l` — Count Lines

Before piping, `wc -l` counts lines in a file:

```bash
wc -l /etc/passwd           # Count how many lines (users) are in the file
# Output: 25
```

### Counting Files in a Directory with Pipe
```bash
ls /etc | wc -l             # Count how many files are in /etc
# Output: 186
```

Here, `ls` generates a list → pipe feeds it to `wc -l` → which counts the lines.

---

### Practical Piping Examples

```bash
# Filter ls output — find files starting with "host"
ls /etc | grep host

# Search the last 20 lines of a log for a specific event
tail -20 /var/log/messages | grep vagrant

# Show only the RAM line from free -m (filter out swap and header)
free -m | grep Mem

# Show first 10 files from a long listing
ls -l | head

# Show last 10 files from a long listing
ls -l | tail
```

> Piping is one of the most powerful Linux concepts. Any command's output can become another command's input — the combinations are virtually limitless.

---

## 9. `find` — Search for Files by Name

`find` performs a **real-time search** of the filesystem for files matching a given name or pattern.

```bash
find /etc/ -name host               # Find file exactly named "host" in /etc
find /etc/ -name "host*"            # Find files starting with "host" in /etc
find / -name "host*"                # Search entire filesystem (slow — use with caution)
```

> Searching from `/` (root) is a real-time scan of the entire OS. This can slow down your system. Prefer searching specific directories when possible.

---

## 10. `locate` — Fast Database Search

`locate` searches a **pre-built database** of filenames rather than scanning the filesystem in real time. Much faster than `find`.

### Install and Setup
```bash
yum install mlocate -y      # Install the locate tool (not installed by default on CentOS)
updatedb                    # Build/update the filename database
```

### Usage
```bash
locate host                 # Find all files with "host" in the name
```

### Important Limitation
`locate` searches its database, which is only as current as the last `updatedb` run. If you add or delete files, `locate` won't reflect that until you run `updatedb` again.

```bash
updatedb && locate host     # Update database first, then search — for accurate results
```

| | `find` | `locate` |
|---|---|---|
| Speed | Slow (real-time scan) | Fast (database lookup) |
| Accuracy | Always current | Only as current as last `updatedb` |
| Requires install | No | Yes (`mlocate`) |

## 11. Quick Reference Summary

| Command | What it does |
|---|---|
| `command > file` | Redirect stdout to file (overwrite) |
| `command >> file` | Redirect stdout to file (append) |
| `command 2> file` | Redirect stderr to file |
| `command &> file` | Redirect all output (stdout + stderr) to file |
| `command > /dev/null` | Discard stdout |
| `command &> /dev/null` | Discard all output silently |
| `cat /dev/null > file` | Empty/wipe a file's contents |
| `cmd1 \| cmd2` | Pipe output of cmd1 as input to cmd2 |
| `wc -l file` | Count lines in a file |
| `ls \| wc -l` | Count number of files in a directory |
| `ls \| grep word` | Filter file listing by name |
| `tail -20 file \| grep word` | Search last 20 lines of a file |
| `free -m \| grep Mem` | Show only the RAM line from free output |
| `find /path -name "file*"` | Find files by name in real time |
| `locate filename` | Fast file search from database |
| `updatedb` | Update the locate database |
| `echo "text"` | Print text to screen or redirect to file |
| `date` | Print current date and time |
| `df -h` | Show disk partition usage |
| `free -m` | Show RAM and swap usage |

---

## 12. Key Takeaways

- `>` overwrites, `>>` appends — always double-check which one you need.
- `/dev/null` is the discard destination — redirect here when you want to suppress output completely.
- `cat /dev/null > file` is a fast, clean way to empty a file without deleting it.
- Stream numbers matter: `1` = stdout, `2` = stderr, `&` = both.
- Log files in `/var/log` are generated by services that redirect their output (`&>`) to those files while running in the background.
- Pipes (`|`) chain commands together — the output of one becomes the input of the next.
- `find` is real-time but slow; `locate` is fast but requires `updatedb` before use.
- Filtering + redirection + piping are the core building blocks of **bash scripting**. Master these before moving on.
