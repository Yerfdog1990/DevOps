# Introduction to Linux

---

## What is Linux?

Linux is a **free, open-source operating system kernel** based on UNIX. Created in 1991 by **Linus Torvalds**, it is the foundation on which most modern server infrastructure, DevOps tooling, and cloud computing is built.

> *"Linux is the foundation on which DevOps and this entire course stands. This is where your real technical strength begins."*

Key characteristics:
- Free and open-source — the source code is available to everyone
- Promotes global collaboration and community contribution
- Offers high performance, stability, and strong security
- Runs on an enormous range of hardware — phones, laptops, servers, supercomputers

## Brief History of Linux

| Phase | Year | Event |
|---|---|---|
| **Early Development** | 1984 | Open-source Unix utilities released under GPL license |
| **Linux Born** | 1991 | Linus Torvalds creates a Unix-like kernel and makes it open source |
| **Community Growth** | 1990s | Developers worldwide contribute; Linux distributions emerge |
| **Widespread Adoption** | 2000s | Linux dominates servers, enterprise, and cloud environments |
| **Today** | Present | Powers servers, Android phones, supercomputers, cloud platforms, IoT devices |

Linus Torvalds released a Unix-like kernel (the **Linux kernel**) and made it open source. From that kernel, organizations and communities built complete operating systems by adding utilities, packaging systems, and tools — these are called **Linux distributions**.

## Open Source — What It Actually Means

Open source is widely misunderstood as simply meaning "free software." It is much more than that.

**Open source means:** the source code used to create the software is **freely available** for anyone to:
- Inspect
- Modify
- Enhance
- Redistribute

This model allows **hundreds or thousands of contributors worldwide** to improve a single piece of software — far more than any single company team could achieve alone. Linux's quality, security, and reliability are a direct result of this model.

> Some open source software is free of cost, but not all. The core idea is about openness of code, not price.

## Linux Architecture

Linux has a layered architecture. From bottom to top:

```
┌─────────────────────────────────────┐
│          USER / APPLICATIONS        │  (browsers, editors, commands)
├─────────────────────────────────────┤
│         SYSTEM UTILITIES & SHELL    │  (bash, cat, ls, vim, etc.)
├─────────────────────────────────────┤
│         SYSTEM LIBRARIES            │  (reusable code; interface to kernel)
├─────────────────────────────────────┤
│              KERNEL                 │  (Linux kernel — Torvalds' creation)
├─────────────────────────────────────┤
│              HARDWARE               │  (CPU, RAM, disk, network, devices)
└─────────────────────────────────────┘
```

### Layer Breakdown

**Hardware Layer** — physical components: CPU, RAM, storage, I/O devices. Communicates with the OS through device drivers and kernel services.

**Kernel** — the core of Linux. Manages hardware resources, process scheduling, memory, and device communication. Prevents conflicts between running programs. This is the kernel Linus Torvalds created.

**System Libraries** — pre-written reusable code that applications use to interact with the kernel without accessing it directly. Act as an interface between apps and the kernel.

**Shell** — the command-line interface (CLI) through which users send commands to the OS. The shell interprets commands and passes them to the kernel. Common shells: `bash`, `sh`, `zsh`.

**System Utilities** — built-in tools for managing and maintaining the system (user management, software installation, monitoring, networking). What users interact with day-to-day.

**Applications** — end-user software: web browsers, text editors, servers, development tools.

## Core Linux Principles (Important for DevOps)

Understanding these principles helps you think the Linux way:

**1. Everything is a file**
In Linux, nearly everything is represented as a file — including hardware devices (your keyboard, mouse, printer, network card). This allows consistent interaction with all system components.

**2. Small, single-purpose programs**
Linux favors small tools that do one thing well. These tools can be chained together to perform complex operations — a philosophy directly mirrored in DevOps pipelines and CI/CD automation.

**3. Avoid captive user interfaces**
Linux avoids requiring user interaction mid-process. Programs should not wait for clicks or manual input. This makes background execution and automation straightforward — essential for DevOps.

**4. Configuration stored in text files**
All system configuration in Linux is stored in plain text files (mainly in `/etc`). This means you can view, edit, version-control, and automate configuration changes with simple text editing — no GUIs required.

## Linux Distributions (Distros)

A **Linux distribution** is a complete operating system built around the Linux kernel, bundled with system software, libraries, package management, and applications. There are 600+ Linux distributions available.

### Two Major Families

For DevOps and IT work, you will encounter two primary families:

#### RPM-Based (Red Hat Family)
Software packaged in `.rpm` format. Install command: `rpm -i <package.rpm>`

| Distro | Notes |
|---|---|
| Red Hat Enterprise Linux (RHEL) | Most stable and secure; commercial/licensed |
| CentOS | Open-source RHEL equivalent |
| Fedora | Cutting-edge; Red Hat's upstream project |
| Oracle Linux | Similar to RHEL |
| Amazon Linux | Used on AWS EC2 instances |
| Rocky Linux / AlmaLinux | Enterprise RHEL alternatives |

#### Debian-Based (Debian Family)
Software packaged in `.deb` format. Install command: `dpkg -i <package.deb>`

| Distro | Notes |
|---|---|
| Ubuntu Server | Most popular for DevOps and cloud (AWS, Azure) |
| Debian | Highly stable; base for many other distros |
| Kali Linux | Security and penetration testing |
| Linux Mint | Beginner-friendly, Windows-like experience |

### Key Difference Between Families

| | RPM-Based | Debian-Based |
|---|---|---|
| Package format | `.rpm` | `.deb` |
| Manual install | `rpm -i` | `dpkg -i` |
| Package manager | `yum` / `dnf` | `apt` |
| Philosophy | Stability, security, vetted packages | Latest software, user-friendliness |
| Best for | Enterprise servers | DevOps automation, cloud, development |

> **Instructor's recommendation:**
> - **RPM/Red Hat** → preferred for running stable production servers
> - **Debian/Ubuntu** → preferred for DevOps automation (easier access to latest libraries and tools)

## Linux Directory Structure

In Linux, **directories** are what Windows calls "folders." The entire filesystem starts from a single root: `/`

Understanding these key directories is essential:

| Directory | Purpose |
|---|---|
| `/` | Root of the entire filesystem |
| `/home/username` | Home directory for normal users (e.g., `/home/vagrant`) |
| `/root` | Home directory of the **root** (admin) user |
| `/bin` | Essential commands usable by all users (`ls`, `cat`, `pwd`, `cd`) |
| `/usr/bin` | User-level commands and programs |
| `/sbin` | System admin commands — root only (`rpm`, `useradd`, `apt`) |
| `/usr/sbin` | Additional system admin commands |
| `/usr/local/bin` | Custom/locally installed commands |
| `/etc` | **System configuration files** — where we spend lots of time (network config, server config, user config) |
| `/var` | Variable data — server files, logs, databases (e.g., `/var/www/html` for web servers, `/var/lib/mysql` for MySQL) |
| `/tmp` | Temporary files — may be cleared on reboot, handle with care |
| `/boot` | Kernel and bootloader files |
| `/proc` | Virtual filesystem with live system/kernel information |
| `/sys` | System hardware and kernel information |
| `/lib` | Shared system libraries |
| `/usr/lib` | Libraries for user programs |
| `/media` | Mount point for removable devices (USB, CD) |
| `/mnt` | Temporary mount point for filesystems |

## Installing Software on Linux

**Debian-based (Ubuntu):**
```bash
sudo apt install package_name
```

**RPM-based (Fedora/CentOS):**
```bash
sudo dnf install package_name   # Fedora / RHEL 8+
sudo yum install package_name   # CentOS / older RHEL
```

**Manual package install:**
```bash
dpkg -i package.deb    # Debian
rpm -i package.rpm     # Red Hat
```
