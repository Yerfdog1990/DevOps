# Linux Package Management

## 1. What is Package Management?

Installing, updating, and removing software in Linux is called **package management**. There are multiple ways to do this, from manually downloading a single package file to using powerful package management tools that handle everything automatically.

The method you use depends on your **Linux distribution (distro)**:

| OS Family | Examples | Package Format | Basic Tool | Advanced Tool |
|---|---|---|---|---|
| RPM-based | CentOS, RHEL, Fedora, AlmaLinux | `.rpm` | `rpm` | `yum` / `dnf` |
| Debian-based | Ubuntu, Debian | `.deb` | `dpkg` | `apt` |

Check which family your OS belongs to:
```bash
cat /etc/os-release
# ID="centos"
# ID_LIKE="rhel fedora"   ← RPM-based
```

Check architecture (important for downloading the right package):
```bash
arch           # e.g. x86_64
uname -m       # same result
```

> Package management requires root privileges. Always switch to root first: `sudo -i`

## 2. List Installed Packages

```bash
rpm -qa                 # List all installed RPM packages (RPM-based OS)
dpkg -l                 # List all installed packages (Debian-based OS)
rpm -qa | grep telnet   # Check if a specific package is installed
```

## 3. Method 1 — Manual RPM Install (Basic)

This is the most manual method — download a single `.rpm` file and install it directly. Useful for understanding how packages work, but not practical for real use.

### Step 1 — Find the RPM Online

Search for the package on repositories like:
- **rpmfind.net** — popular and clean
- **centos.pkgs.org**
- **rpm.pbone.net**

Search for your package, then filter by:
- Your OS (e.g. CentOS Stream 9)
- Your architecture (e.g. x86_64)

Right-click the download link → **Copy link address**

### Step 2 — Download to Linux

Use `curl` or `wget` to download from the command line:

```bash
# Using curl
curl https://rpmfind.net/.../telnet-0.17-xxx.x86_64.rpm -o telnet-0.17-xxx.x86_64.rpm

# Using wget (simpler for downloads)
wget https://rpmfind.net/.../telnet-0.17-xxx.x86_64.rpm
```

| Tool | Best For |
|---|---|
| `wget` | Downloading files — simple and direct |
| `curl` | Downloading + many other URL operations |

### Step 3 — Install the RPM

```bash
rpm -ivh telnet-0.17-xxx.x86_64.rpm
```

| Option | Meaning |
|---|---|
| `-i` | Install |
| `-v` | Verbose — print output |
| `-h` | Human-readable format (shows progress) |

### Step 4 — Verify Installation

```bash
rpm -qa | grep telnet       # Confirm package is listed
telnet                      # Try running the command
```

### Step 5 — Remove (Uninstall) an RPM

```bash
rpm -qa | grep telnet                    # Get the exact package name
rpm -e telnet-0.17-xxx.x86_64           # Erase (remove) by full package name
```

| Option | Meaning |
|---|---|
| `-e` | Erase (uninstall) the package |

### The Problem with Manual RPM

When you try to install a package with dependencies, you get errors like:

```
error: Failed dependencies:
    libssl.so.1 is needed by httpd-2.4.x
    apr-util >= 1.2 is needed by httpd-2.4.x
```

You'd have to manually download and install each dependency, then install those dependencies' dependencies, and so on. In the old days, this was known as **"dependency hell"** — which is exactly why package managers were created.

## 4. Method 2 — Yum / DNF (Recommended)

`yum` and `dnf` are **package managers** that automatically handle dependencies, downloads, and installation from online repositories. `dnf` is the newer generation replacement for `yum` — prefer `dnf` when possible.

### How it Works — Repositories

Package managers connect to **repositories** (online software stores) to find and download packages.

Repository configuration files are stored in:
```bash
ls /etc/yum.repos.d/        # List configured repositories
cat /etc/yum.repos.d/centos.repo    # View a repo config file
```

A repo config file contains the URL of the repository, its name, and whether it's enabled.

---

### Common DNF / Yum Commands

#### Search for a Package
```bash
dnf search httpd            # Search all repos for packages matching "httpd"
yum search httpd            # Same with yum
```

#### Install a Package
```bash
dnf install httpd           # Install httpd and all its dependencies automatically
yum install httpd           # Same with yum
dnf install httpd -y        # Install without asking yes/no confirmation
```

When you run `dnf install`:
- It searches all configured repositories
- Resolves all dependencies automatically
- Downloads and installs everything needed
- Asks for confirmation (`y` to proceed)

#### Remove a Package
```bash
dnf remove httpd            # Remove httpd (also removes unused dependencies)
yum remove httpd
```

#### Upgrade Packages
```bash
dnf upgrade                 # Upgrade all packages on the system
yum upgrade
dnf upgrade httpd           # Upgrade a specific package only
```

> Always run `dnf upgrade` on a fresh OS before you start using it — it patches vulnerabilities and applies bug fixes.

#### Reinstall a Package
```bash
dnf reinstall httpd         # Reinstall if the package didn't install cleanly
```

#### View Command History
```bash
dnf history                 # See all past dnf/yum operations (installs, removes, upgrades)
```

#### Clean Cache
```bash
dnf clean all               # Clear the local cache
yum clean all
```

> If you added a new repository but packages still aren't found, run `dnf clean all` then try again.

#### List Repositories
```bash
dnf repolist                # Show all currently configured and enabled repositories
```

#### Get Help
```bash
dnf --help                  # List all available dnf options and subcommands
```

---

### DNF / Yum Quick Reference

| Command | What it does |
|---|---|
| `dnf search <name>` | Search repos for a package |
| `dnf install <name>` | Install a package + dependencies |
| `dnf install <name> -y` | Install without confirmation prompt |
| `dnf remove <name>` | Uninstall a package |
| `dnf reinstall <name>` | Reinstall a package |
| `dnf upgrade` | Upgrade all packages |
| `dnf upgrade <name>` | Upgrade a specific package |
| `dnf history` | View past install/remove operations |
| `dnf repolist` | List all configured repositories |
| `dnf clean all` | Clear cached repo data |
| `dnf grouplist` | List available package groups |
| `dnf groupinstall "name"` | Install a group of related packages |
| `dnf --help` | Show all available commands |

## 5. What if the Package isn't in Any Repository?

Sometimes `dnf install` can't find a package:

```bash
dnf install jenkins
# No match for argument: jenkins
# Error: Unable to find a match: jenkins
```

This means none of the configured repositories contain that package. The solution:

1. **Google it** — search `install jenkins centos` or `install <package> linux`
2. **Go to the vendor's website** — the software vendor (e.g. jenkins.io) always provides installation instructions
3. **Add the vendor's repository** — then install normally with `dnf`

---

## 6. Adding a Third-Party Repository — Jenkins Example

The vendor's website (jenkins.io → Linux → Red Hat / CentOS) provides these steps:

### Step 1 — Download and Add the Repo File
```bash
wget -O /etc/yum.repos.d/jenkins.repo https://pkg.jenkins.io/redhat-stable/jenkins.repo
```

This downloads the Jenkins repository config and places it in `/etc/yum.repos.d/`. Now `dnf` knows where to find Jenkins packages.

You can verify it was added:
```bash
cat /etc/yum.repos.d/jenkins.repo     # View the repo configuration
dnf repolist                           # Jenkins should now appear in the list
```

### Step 2 — Import the GPG Key
```bash
rpm --import https://pkg.jenkins.io/redhat-stable/jenkins.io-2023.key
```

Some repositories require a security key for trusted access. This imports it.

### Step 3 — Upgrade and Install Dependencies
```bash
dnf upgrade -y
dnf install fontconfig java-17-openjdk -y    # Jenkins requires Java 17
```

### Step 4 — Install Jenkins
```bash
dnf install jenkins -y
```

> **Key takeaway:** If a package isn't in your default repos, the vendor will always tell you exactly how to add their repo and install the package. Always check the official documentation.

## 7. EPEL — Extra Packages for Enterprise Linux

`epel-release` is a special package that gives you access to a huge collection of additional repositories, making far more software available through `dnf`.

```bash
dnf install epel-release -y        # Install EPEL
dnf repolist                        # You'll now see additional repositories listed
```

> Install `epel-release` on any CentOS / AlmaLinux / RHEL system early on — it dramatically expands the number of packages available to you.

## 8. How Package Management Fits Together

```
You want to install a package
        │
        ▼
Is it available via dnf/yum?
    YES ──► dnf install <package> -y         Done ✓
        │
       NO
        │
        ▼
Search vendor website for install instructions
        │
        ▼
Add vendor's .repo file to /etc/yum.repos.d/
Import GPG key if required
        │
        ▼
dnf install <package> -y                     Done ✓
```

---

## 9. Key Takeaways

- CentOS / RHEL / Fedora are **RPM-based** — use `rpm`, `yum`, `dnf`. Ubuntu / Debian are **Debian-based** — use `dpkg`, `apt`.
- Use `arch` or `uname -m` to find your CPU architecture before downloading any package manually.
- Manual `rpm` install works but suffers from **dependency hell** — you must manually resolve every dependency.
- `dnf` and `yum` solve dependency hell automatically — they find, download, and install all required packages.
- Prefer `dnf` over `yum` — it is the newer, recommended replacement.
- If a package isn't found by `dnf`, check the **vendor's website** for instructions to add their repository.
- Repository config files live in `/etc/yum.repos.d/` — each `.repo` file gives `dnf` access to a software source.
- Run `dnf upgrade` on every new server before you start using it — patches vulnerabilities and applies fixes.
- `dnf clean all` clears the cache — useful if newly added repositories still aren't being detected.
- Install `epel-release` on RPM-based systems to unlock access to a much larger pool of packages.
- `dnf history` tracks every install and remove operation — useful for auditing and troubleshooting.
