# Ubuntu Commands & Differences from CentOS

## 1. Overview

Ubuntu and CentOS are both Linux distributions, and **most commands work identically on both**. The differences are mainly in:

- User management (`useradd` vs `adduser`)
- Package management (`yum`/`dnf` vs `apt`)
- Default text editor in some tools
- Service behavior after installation

This note covers the key differences and Ubuntu-specific commands.

```bash
cat /etc/os-release
# NAME="Ubuntu"
# VERSION="22.04 LTS"
```

## 3. User Management — `adduser` vs `useradd`

This is one of the most important differences between Ubuntu and CentOS.

### The Problem with `useradd` in Ubuntu

`useradd` exists in Ubuntu but is **incomplete** — it does not create a home directory, a mail spool, or set up default files:

```bash
useradd devops          # Creates user, but...
su - devops             # ...no home directory! Takes you to / instead
```

Cleanup:
```bash
userdel -r devops
# Warning: no home directory found while deleting
# Warning: no mail spool found
```

### The Correct Command — `adduser`

Ubuntu provides `adduser`, which is the proper, interactive user creation command:

```bash
adduser devops
```

`adduser` automatically:
- Creates the user `devops`
- Creates a group called `devops`
- Adds the user to that group
- Creates the home directory `/home/devops`
- Copies default files from `/etc/skel` into the home directory
- Prompts you to set a **password**
- Asks for optional info (full name, phone, etc.) — just press Enter to skip each

```
Adding user `devops` ...
Adding new group `devops` (1001) ...
Adding new user `devops` (1001) with group `devops` ...
Creating home directory `/home/devops` ...
Copying files from `/etc/skel` ...
New password: ****
Retype new password: ****
Full Name []: (Enter)
Room Number []: (Enter)
...
Is the information correct? [Y/n] Y
```

### Commands That Remain the Same

| Command | Works the same on Ubuntu |
|---|---|
| `passwd username` | ✅ |
| `groupadd groupname` | ✅ |
| `usermod -aG group user` | ✅ |
| `userdel -r username` | ✅ |
| `id username` | ✅ |
| `su - username` | ✅ |

## 4. Visudo — Default Editor Difference

On CentOS, `visudo` opens `/etc/sudoers` in **vim** by default.
On Ubuntu, the default editor is **nano**.

```bash
visudo          # Opens in nano on Ubuntu
```

### Switch to Vim Temporarily

```bash
export EDITOR=vim
visudo              # Now opens in vim
```

`export EDITOR=vim` sets an **environment variable** that tells the system which editor to use. This is temporary — it resets when you log out.

> Making it permanent (so you don't have to run this every login) is covered in the Bash Scripting section.

## 5. Package Management — `apt`

Ubuntu is **Debian-based**, so it uses `.deb` packages and the `apt` package manager instead of `.rpm` and `yum`/`dnf`.

### Repository Configuration

```bash
cat /etc/apt/sources.list       # View configured repositories
ls /etc/apt/                    # Also check sources.list.d/ for additional repos
```

Ubuntu has access to a very large number of repositories from around the world, giving it broader software availability than CentOS by default.

---

### The `apt update` Step — Important Difference from Yum

**Before installing any software on Ubuntu, always run:**

```bash
apt update
```

This command checks all configured repositories and **refreshes the local package list**. Without it, `apt` may not see newly available packages or may install outdated versions.

> With `yum`/`dnf` on CentOS, this refresh happens automatically. On Ubuntu with `apt`, you must do it manually.

| Action | CentOS (`yum`/`dnf`) | Ubuntu (`apt`) |
|---|---|---|
| Refresh package list | Automatic | `apt update` (manual) |
| Install a package | `dnf install <pkg>` | `apt install <pkg>` |
| Remove a package | `dnf remove <pkg>` | `apt remove <pkg>` |
| Upgrade all packages | `dnf upgrade` | `apt upgrade` |
| Search for a package | `dnf search <pkg>` | `apt search <pkg>` |
| List installed packages | `rpm -qa` | `dpkg -l` |

---

### Common `apt` Commands

#### Update the package list
```bash
apt update
```

#### Search for a package
```bash
apt search tree
# Shows all packages with "tree" in the name or description
```

#### Install a package
```bash
apt install tree            # Install with confirmation prompt
apt install tree -y         # Install without prompt
apt install apache2 -y      # Install Apache (equivalent of httpd on CentOS)
```

`apt` resolves and installs all dependencies automatically, just like `dnf`.

#### Remove a package
```bash
apt remove apache2          # Remove package but keep config files and data
```

#### Purge a package (clean uninstall)
```bash
apt purge apache2           # Remove package AND all its config/data files
```

> Use `apt purge` for a completely clean uninstall. `apt remove` leaves config files behind, which can be useful if you plan to reinstall later.

#### Upgrade all packages
```bash
apt upgrade                 # Upgrade all installed packages to latest versions
```

> Note: `apt update` only refreshes the list. `apt upgrade` actually performs the upgrades. Always run `apt update` first, then `apt upgrade`.

---

### Full `apt` Command Reference

| Command | What it does |
|---|---|
| `apt update` | Refresh the package list from repositories |
| `apt search <name>` | Search for a package |
| `apt install <name>` | Install a package + dependencies |
| `apt install <name> -y` | Install without yes/no prompt |
| `apt remove <name>` | Remove package (keeps config files) |
| `apt purge <name>` | Remove package + all config and data |
| `apt upgrade` | Upgrade all installed packages |
| `apt upgrade <name>` | Upgrade a specific package |

## 6. Manual Package Install — `dpkg`

Just like CentOS has `rpm` for manual installs, Ubuntu has `dpkg` for `.deb` packages.

### Download a `.deb` package manually
```bash
wget https://ubuntu.pkgs.org/.../tree_xxx_amd64.deb
```

### Install the `.deb` file
```bash
dpkg -i tree_xxx_amd64.deb
```

| Option | Meaning |
|---|---|
| `-i` | Install |
| `-r` | Remove |
| `-l` | List all installed packages |

### List installed packages
```bash
dpkg -l                         # List all installed Debian packages
dpkg -l | grep tree             # Search for a specific installed package
```

### Remove a package
```bash
dpkg -r tree                    # Remove the tree package
```

> Like `rpm`, `dpkg` does not handle dependencies automatically. Use `apt` for dependency resolution.

## 7. Service Behavior Difference

On **CentOS**, installing a service does **not** start it — you must manually run `systemctl start`.

On **Ubuntu**, installing a service package **starts it automatically**:

```bash
apt install apache2 -y

systemctl status apache2
# Active: active (running)   ← already started automatically!
```

Check if also enabled:
```bash
systemctl is-enabled apache2
# enabled   ← also enabled at boot automatically
```

> On Ubuntu, services installed via `apt` are started **and** enabled by default. On CentOS, you must do both manually after installation.

## 8. UFW — Ubuntu Firewall

When installing or removing network services like Apache2 on Ubuntu, the package manager may also update **UFW (Uncomplicated Firewall)** rules automatically.

```bash
ufw status          # Check firewall status
```

UFW is Ubuntu's default firewall management tool. More details on firewall configuration will be covered in later lectures.

## 9. CentOS vs Ubuntu — Full Comparison

| Feature | CentOS | Ubuntu |
|---|---|---|
| OS family | RPM-based | Debian-based |
| Package format | `.rpm` | `.deb` |
| Manual install tool | `rpm` | `dpkg` |
| Package manager | `yum` / `dnf` | `apt` |
| Repository config | `/etc/yum.repos.d/` | `/etc/apt/sources.list` |
| Refresh package list | Automatic | `apt update` (manual) |
| Create user | `useradd` (full) | `adduser` (use this instead of useradd) |
| Default visudo editor | vim | nano |
| Apache package name | `httpd` | `apache2` |
| Service auto-start after install | ❌ Manual | ✅ Automatic |
| List installed packages | `rpm -qa` | `dpkg -l` |
| Firewall tool | `firewalld` | `ufw` |

## 10. Key Takeaways

- Most Linux commands work identically on CentOS and Ubuntu — the differences are focused in user management, package management, and service behavior.
- On Ubuntu, always use **`adduser`** instead of `useradd` — it creates the home directory, sets a password, and copies skeleton files automatically.
- Always run **`apt update`** before installing any package on Ubuntu — unlike `yum`/`dnf`, it does not refresh the package list automatically.
- **`apt remove`** keeps config files; **`apt purge`** removes everything cleanly. Use `purge` for a complete uninstall.
- On Ubuntu, services installed via `apt` are **started and enabled automatically** — you don't need to run `systemctl start` and `systemctl enable` manually.
- **`dpkg`** is the low-level Debian package tool (like `rpm` for CentOS) — it doesn't handle dependencies. Use `apt` for that.
- Run **`export EDITOR=vim`** before `visudo` on Ubuntu if you prefer vim over nano. Making this permanent is covered in Bash Scripting.
- Ubuntu's repository ecosystem is larger than CentOS's — `apt update` gives you access to a very wide range of software.
