# Filters in Linux

## 1. What are Filters?

Filters are commands that help you **find, read, extract, and transform** data from files. Instead of reading entire files manually, filters let you pull exactly the information you need — a critical skill for system administration and scripting.

Key filter commands covered here:

- `grep` — search for text in files
- `less` / `more` — file readers
- `head` / `tail` — view first or last lines
- `cut` — extract specific columns
- `awk` — intelligent column extraction
- `sed` — search and replace across files

---

## 2. `grep` — Search for Text in Files

`grep` finds lines in a file that contain a specific word or pattern.

### Basic Usage
```bash
grep firewall anaconda-ks.cfg
# Shows all lines containing the word "firewall"
```

### Common Options

| Option | Meaning | Example |
|---|---|---|
| `-i` | Case-insensitive search | `grep -i firewall file.txt` |
| `-R` | Search recursively into subdirectories | `grep -iR firewall /etc/*` |
| `-v` | Inverse — show lines that do NOT match | `grep -v firewall file.txt` |

### Searching Multiple Files
```bash
grep -i firewall *              # Search all files in current directory
grep -iR firewall /etc/*       # Search all files and subdirectories in /etc
```

When searching multiple files, grep shows the **filename** alongside each result.

> If a directory is in the search path, grep throws an error unless you use `-R` to recurse into it.

### Real-World Use Case — Finding a Config Setting
You know a setting exists somewhere in `/etc` but don't know which file:
```bash
grep -R SELINUX /etc/*
# Finds all files in /etc that contain the word SELINUX
```

Once you find the file, open it with vim, make the change, and save. This is the standard sysadmin workflow — you don't need to memorize file locations, just search for the setting.

> **SELINUX** (Security-Enhanced Linux) is often switched from `enforcing` to `permissive` or `disabled`. Searching for it is a real example of this workflow.

### Inverse Search with `-v`
```bash
grep -iv firewall anaconda-ks.cfg
# Shows every line EXCEPT lines containing "firewall" (case-insensitive)
```

Useful when you want to exclude certain content from your view. The result is a very long list — everything that does not match.

## 3. `less` and `more` — File Readers

### `less`
Opens a file in a scrollable, interactive reader. Better than `cat` for large files since `cat` dumps everything at once.

```bash
less /var/log/messages
```

| Key | Action |
|---|---|
| `↑` / `↓` | Scroll up and down |
| `/word` | Search for a word inside the file |
| `n` | Jump to next search match |
| `q` | Quit the reader |

### `more`
Similar to `less` but more limited — no up-arrow scrolling, navigation is forward only.

```bash
more /var/log/messages
```

- Navigate with `Enter` (line by line) or `Space` (page by page)
- Shows progress as a percentage through the file
- Press `q` to quit early, or read to the end

> `less` is generally more useful than `more`. Use `less` by default.

## 4. `head` and `tail` — View Start or End of a File

### `head` — First Lines of a File
```bash
head /etc/passwd            # Show first 10 lines (default)
head -20 /etc/passwd        # Show first 20 lines
head -2 /etc/passwd         # Show first 2 lines only
```

### `tail` — Last Lines of a File
```bash
tail /var/log/messages      # Show last 10 lines (default)
tail -20 /var/log/messages  # Show last 20 lines
```

### `tail -f` — Live Log Monitoring (Follow Mode)
The `-f` (follow) option keeps the file open and **displays new lines in real time** as they are written to the file. This is essential for troubleshooting.

```bash
tail -f /var/log/messages
# Stays open; shows new log entries live as they appear
# Press Ctrl+C to quit
```

**Practical use:** Open two terminal sessions — tail a log in one, perform an action (like an SSH login) in the other, and watch the event appear in the log instantly.

### Log Files Location
```bash
ls /var/log/                    # System and service log files
tail -f /var/log/messages       # Main system log on Red Hat / CentOS
tail -f /var/log/yum.log        # Yum package manager activity log
```

> **Sysadmin tip:** When troubleshooting a server, always start with the log files. Keep `tail -f` running in one shell while you make changes in another — you'll see errors appear in real time.

## 5. `cut` — Extract Specific Columns

`cut` extracts specific fields (columns) from a structured file. It works best when columns are separated by a consistent **delimiter** (like `:` or `,`).

### Example — `/etc/passwd`
This file stores user information, with columns separated by colons (`:`):

```
root:x:0:0:root:/root:/bin/bash
vagrant:x:1000:1000:vagrant:/home/vagrant:/bin/bash
```

| Column (Field) | Content |
|---|---|
| 1 | Username |
| 2 | Password placeholder |
| 3 | User ID |
| 4 | Group ID |
| 5 | Description |
| 6 | Home directory |
| 7 | Shell |

### Usage
```bash
cut -d: -f1 /etc/passwd         # Get column 1 (usernames)
cut -d: -f3 /etc/passwd         # Get column 3 (user IDs)
cut -d: -f4 /etc/passwd         # Get column 4 (group IDs)
```

| Option | Meaning |
|---|---|
| `-d:` | Delimiter is `:` (colon) |
| `-f1` | Field (column) number to extract |

> `cut` requires a **consistent delimiter**. If the file doesn't have clean separators, use `awk` instead.

---

## 6. `awk` — Intelligent Column Extraction

`awk` is a powerful text-processing tool that handles more complex filtering. It supports regular expressions and custom logic, making it more flexible than `cut`.

### Basic Example — Get First Column (like `cut`)
```bash
awk -F':' '{print $1}' /etc/passwd
# Same result as: cut -d: -f1 /etc/passwd
```

| Part | Meaning |
|---|---|
| `-F':'` | Field separator is `:` |
| `{print $1}` | Print the first field/column |
| `$2`, `$3`... | Second, third columns etc. |

> `awk` is more powerful than `cut` for complex filtering. We'll explore more `awk` features later in the course.

## 7. Search and Replace

### Method 1 — Inside Vim (Single File)

Open the file in vim, then in extended mode use:

```
:%s/search_term/replacement/
```

**Examples:**
```vim
:%s/coronavirus/covid-19/       " Replace first occurrence per line
:%s/coronavirus/covid-19/g      " Replace ALL occurrences (g = global)
:%s/covid-19//g                 " Replace with nothing (effectively delete the word)
```

| Command | Meaning |
|---|---|
| `%s` | Apply substitution to all lines in the file |
| `/old/new/` | Replace "old" with "new" |
| `/g` | Global — replace every occurrence, not just the first per line |

> Without `/g`, only the **first occurrence** on each line is replaced.

---

### Method 2 — `sed` Command (Single or Multiple Files)

`sed` (Stream Editor) performs search and replace from the command line, without opening a file in an editor. Ideal for bulk changes across many files.

**Basic syntax:**
```bash
sed 's/search/replace/g' filename
```

**Examples:**
```bash
sed 's/coronavirus/covid-19/g' sample.txt      # Print result (file unchanged)
sed 's/coronavirus/covid-19/g' *.txt           # Apply to all .txt files
sed 's/coronavirus/covid-19/g' *              # Apply to all files in current dir
```

> By default, `sed` only **prints** the result to the screen — it does not modify the file.

### Making Changes Permanent with `-i`
```bash
sed -i 's/coronavirus/covid-19/g' sample.txt
# Now actually modifies the file
```

**Recommended workflow:**
```bash
# Step 1: Preview changes (no -i)
sed 's/coronavirus/covid-19/g' sample.txt

# Step 2: Apply changes once confirmed (add -i)
sed -i 's/coronavirus/covid-19/g' sample.txt
```

### Replace with Nothing (Delete a Word)
```bash
sed -i 's/covid-19//g' sample.txt
# Deletes every occurrence of "covid-19" from the file
```

## 8. Quick Reference Summary

| Command | What it does |
|---|---|
| `grep word file` | Search for a word in a file |
| `grep -i word file` | Case-insensitive search |
| `grep -R word /path/*` | Recursive search through directories |
| `grep -v word file` | Show lines that do NOT contain the word |
| `less file` | Scrollable file reader (use `q` to quit) |
| `more file` | Forward-only file reader |
| `head file` | Show first 10 lines |
| `head -n file` | Show first n lines |
| `tail file` | Show last 10 lines |
| `tail -n file` | Show last n lines |
| `tail -f file` | Follow file in real time (live log monitoring) |
| `cut -d: -f1 file` | Extract column 1, delimited by `:` |
| `awk -F':' '{print $1}' file` | Extract column 1 using awk |
| `sed 's/old/new/g' file` | Preview search and replace |
| `sed -i 's/old/new/g' file` | Apply search and replace to file |
| `sed -i 's/word//g' file` | Delete a word from a file |

---

## 9. Key Takeaways

- `grep` is one of the most useful commands in Linux — use it to find settings in config files without memorizing file locations.
- Linux is **case-sensitive** everywhere: `grep firewall` and `grep Firewall` return different results. Use `-i` to ignore case.
- `grep -R` is essential for searching through entire directory trees like `/etc`.
- `tail -f` is the go-to tool for **live log monitoring** during troubleshooting.
- `cut` is great for structured files with consistent delimiters. When the structure is irregular, use `awk`.
- In vim, `:%s/old/new/g` does global search-and-replace. Don't forget `/g` or only the first match per line is replaced.
- With `sed`, always **preview first** (without `-i`), then apply changes (with `-i`). It's a safer workflow.
- Most Linux system administration work follows this pattern: **search for the setting → find the file → edit it → save it**. Filters make this workflow fast and efficient.
