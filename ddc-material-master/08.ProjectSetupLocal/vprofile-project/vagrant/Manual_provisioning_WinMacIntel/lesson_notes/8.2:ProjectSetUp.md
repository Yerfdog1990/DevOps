# VM Setup with Vagrant

## 📌 Overview

In this section, we set up all the **virtual machines** required for the VProfile project stack using a **Vagrantfile**. The setup is automated, meaning all five VMs (DB, Memcache, RabbitMQ, Tomcat, Nginx) are provisioned with a single command.

## 🔌 Step 4: About the Vagrant Host Manager Plugin

### What is a Plugin?
A plugin adds **extra features** to an existing tool. The `vagrant-hostmanager` plugin adds **automatic hostname-to-IP mapping** across all VMs.

### What does it do?
- Automatically updates the `/etc/hosts` file on **every VM**
- Maps each VM's hostname to its IP address
- Example entries it creates:

```
192.168.56.15   db01
192.168.56.14   mc01
192.168.56.13   rmq01
192.168.56.12   app01
192.168.56.11   web01
```

- Without this, VMs would not be able to resolve each other's names
- In our configuration files, we reference services **by name** (e.g., `app01`, `db01`) — this plugin makes that work

### Vagrantfile settings that enable this:
```ruby
config.hostmanager.enabled = true
config.hostmanager.manage_host = true
```

## 📄 Understanding the Vagrantfile

This is a **multi-VM Vagrantfile** defining **5 virtual machines**:

| VM Name | Service | Box / OS | IP Address | Memory | Notes |
|---|---|---|---|---|---|
| `db01` | MySQL (Database) | `generic/centos9s` | `192.168.56.15` | 600 MB | |
| `mc01` | Memcached | `generic/centos9s` | `192.168.56.14` | 600 MB | |
| `rmq01` | RabbitMQ | `generic/centos9s` | `192.168.56.13` | 600 MB | |
| `app01` | Apache Tomcat | `generic/centos9s` | `192.168.56.12` | 800 MB | |
| `web01` | Nginx | `ubuntu/jammy64` | `192.168.56.11` | 800 MB | GUI enabled (`vb.gui = true`) |

### Key Vagrantfile settings:
- Each VM has a defined **hostname**, **static private IP**, and **memory size**
- The first four VMs use **CentOS 9 Stream** (`generic/centos9s`)
- The Nginx VM (`web01`) uses **Ubuntu 22.04 LTS Jammy** (`ubuntu/jammy64`)
- Memory is set to the **minimum** so most computers can run it
- If you have **16 GB+ RAM**, you can increase memory to `1024 MB` (1 GB) per VM for better performance
- `web01` has `vb.gui = true` — this means VirtualBox will open a **graphical console window** for this VM

### Global settings at the top of the Vagrantfile:
```ruby
config.hostmanager.enabled = true
config.hostmanager.manage_host = true
```
These two lines activate the `vagrant-hostmanager` plugin for all VMs in the file.

## 🚀 Step 5: Bring Up the Virtual Machines

### Pre-flight Check — Remove Any Existing VMs

Check for any running VMs first:
```bash
vagrant global-status
```

If any VMs are listed, navigate to their directory and destroy them:
```bash
vagrant destroy
```

Then clean up stale entries:
```bash
vagrant global-status --prune
```

### Bring Up All VMs:
```bash
vagrant up
```

> ⏳ **NOTE:** Bringing up all VMs may take a long time based on your system and internet speed.

> 🔄 **If VM setup stops in the middle**, simply run `vagrant up` again to resume.

> ℹ️ **INFO:** All VM hostnames and `/etc/hosts` file entries will be **automatically updated** by the `vagrant-hostmanager` plugin — no manual editing required.

> 🔑 If prompted for a password — enter **your computer's login password**, not a VM password. Most users won't be prompted at all.

### Troubleshooting — Timeout Errors:
If a VM times out during boot:
```bash
vagrant reload <vm-name>    # Reboot a specific VM
# or
vagrant reload              # Reboot all VMs
```

Then run `vagrant up` again if needed.

### Log into a VM:
```bash

```

You should see the hostname `web01` in the terminal prompt — confirming the hostname is set correctly.

### Switch to Root User:
```bash

sudo su -
```

### Check the `/etc/hosts` File:
```bash
cat /etc/hosts
```

You should see all VM hostnames and IPs automatically populated — this was done by the `vagrant-hostmanager` plugin. **You did not add these manually.**

**Expected output (from `web01`):**
```
127.0.0.1       localhost
# The following lines are desirable for IPv6 capable hosts
::1     ip6-localhost   ip6-loopback
fe00::0 ip6-localnet
ff00::0 ip6-mcastprefix
ff02::1 ip6-allnodes
ff02::2 ip6-allrouters
ff02::3 ip6-allhosts
127.0.1.1       ubuntu-jammy    ubuntu-jammy
127.0.2.1 web01 web01
## vagrant-hostmanager-start
192.168.56.13   rmq01
192.168.56.11   web01
192.168.56.14   mc01
192.168.56.12   app01
192.168.56.15   db01

```

> 💡 The entries between `## vagrant-hostmanager-start` and `## vagrant-hostmanager-end` are **automatically injected** by the plugin — this is how all VMs can resolve each other by hostname without a DNS server.

### Test VM Connectivity:
```bash
ping app01 -c 4
```

- `-c 4` = send 4 packets
- If you get replies → the VMs can communicate ✅
- If you get timeouts → reboot the target VM (`vagrant reload app01`)

## 📋 Service Setup Order

Once all VMs are up and running (bare OS), services must be **installed and configured in a specific order**:

### 🔼 Startup Order (Setup / Boot):
```
1. MySQL      (db01)    ← Set up first — everything depends on DB
2. Memcached  (mc01)    ← Depends on MySQL being available
3. RabbitMQ   (rmq01)   ← Backend messaging service
4. Tomcat     (app01)   ← Application server
5. Nginx      (web01)   ← Frontend/load balancer — set up last
```

### 🔽 Shutdown Order (Reverse):
```
1. Nginx      (web01)   ← Cut user access first
2. Tomcat     (app01)
3. RabbitMQ   (rmq01)
4. Memcached  (mc01)
5. MySQL      (db01)    ← Database shuts down last
```

> 📌 **Why this order?**
> - The database must be running before any service that depends on it (Memcache, Tomcat) starts
> - Some applications **mandatorily** require the database to be up before they can start
> - For shutdown: always stop user-facing services first to prevent data corruption or failed requests
> - This is a **standard best practice** in production environments

## 📄 Full Vagrantfile (Reference)

```ruby
Vagrant.configure("2") do |config|
  config.hostmanager.enabled = true
  config.hostmanager.manage_host = true

  ### DB VM ###
  config.vm.define "db01" do |db01|
    db01.vm.box = "generic/centos9s"
    db01.vm.hostname = "db01"
    db01.vm.network "private_network", ip: "192.168.56.15"
    db01.vm.provider "virtualbox" do |vb|
      vb.memory = "600"
    end
  end

  ### Memcache VM ###
  config.vm.define "mc01" do |mc01|
    mc01.vm.box = "generic/centos9s"
    mc01.vm.hostname = "mc01"
    mc01.vm.network "private_network", ip: "192.168.56.14"
    mc01.vm.provider "virtualbox" do |vb|
      vb.memory = "600"
    end
  end

  ### RabbitMQ VM ###
  config.vm.define "rmq01" do |rmq01|
    rmq01.vm.box = "generic/centos9s"
    rmq01.vm.hostname = "rmq01"
    rmq01.vm.network "private_network", ip: "192.168.56.13"
    rmq01.vm.provider "virtualbox" do |vb|
      vb.memory = "600"
    end
  end

  ### Tomcat VM ###
  config.vm.define "app01" do |app01|
    app01.vm.box = "generic/centos9s"
    app01.vm.hostname = "app01"
    app01.vm.network "private_network", ip: "192.168.56.12"
    app01.vm.provider "virtualbox" do |vb|
      vb.memory = "800"
    end
  end

  ### Nginx VM ###
  config.vm.define "web01" do |web01|
    web01.vm.box = "ubuntu/jammy64"
    web01.vm.hostname = "web01"
    web01.vm.network "private_network", ip: "192.168.56.11"
    web01.vm.provider "virtualbox" do |vb|
      vb.gui = true
      vb.memory = "800"
    end
  end

end
```

| Concept | Explanation |
|---|---|
| **Multi-VM Vagrantfile** | A single Vagrantfile that defines and manages multiple VMs |
| **vagrant-hostmanager** | Plugin that auto-populates `/etc/hosts` with hostname-to-IP mappings across all VMs |
| **`/etc/hosts`** | A local file that resolves hostnames to IPs — checked before querying DNS |
| **Manual Provisioning** | VMs are brought up automatically, but services are installed/configured manually step by step |
| **`vagrant global-status`** | Lists all Vagrant-managed VMs and their state |
| **`vagrant global-status --prune`** | Cleans up stale/invalid VM entries from Vagrant's records |
