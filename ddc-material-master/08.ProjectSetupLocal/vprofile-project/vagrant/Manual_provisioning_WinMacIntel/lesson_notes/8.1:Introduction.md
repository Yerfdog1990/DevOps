# Introduction to VProfile Project

## 📌 Project Overview

**Project Name:** V Profile Project — Local Setup

The VProfile Project involves setting up a **multi-tier web application stack** locally on your laptop or desktop. The application itself is a **social networking site written in Java**, and the goal is to automate the entire local environment setup using infrastructure-as-code principles.

---

## 🎯 Why Are We Doing This Project?

### Reason 1: Baseline for Upcoming Projects
This project serves as the **foundation** for a series of advanced projects, including:
- Deploying the stack on the cloud
- Refactoring the architecture
- Containerizing applications (Docker)
- Deploying on a Kubernetes cluster
- And many more...

Understanding the VProfile Project first is essential before moving on to any of these advanced topics.

### Reason 2: Setting Up a Local Lab for R&D
- Allows you to **replicate real-world project stacks** on your local machine
- Great for experimenting, testing, and gaining confidence before touching production systems

---

## 🔴 The Problem: Why Local Setup Is Hard

In a real-world scenario, your project may involve multiple services like:
- **Database services** — MySQL, PostgreSQL
- **Web services** — Apache, Nginx
- **Application services** — Tomcat, JBoss, GlassFish

You might have a Runbook or setup document, but manually setting up all these services has serious drawbacks:

| Problem | Description |
|---|---|
| **Complex** | Multiple interdependent services are difficult to configure manually |
| **Time-consuming** | Manual setup takes significant time |
| **Not repeatable** | You can't easily redo or rebuild the environment from scratch |
| **Lack of confidence** | Developers/DevOps engineers may be hesitant to make changes on real servers |

---

## ✅ The Solution: Automated, Repeatable Local Setup

The solution is to use **Infrastructure as Code (IaC)** to automate the local setup:

- ✔️ **Automated** — No manual intervention required
- ✔️ **Repeatable** — Run the setup as many times as needed
- ✔️ **Consistent** — Same environment every time
- ✔️ **R&D Friendly** — Experiment freely on your local machine without risk

## 🏗️ Application Stack Architecture

The VProfile application is a **Java-based social networking web application**. It uses the following services working together as a stack:

```
User (Browser)
    │
    ▼
[ Nginx ] ← Load Balancer / Web Server
    │
    ▼
[ Apache Tomcat ] ← Java Web Application Server (hosts the app)
    │          │
    │          ▼
    │     [ RabbitMQ ] ← Message Broker / Queuing Agent
    │
    ▼
[ Memcached ] ← Database Caching Layer
    │
    ▼
[ MySQL ] ← Relational Database (stores user info)
```

---

## 🔍 Service-by-Service Breakdown

### 1. 🌐 Nginx (Load Balancer)
- Acts as the **entry point** for the application
- The user enters the **IP address** of the Nginx server in the browser
- Nginx routes incoming requests to the **Apache Tomcat** server
- Commonly used as a **load balancer and reverse proxy**
- Similar to Apache HTTPD but widely preferred for load balancing

### 2. ☕ Apache Tomcat (Application Server)
- A **Java Web Application Service** — used to host Java-based web apps
- The VProfile application code (written in Java by developers) lives here
- Handles all application logic and user interactions
- Can connect to **NFS (Network File System)** for shared/centralized external storage across a cluster of servers

### 3. 🐇 RabbitMQ (Message Broker)
- A **Message Broker / Queuing Agent** used to connect applications together
- In this project, it is used as a **dummy service** to add realistic complexity
- In real-world use: used for **data streaming** and **decoupling services**
- As a DevOps engineer, you should know it exists and what its role is

### 4. ⚡ Memcached (Database Caching)
- A **database caching service** connected to MySQL
- **How it works:**
    1. User logs in → request goes to Memcached first
    2. If data is not cached → fetched from MySQL and then **cached in Memcached**
    3. Next time the same request comes → served directly from cache (faster!)
- Similar concept to **browser cache**, but at the database level
- Very widely used in production environments

### 5. 🗄️ MySQL (Database)
- Stores all **user information** (usernames, passwords, etc.)
- When a user logs in, the application runs an **SQL query** to verify credentials
- Works in conjunction with Memcached to optimize performance

## 🤖 Automation Stack Architecture

```
[ Vagrant ]
    │
    ▼
[ Oracle VM VirtualBox ] ← Hypervisor
    │
    ▼
[ Virtual Machines ]
    ├── VM 1: Nginx
    ├── VM 2: Apache Tomcat
    ├── VM 3: Memcached
    ├── VM 4: RabbitMQ
    └── VM 5: MySQL
```

- **Vagrant** communicates with **VirtualBox** to automatically create VMs
- **Bash scripts/commands** are used to set up each service on its respective VM
- Everything is driven by a **Vagrantfile** (the infrastructure-as-code definition)

## 🔄 Flow of Execution (Step-by-Step)

| Step | Action |
|---|---|
| 1 | Set up all prerequisite tools (VirtualBox, Vagrant, Git Bash, IDE) |

| 9 | Set up **Apache Tomcat** service |

| 11 | Build and deploy the Java application to Tomcat |
| 12 | Verify everything by accessing the app through the browser |

## 💡 Key Concepts to Understand

| Concept | Explanation |
|---|---|
| **Stack** | A collection of services working together to deliver a web application experience |
| **Infrastructure as Code (IaC)** | Managing infrastructure through code/scripts instead of manual configuration |
| **Load Balancer** | Distributes incoming traffic to backend servers (here: Nginx → Tomcat) |
| **Message Broker** | Middleware that allows services to communicate asynchronously (RabbitMQ) |
| **Database Caching** | Stores frequently accessed DB query results in memory for faster retrieval (Memcached) |
| **NFS (Network File System)** | Shared centralized storage accessible by multiple servers in a cluster |
| **Hypervisor** | Software that creates and manages virtual machines (VirtualBox) |

---

## 🧠 Why DevOps Engineers Need to Understand the Stack

As a DevOps engineer, you are more focused on **implementation** than functionality — but understanding the flow is critical for **troubleshooting**:

> **Example:**
> - ❌ Web page not loading → Problem likely in **Nginx or Tomcat**
> - ❌ User can't log in (but page loads) → Problem likely in **MySQL or Memcached**
> - ❌ Application slowness → Could be **Memcached** not caching properly

Understanding the service flow helps you quickly **identify where issues originate** without having to be a deep expert in each individual service.
