# Database Setup — MySQL (MariaDB) 

## 📌 Overview

The database is the **first service** to be set up in the VProfile stack. All other services (Memcache, Tomcat, etc.) depend on the database being up and configured correctly before they can start.

> 💡 **If you took a long break** since the last session, reboot all VMs first:
> ```bash
> vagrant reload
> ```
> If you are continuing directly from the previous lecture, skip this step.


```bash
systemctl start mariadb
systemctl enable mariadb
```

Verify the service is running:
```bash
systemctl status mariadb
```

You should see **`Active: active (running)`** in the output. Press `q` to exit the status view.

## 🔐 Step 7: Run MySQL Secure Installation

This script walks through a series of security questions to harden the database:

```bash
mysql_secure_installation
```

### Answer each prompt as follows:

| Prompt | Answer | Notes |
|---|---|---|
| Enter current password for root | *(just press Enter)* | No password set yet on a fresh install |
| Switch to unix_socket authentication | *(press Enter — defaults to Y)* | |
| Set root password? | `Y` | |
| New password | `admin123` | Use a long, complex password in production |
| Re-enter new password | `admin123` | |
| Remove anonymous users? | `Y` | Prevents passwordless logins |
| Disallow root login remotely? | `n` | Skip — root remote login not needed here |
| Remove test database and access to it? | `Y` | Removes default test DB |
| Reload privilege tables now? | `Y` | Applies all changes immediately |

### Expected output summary:
```

New password:
Re-enter new password:
Password updated successfully!
Reloading privilege tables..
 ... Success!

Remove anonymous users? [Y/n] Y
 ... Success!

Disallow root login remotely? [Y/n] n
 ... skipping.

Remove test database and access to it? [Y/n] Y
 - Dropping test database...
 ... Success!
 - Removing privileges on test database...
 ... Success!

Reload privilege tables now? [Y/n] Y
 ... Success!
```

> ⚠️ **Important:** The root password here is the **database root user** password — NOT your Linux system root password.

## 🗄️ Step 8: Create Database and Users

Log into the MySQL shell:

```bash
mysql -u root -padmin123
```

> ⚠️ Entering the password directly in the command (`-padmin123`) is shown here for convenience only. In production, always use `-p` alone and enter the password when prompted to avoid it being stored in shell history.

### Create the database:

```sql
mysql> create database accounts;
```

> The VProfile application specifically requires a database named **`accounts`** — this name is hardcoded in the application configuration.

### Create user with local access:

```sql
mysql> grant all privileges on accounts.* TO 'admin'@'localhost' identified by 'admin123';
```

### Create user with remote access:

```sql
mysql> grant all privileges on accounts.* TO 'admin'@'%' identified by 'admin123';
```

> 📝 **Why two grants?**
> - `'admin'@'localhost'` — allows the admin user to connect **locally** from the DB VM itself
> - `'admin'@'%'` — the `%` is a wildcard meaning **from any host**. The VProfile application runs on `app01` (Tomcat VM) and connects to this database remotely, so this remote access grant is required

### Flush privileges and exit:

```sql
mysql> FLUSH PRIVILEGES;
mysql> exit;
```

> `FLUSH PRIVILEGES` reloads the grant tables — acts like a reload to ensure all changes take effect immediately.

## 💾 Step 9: Download Source Code & Initialize Database

### Clone the source code (on the `main` branch):

```bash
cd /tmp
git clone -b main https://github.com/hkhcoder/vprofile-project.git
```

### Navigate into the project:

```bash
cd vprofile-project
```

### Run the SQL dump to initialize the database schema:

```bash
mysql -u root -padmin123 accounts < src/main/resources/db_backup.sql
```

> 📝 **What is a DB dump / DB backup SQL file?**
> - A `.sql` file containing pre-written SQL queries (schema definitions, table structures, seed data)
> - Provided by developers to initialize the database with the correct structure
> - The `<` symbol is **input redirection** — it feeds the SQL file directly into the MySQL command
> - In real-world projects, this is called **initializing the database** — sometimes done manually like this, sometimes automatically by the application on first startup

### Verify the schema was loaded correctly:

Log into the `accounts` database directly:
```bash
mysql -u root -padmin123 accounts
```

Check the tables:
```sql
mysql> show tables;
```

You should see the tables created by the SQL dump. Then check all databases:
```sql
mysql> show databases;
```

You should see `accounts` listed alongside system databases (`mysql`, `information_schema`, `performance_schema`).

Exit the MySQL shell:
```sql
mysql> exit;
```

## 🔥 Step 11: Configure Firewall

Start and enable the firewall service, then open port `3306` (the default MySQL/MariaDB port) so other VMs can connect to the database:

```bash
systemctl start firewalld
systemctl enable firewalld
```

Check active firewall zones:
```bash
firewall-cmd --get-active-zones
```

Open port 3306 permanently:
```bash
firewall-cmd --zone=public --add-port=3306/tcp --permanent
```

Reload firewall to apply changes:
```bash
firewall-cmd --reload
```

Restart MariaDB after firewall changes:
```bash
systemctl restart mariadb
```

> 📝 **What is port 3306?**
> Port `3306` is the default port that MySQL/MariaDB listens on. By opening this port in the firewall, we allow other VMs (like `app01` running Tomcat) to connect to the database over the private network.

## 🧠 Key Concepts

| Concept | Explanation |
|---|---|
| **MariaDB** | An open-source fork of MySQL — fully compatible, used as a drop-in replacement |
| **Package vs Service name** | `mariadb-server` is the package name; `mariadb` is the service name — they can differ |
| **`mysql_secure_installation`** | A built-in script to set root password and remove insecure defaults from a fresh DB install |
| **DB Dump / db_backup.sql** | A SQL file provided by developers containing the schema and initial data to set up the database |
| **`FLUSH PRIVILEGES`** | Forces MariaDB to reload the grant/privilege tables so changes take effect immediately |
| **`@'%'` in GRANT** | Wildcard meaning the user can connect from **any host** — required for remote app connections |
| **Port 3306** | The default port MySQL/MariaDB listens on for incoming connections |
| **Input Redirection (`<`)** | Shell operator that feeds a file as input to a command — used to run the SQL dump file |
| **Initializing the Database** | The process of loading the schema and seed data into a fresh database so the app can use it |

## ✅ Verification Checklist

Before moving to the next service (Memcache), confirm:

- [ ] MariaDB service is **active and running** (`systemctl status mariadb`)
- [ ] Root password is set to `admin123`
- [ ] Database `accounts` has been created
- [ ] Admin user has both local (`localhost`) and remote (`%`) access grants
- [ ] `db_backup.sql` has been imported — `show tables;` returns results
- [ ] Firewall is running and port `3306` is open
- [ ] MariaDB has been restarted after all changes
