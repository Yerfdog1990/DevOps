# Tomcat Setup 

## Overview

Tomcat is the Java application server that hosts and runs the vProfile web application. It runs on its own VM (`app01`). Unlike MySQL or Memcached, Tomcat is **not installed from a package manager** — instead the binary is downloaded directly and set up manually, including creating a dedicated system user and registering it as a `systemctl`-managed service.

This is a two-part setup:
1. **Tomcat service setup** — install, configure, and start the Tomcat service
2. **Application deployment** — build the vProfile source code with Maven and deploy it onto Tomcat

This document covers Part 1. See the **Application Deployment** notes for Part 2.

---

## Part 1: Tomcat Service Setup

### 1. Log Into the Tomcat VM

```bash
vagrant ssh app01
```

Then switch to the root user:

```bash
sudo -i
```

---

### 2. Verify `/etc/hosts` Entries

Ensure all VMs in the stack are resolvable by hostname:

```bash
cat /etc/hosts
```

If any entries are missing, add them manually with the correct IP addresses and hostnames. This is critical — the vProfile application uses hostnames like `db01`, `mc01`, and `rmq01` to connect to backend services.

---

### 3. Update the OS

```bash
yum update -y
```

---

### 4. Set EPEL Repository

```bash
yum install epel-release -y
```

---

### 5. Install Dependencies

Install Java 11 (required to run Tomcat), Git, Maven, and wget:

```bash
dnf -y install java-11-openjdk java-11-openjdk-devel
dnf install git maven wget -y
```

> The vProfile project uses **Java 11** and **Tomcat 9**. The instructor's video references JDK 17 and Tomcat 10 for a different variant of the project — follow the commands in this document for consistency with the reference material.

---

### 6. Download the Tomcat Binary

Navigate to the `/tmp` directory and download the Tomcat 9 tarball directly from the Apache archive:

```bash
cd /tmp/
wget https://archive.apache.org/dist/tomcat/tomcat-9/v9.0.75/bin/apache-tomcat-9.0.75.tar.gz
```

> Tomcat is not available via `dnf install`. The binary is downloaded directly and set up manually.

---

### 7. Extract the Tarball

```bash
tar xzvf apache-tomcat-9.0.75.tar.gz
```

You should now have a folder called `apache-tomcat-9.0.75` in `/tmp/`.

---

### 8. Create the Tomcat System User

Create a dedicated `tomcat` user with a home directory at `/usr/local/tomcat` and no login shell (a system/service account):

```bash
useradd --home-dir /usr/local/tomcat --shell /sbin/nologin tomcat
```

**What this does:**

- `--home-dir /usr/local/tomcat` — sets the home directory and also creates the folder
- `--shell /sbin/nologin` — prevents anyone from logging in interactively as this user, which is correct for a service account

---

### 9. Copy Tomcat Files to the Home Directory

Copy all extracted Tomcat files into the tomcat user's home directory:

```bash
cp -r /tmp/apache-tomcat-9.0.75/* /usr/local/tomcat/
```

---

### 10. Set Correct Ownership

By default the copied files will be owned by `root`. Change ownership recursively to the `tomcat` user and group:

```bash
chown -R tomcat.tomcat /usr/local/tomcat
```

Verify:

```bash
ls -l /usr/local/tomcat/
```

All files and directories should now show `tomcat tomcat` as the owner.

---

### 11. Create the Tomcat systemd Service File

Create a new systemd unit file so Tomcat can be managed with `systemctl`:

```bash
vi /etc/systemd/system/tomcat.service
```

Enter insert mode (`i`) and paste the following content exactly:

```ini
[Unit]
Description=Tomcat
After=network.target

[Service]
User=tomcat
WorkingDirectory=/usr/local/tomcat
Environment=JRE_HOME=/usr/lib/jvm/jre
Environment=JAVA_HOME=/usr/lib/jvm/jre
Environment=CATALINA_HOME=/usr/local/tomcat
Environment=CATALINA_BASE=/usr/local/tomcat
ExecStart=/usr/local/tomcat/bin/catalina.sh run
ExecStop=/usr/local/tomcat/bin/shutdown.sh
SyslogIdentifier=tomcat-%i

[Install]
WantedBy=multi-user.target
```

Save and exit: press `Esc`, then type `:wq` and hit `Enter`.

**Key fields explained:**

| Field | Purpose |
|-------|---------|
| `After=network.target` | Ensures Tomcat starts only after the network is ready |
| `User=tomcat` | Runs the service as the `tomcat` system user |
| `CATALINA_HOME` / `CATALINA_BASE` | Tells Tomcat where its installation and config directories are |
| `ExecStart` | Command to start Tomcat |
| `ExecStop` | Command to gracefully shut down Tomcat |
| `WantedBy=multi-user.target` | Enables Tomcat to start in normal multi-user runlevel |

---

### 12. Reload systemd

After creating or modifying any systemd unit file, reload the daemon so it picks up the changes:

```bash
systemctl daemon-reload
```

> **Rule:** Always run `systemctl daemon-reload` after adding or editing a `.service` file.

---

### 13. Start and Enable Tomcat

```bash
systemctl start tomcat
systemctl enable tomcat
```

Verify the service is running:

```bash
systemctl status tomcat
```

The output should show `active (running)`. Press `q` to exit.

---

### 14. Configure the Firewall

Start and enable the firewall, then open port 8080 (Tomcat's default HTTP port):

```bash
systemctl start firewalld
systemctl enable firewalld
firewall-cmd --get-active-zones
firewall-cmd --zone=public --add-port=8080/tcp --permanent
firewall-cmd --reload
```

**What each command does:**

| Command | Purpose |
|---------|---------|
| `systemctl start firewalld` | Starts the firewall service |
| `systemctl enable firewalld` | Enables firewall on boot |
| `--get-active-zones` | Shows which firewall zones are currently active |
| `--zone=public --add-port=8080/tcp --permanent` | Permanently opens port 8080 in the public zone |
| `--reload` | Applies the permanent rule to the running firewall |

## Key Concepts

| Concept | Explanation |
|---------|-------------|
| **Tomcat** | A Java servlet container — it hosts and runs Java web applications packaged as `.war` files |
| **Service account** | A user like `tomcat` created solely to run a service; `nologin` shell prevents interactive use |
| **systemd unit file** | A configuration file that defines how a service is started, stopped, and managed by `systemctl` |
| **daemon-reload** | Required after any change to systemd unit files; tells systemd to re-read its config |
| **Port 8080** | Tomcat's default HTTP port; different from the standard web port 80 |

---

## Key Port

| Port | Protocol | Purpose |
|------|----------|---------|
| 8080 | TCP | Tomcat HTTP access for the vProfile web application |
