# RabbitMQ Setup 

## Overview

RabbitMQ is a message broker (queuing service) used in the vProfile stack to handle asynchronous communication between services. It runs on its own VM (`rmq01`). Setup involves installing RabbitMQ from its own repository, creating an application user, assigning administrator permissions, configuring the firewall, and verifying the service is running.

---

## Setup Steps

### 1. Log Into the RabbitMQ VM

```bash
vagrant ssh rmq01
```

Make sure you are in the correct project folder before SSHing in. Then switch to the root user:

```bash
sudo -i
```

---

### 2. Verify `/etc/hosts` Entries

Ensure all VMs in the stack are resolvable by hostname:

```bash
cat /etc/hosts
```

If any entries are missing, add them manually with the correct IP addresses and hostnames for each VM in the stack.

---

### 3. Update the OS

Apply the latest patches:

```bash
yum update -y
```

> This step can take time. It is optional for lab environments but good practice before any software installation.

---

### 4. Install Prerequisites

Install the EPEL repository and `wget`:

```bash
sudo yum install epel-release -y
sudo yum install wget -y
```

> `wget` may already be installed on your system — that is fine, the command will simply confirm it.

---

### 5. Install the RabbitMQ Repository

Navigate to the `/tmp` directory, then install the official CentOS RabbitMQ repository package. RabbitMQ is not available in the default Rocky/CentOS repositories, so this step registers the correct package source:

```bash
cd /tmp/
dnf -y install centos-release-rabbitmq-38
```

This sets up the repository so the next step can pull RabbitMQ packages from the correct source.

---

### 6. Install RabbitMQ Server

Enable the newly added repository and install RabbitMQ in a single command:

```bash
dnf --enablerepo=centos-rabbitmq-38 -y install rabbitmq-server
```

**What this does:**

- `--enablerepo=centos-rabbitmq-38` — activates the RabbitMQ repository registered in the previous step
- `-y install rabbitmq-server` — installs RabbitMQ server and its dependencies without prompting

> These are two logical actions (enable repo + install package) combined into one command.

---

### 7. Start and Enable RabbitMQ

Start the service and enable it to launch automatically on boot in a single command:

```bash
systemctl enable --now rabbitmq-server
```

The `--now` flag combines `start` and `enable` together. Alternatively, you can run them separately:

```bash
sudo systemctl start rabbitmq-server
sudo systemctl enable rabbitmq-server
```

Both approaches produce the same result.

---

### 8. Configure RabbitMQ

Create the RabbitMQ configuration file and write the required settings into it using `echo` with output redirection:

```bash
sudo sh -c 'echo "[{rabbit, [{loopback_users, []}]}]." > /etc/rabbitmq/rabbitmq.config'
```

**What this does:**

- Creates (or overwrites) `/etc/rabbitmq/rabbitmq.config`
- Writes a configuration directive that **disables the loopback-only restriction** for users
- Without this, RabbitMQ restricts the `guest` user to localhost connections only; this setting allows application users to connect remotely

---

### 9. Add an Application User

Add a RabbitMQ user named `test` with the password `test`:

```bash
sudo rabbitmqctl add_user test test
```

> This is analogous to creating a database user in MySQL. The application will use this account to authenticate with RabbitMQ.

---

### 10. Grant Administrator Permissions

Assign the `administrator` tag to the `test` user:

```bash
sudo rabbitmqctl set_user_tags test administrator
```

Then set full access permissions for this user across all virtual hosts:

```bash
sudo rabbitmqctl set_permissions -p / test ".*" ".*" ".*"
```

**Permission breakdown:**

| Parameter | Value | Meaning |
|-----------|-------|---------|
| `-p /` | default virtual host | applies to the `/` vhost |
| First `".*"` | configure | can configure any resource |
| Second `".*"` | write | can write to any resource |
| Third `".*"` | read | can read from any resource |

---

### 11. Restart RabbitMQ

Restart the service to apply the configuration file changes:

```bash
sudo systemctl restart rabbitmq-server
```

> **Rule:** Whenever a configuration file is changed, always restart the service.

---

### 12. Configure the Firewall

Open port 5672 so that other VMs in the stack can connect to RabbitMQ:

```bash
firewall-cmd --add-port=5672/tcp
firewall-cmd --runtime-to-permanent
```

Port 5672 is the standard AMQP port used by RabbitMQ for application connections.

---

## Troubleshooting: `firewall-cmd --runtime-to-permanent` Permission Denied

Even after fixing the SELinux context with `restorecon` (which corrects the label from `user_tmp_t` to `net_conf_t`), you may still see this error on `rmq01`:

```
Error: [Errno 13] Permission denied: '/etc/sysconfig/network-scripts/ifcfg-eth1'
```

Once SELinux is no longer the cause, the remaining issue is almost certainly **wrong file ownership or a locked immutable attribute** on the interface config file. Work through the steps below in order.

---

### Step 1: Check File Ownership

```bash
ls -l /etc/sysconfig/network-scripts/ifcfg-eth1
```

You will likely see the file is owned by `vagrant vagrant` instead of `root root`. Firewalld cannot write to a network config file it does not own.

---

### Step 2: Fix Ownership and Permissions

Correct the owner and restrict the permissions to root-only:

```bash
sudo chown root:root /etc/sysconfig/network-scripts/ifcfg-eth1
sudo chmod 600 /etc/sysconfig/network-scripts/ifcfg-eth1
```

Verify:

```bash
ls -l /etc/sysconfig/network-scripts/ifcfg-eth1
```

Expected output:

```
-rw-------. 1 root root ...
```

---

### Step 3: Check for an Immutable Attribute

Even with correct ownership, if the file has the immutable flag set, nothing can modify it — not even root:

```bash
lsattr /etc/sysconfig/network-scripts/ifcfg-eth1
```

If you see an `i` flag in the output like:

```
----i---------e-- /etc/sysconfig/network-scripts/ifcfg-eth1
```

Remove it:

```bash
sudo chattr -i /etc/sysconfig/network-scripts/ifcfg-eth1
```

---

### Step 4: Retry the Firewall Command

```bash
sudo firewall-cmd --runtime-to-permanent
```

Expected output:

```
success
```

---

### Recommended Alternative: Use `--permanent` Directly

Rather than adding a runtime rule and converting it, write the permanent rule in one step — this is the standard production approach and avoids the permission issue entirely:

```bash
sudo firewall-cmd --permanent --add-port=5672/tcp
sudo firewall-cmd --reload
```

Then verify the port is open:

```bash
sudo firewall-cmd --list-ports
```

Expected output:

```
5672/tcp
```

---

### 13. Start, Enable, and Verify the Service

Ensure the service is started, enabled on boot, and confirm it is running:

```bash
sudo systemctl start rabbitmq-server
sudo systemctl enable rabbitmq-server
sudo systemctl status rabbitmq-server
```

The output should show `active (running)`. Press `q` to exit the status view.

## Key Concepts

| Concept | Explanation |
|---------|-------------|
| **Message broker** | RabbitMQ sits between services and queues messages so producers and consumers don't need to communicate directly or simultaneously |
| **Virtual host (`/`)** | RabbitMQ's logical namespace for isolating resources; `/` is the default |
| **User tags** | Roles assigned to RabbitMQ users; `administrator` grants full management access |
| **loopback_users** | A RabbitMQ setting controlling which users are restricted to local connections; setting it to `[]` removes all restrictions |

---

## Key Ports

| Port | Protocol | Purpose |
|------|----------|---------|
| 5672 | TCP | Default RabbitMQ AMQP port (application connections) |
| 15672 | TCP | RabbitMQ management UI (if plugin enabled) |
