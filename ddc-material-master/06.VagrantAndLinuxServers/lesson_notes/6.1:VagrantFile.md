## 2. Environment Setup

### 2.1 Clean Up Existing VMs First

Before starting new work, always check and remove existing VMs.

```bash
vagrant global-status          # List all VMs across your system
vagrant global-status --prune  # Same, but removes stale/invalid entries
```

> ⚠️ `global-status` caches data and can show VMs that no longer exist. Always run with `--prune` to get accurate results.

To delete a VM, navigate into its folder and destroy it there — this is the most reliable method:

```bash
cd /path/to/vm/folder
vagrant status          # Confirms the VM state for this folder only
vagrant destroy --force # Deletes without a confirmation prompt
```

You can also destroy by ID, but this is less reliable since IDs can be stale:

```bash
vagrant destroy <VM_ID>
vagrant halt <VM_ID>
```

### 2.2 Set Up VS Code

VS Code is the recommended editor for managing Vagrantfiles. It integrates with the terminal and GitHub Copilot.

**Set your default terminal:**

| OS      | Shortcut           | Action |
|---------|--------------------|--------|
| Windows | `Ctrl + Shift + P` | Type `Terminal: Select Default Profile` → select **Git Bash** |
| macOS   | `Cmd + Shift + P`  | No change needed — Terminal is already the default |

**Install the Vagrantfile extension:**

1. Click the Extensions icon in the sidebar
2. Search for `Vagrantfile`
3. Install it — this adds syntax highlighting for Vagrantfiles

**Open your project:** `File → Open Folder` → select the folder containing your Vagrantfile.

## 3. Vagrantfile – Structure & Syntax

A Vagrantfile is written in **Ruby**, but you don't need to know Ruby. Just understand the structure and settings.

### 3.1 Key Syntax Rules

| Element | Meaning |
|---------|---------|
| `#` | Comment — anything after this on the same line is ignored; also used to disable settings |
| `config` | The main object — all VM settings are prefixed with `config.vm.` |
| `do \|config\| ... end` | The main configuration block |
| `do \|vb\| ... end` | A nested block for provider-specific settings |

> **For non-programmers:** Whatever word appears between the `| |` pipes is the prefix for all settings inside that block. `config` → settings use `config.vm.`. A nested `|vb|` → settings use `vb.`.

### 3.2 The Configure Block (Required Wrapper)

Every Vagrantfile must have this outer block. **All settings must go inside it.**

```ruby
Vagrant.configure("2") do |config|
  # All settings go here
end
```

- `"2"` is the Vagrant configuration version — always use `"2"`
- `do ... end` marks the start and end of the block

> ⚠️ Placing any `config.` line **outside** this block causes:
> `undefined local variable or method 'config'`

## 4. Vagrantfile – Core Settings

### 4.1 Box (VM Image)

Specifies the operating system to use. Downloaded from Vagrant Cloud if not already local.

```ruby
config.vm.box = "ubuntu/jammy64"
config.vm.box_check_update = false  # Optional: disables automatic update checks
```

Common boxes: `ubuntu/jammy64`, `ubuntu/focal64`, `centos/7`

> macOS M-series (ARM) users must use a box compatible with `vmware_desktop`.

### 4.2 Network Settings

Controls how the VM connects to your host machine and network. Multiple entries are allowed.

```ruby
# Public network — VM gets a dynamic IP from your router (like any device on the LAN)
config.vm.network "public_network"

# Private network — VM gets a fixed static IP, reachable only from your host machine
config.vm.network "private_network", ip: "192.168.33.10"
```

| Type | IP Assignment | Reachable From |
|------|---------------|----------------|
| `public_network` | Dynamic (DHCP from router) | Any device on your LAN |
| `private_network` | Static (you define it) | Host machine only |

Use the `192.168.56.x` range for private IPs — the last octet can be any number you choose.

> Network settings only apply at **boot time**. After editing, run `vagrant reload` (if the VM is running) or `vagrant up` (if it's off).

### 4.3 Provider Block (RAM & CPU)

Allocates hardware resources and configures the virtualization provider.

```ruby
# Windows — VirtualBox
config.vm.provider "virtualbox" do |vb|
  vb.memory = 1024  # RAM in MB (1024 = 1 GB)
  vb.cpus = 2       # Number of CPU cores
  vb.gui = false    # Set to true to show the VM window (useful for debugging)
end

# macOS M-series — VMware
config.vm.provider "vmware_desktop" do |v|
  v.memory = 1024
  v.cpus = 2
end
```

> ⚠️ `bridge_adapter1` is VirtualBox-specific. Remove it if using VMware to avoid errors.

### 4.4 Provisioning (Optional)

Runs shell commands automatically the first time `vagrant up` is called — useful for installing software.

```ruby
config.vm.provision "shell", inline: <<-SHELL
  apt-get update -y
  apt-get install -y apache2
SHELL
```

To re-run provisioning on an already-running VM:

```bash
vagrant provision
vagrant up --provision
```

### 4.5 Synced Folders (Optional)

Shares a folder between your host machine and the VM. Changes in either location are reflected in both.

```ruby
config.vm.synced_folder "./data", "/vagrant_data"
# "./data" = path on host | "/vagrant_data" = path inside VM
```

## 5. Complete Vagrantfile Example

```ruby
Vagrant.configure("2") do |config|

  # Box image
  config.vm.box = "ubuntu/jammy64"          # Windows/VirtualBox
  # config.vm.box = "your-arm-box"          # macOS M-series/VMware
  config.vm.box_check_update = false

  # Networking
  config.vm.network "public_network"
  config.vm.network "private_network", ip: "192.168.33.10"

  # Provider / hardware — choose one block based on your OS
  config.vm.provider "virtualbox" do |vb|   # Windows
    vb.memory = 1024
    vb.cpus = 2
  end

  # Provisioning
  config.vm.provision "shell", inline: <<-SHELL
    apt-get update -y
  SHELL

  # Synced folder
  config.vm.synced_folder "./data", "/vagrant_data"

end
```

> **macOS M-series users:** Replace `"virtualbox"` with `"vmware_desktop"` in the provider block and use a compatible ARM box.

## 6. Common Errors & Fixes

### `undefined local variable or method 'config'`

A `config.` setting is outside the `Vagrant.configure` block.

```ruby
# ❌ WRONG — config.vm.network is outside the block
config.vm.network "private_network", ip: "192.168.33.10"

Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"
end
```

```ruby
# ✅ CORRECT — all settings inside the block
Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"
  config.vm.network "private_network", ip: "192.168.33.10"
end
```

Always validate before running `vagrant up`:

```bash
vagrant validate
# Expected: Vagrantfile validated successfully.
```

### `vagrant global -status` (space instead of hyphen)

```bash
vagrant global -status   # ❌ Vagrant reads "-status" as an unknown flag
vagrant global-status    # ✅ One hyphenated command
```

### `VagrantFile up` (filename used as a command)

```bash
VagrantFile up   # ❌ VagrantFile is just a filename
vagrant up       # ✅ vagrant (lowercase) is the CLI tool
```

## 7. Verifying Your VM After Boot

After `vagrant up`, SSH in and confirm resources were applied correctly:

```bash
vagrant ssh
sudo -i

ip address show   # Confirm static IP and bridged adapter IP
free -m           # Confirm RAM (~1024 MB)
cat /proc/cpuinfo # Confirm CPU core count
```

## 8. Using GitHub Copilot with Vagrantfiles

GitHub Copilot is an AI code tool built into VS Code. It can auto-complete, explain, and generate Vagrantfiles.

**Auto-complete:** Start typing a setting and press Enter — Copilot suggests the next line. Press **Tab** to accept.

**Explain a setting:**
1. Select the line(s) you don't understand
2. Press `Ctrl + I` (Windows) or `Cmd + I` (macOS)
3. Type `/explain` and hit Enter

**Generate a full Vagrantfile:**
1. Create a new empty file named `Vagrantfile` (capital V)
2. Open Copilot chat with `Ctrl + I` / `Cmd + I`
3. Write a plain-English description, e.g.:

```
Write a Vagrantfile with box ubuntu/jammy64, virtualbox provider,
1GB RAM, 2 CPUs, bridged adapter, and static private IP 192.168.33.10.
```

4. Review the output, request changes if needed, then accept

> Learning to write clear, specific prompts for AI tools is called **prompt engineering**. Be precise — include box name, provider, memory, CPU count, and IP details.

## 9. Quick Reference

### Common Commands

| Command | Description |
|---------|-------------|
| `vagrant global-status` | List all VMs on the system |
| `vagrant global-status --prune` | List all VMs and clear stale entries |
| `vagrant status` | Status of VM in the current folder only |
| `vagrant up` | Create and start the VM |
| `vagrant halt` | Shut down the VM gracefully |
| `vagrant reload` | Restart VM and apply Vagrantfile changes |
| `vagrant destroy --force` | Delete the VM without confirmation |
| `vagrant ssh` | Connect to the running VM |
| `vagrant validate` | Check Vagrantfile for syntax errors |
| `vagrant provision` | Re-run provisioning on a running VM |

### Key Rules to Remember

1. All settings must be **inside** the `Vagrant.configure("2") do |config| ... end` block.
2. `global-status` can show stale data — always use `--prune` for accuracy.
3. `public_network` = dynamic IP from router; `private_network` with `ip:` = static IP.
4. RAM and CPU settings go in the **provider block** (`virtualbox` or `vmware_desktop`).
5. Network and resource changes only take effect at **boot time** — use `vagrant reload` or `vagrant up`.
6. Always run `vagrant validate` before `vagrant up` to catch errors early.
