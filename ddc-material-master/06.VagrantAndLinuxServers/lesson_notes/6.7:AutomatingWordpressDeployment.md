# Infrastructure as Code – Automating WordPress Deployment with Vagrant Provisioning

---

## 1. Overview

In previous lectures the WordPress LAMP stack was set up manually, step by step. This lecture automates that entire process by moving every command into a Vagrant provisioning block — so a single `vagrant up` creates a fully running WordPress site with no manual intervention.

The same principle from the finance website automation applies here:

> **Automate only what you already understand manually.** The provisioning commands are identical to the manual steps — just scripted.

## 3. Key Scripting Techniques for WordPress Automation

WordPress automation introduces two challenges not present in the finance website setup: **creating a file with content** and **running MySQL queries** — both from within a shell script.

### 3.1 Creating a File With Content — The `cat` Heredoc

To create a file and write content into it automatically, use `cat` with output redirection and a heredoc:

```bash
cat > /path/to/file <<EOF
content goes here
more content
EOF
```

| Part | Meaning |
|------|---------|
| `cat` | Reads input and writes it out |
| `>` | Output redirection — writes the output to the specified file |
| `<<EOF` | Heredoc — everything between the two `EOF` markers is treated as input |
| `EOF` | The closing marker — must be on its own line with **no leading spaces** |

> ⚠️ **Critical:** The closing `EOF` must have no spaces before or after it. Any extra whitespace causes a "heredoc error" and provisioning will stop at that point.

This technique is used to create the Apache configuration file (`wordpress.conf`) automatically.

### 3.2 Running MySQL Queries From a Shell Script

Inside the provisioning shell block you cannot open an interactive MySQL prompt. Instead, use the `-e` flag to pass a query directly:

```bash
mysql -u root -e "CREATE DATABASE wordpress;"
mysql -u root -e "CREATE USER wordpress@localhost IDENTIFIED BY 'admin123';"
mysql -u root -e "GRANT SELECT,INSERT,UPDATE,DELETE,CREATE,DROP,ALTER ON wordpress.* TO wordpress@localhost;"
mysql -u root -e "FLUSH PRIVILEGES;"
```

- `-e` stands for **execute** — runs the query string and exits immediately
- Each query is a separate `mysql -u root -e` command
- Queries containing single quotes (e.g. passwords) should use **double quotes** as the outer wrapper to avoid conflicts:

```bash
mysql -u root -e "CREATE USER wordpress@localhost IDENTIFIED BY 'admin123';"
#                 ^--- double quotes wrap the command
#                                                              ^--- single quotes for the password value
```

## 4. The Complete Vagrantfile

```ruby
Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/focal64"
  config.vm.network "private_network", ip: "192.168.56.11"
  config.vm.network "public_network"

  config.vm.provider "virtualbox" do |vb|
    vb.memory = 1600
  end

  config.vm.provision "shell", inline: <<-SHELL

    # Step 1 — Install dependencies
    apt update
    apt install -y apache2 ghostscript libapache2-mod-php mysql-server php \
      php-bcmath php-curl php-imagick php-intl php-json php-mbstring \
      php-mysql php-xml php-zip

    # Step 2 — Download WordPress
    mkdir -p /srv/www
    chown www-data: /srv/www
    curl https://wordpress.org/latest.tar.gz | sudo -u www-data tar zx -C /srv/www

    # Step 3 — Create Apache config file using heredoc
    cat > /etc/apache2/sites-available/wordpress.conf <<EOF
<VirtualHost *:80>
    DocumentRoot /srv/www/wordpress
    <Directory /srv/www/wordpress>
        Options FollowSymLinks
        AllowOverride Limit Options FileInfo
        DirectoryIndex index.php
        Require all granted
    </Directory>
    <Directory /srv/www/wordpress/wp-content>
        Options FollowSymLinks
        Require all granted
    </Directory>
</VirtualHost>
EOF

    # Step 4 — Enable WordPress site, disable default
    a2ensite wordpress
    a2enmod rewrite
    a2dissite 000-default
    service apache2 reload

    # Step 5 — Configure MySQL database
    mysql -u root -e "CREATE DATABASE wordpress;"
    mysql -u root -e "CREATE USER wordpress@localhost IDENTIFIED BY 'admin123';"
    mysql -u root -e "GRANT SELECT,INSERT,UPDATE,DELETE,CREATE,DROP,ALTER ON wordpress.* TO wordpress@localhost;"
    mysql -u root -e "FLUSH PRIVILEGES;"
    service mysql start

    # Step 6 — Configure WordPress to connect to the database
    sudo -u www-data cp /srv/www/wordpress/wp-config-sample.php /srv/www/wordpress/wp-config.php
    sudo -u www-data sed -i 's/database_name_here/wordpress/'   /srv/www/wordpress/wp-config.php
    sudo -u www-data sed -i 's/username_here/wordpress/'        /srv/www/wordpress/wp-config.php
    sudo -u www-data sed -i 's/password_here/admin123/'         /srv/www/wordpress/wp-config.php

    # Step 7 — Restart services to apply all changes
    service mysql restart
    service apache2 restart

  SHELL
end
```

## 5. Important Details and Common Mistakes

### The Heredoc Must Have No Leading Spaces on the Closing Marker

```bash
# ❌ WRONG — space before EOF causes a heredoc error
    EOF

# ✅ CORRECT — EOF starts at column 1, no indentation
EOF
```

If provisioning stops with a heredoc-related error, this is almost always the cause. Check the closing `EOF` in your Vagrantfile carefully.

### All Commands Must Be Non-Interactive

Every command in the provisioning block must run without waiting for user input:

| Command | Why non-interactive |
|---------|-------------------|
| `apt install -y` | `-y` auto-confirms installation prompts |
| `unzip -o` | `-o` overwrites without prompting |
| `mkdir -p` | `-p` won't error if directory exists |
| `mysql -u root -e "..."` | `-e` executes and exits — no interactive prompt |

### Compare Against the Documentation

Before running `vagrant up`, compare every command in the provisioning block line by line with the [Ubuntu WordPress documentation](https://ubuntu.com/tutorials/install-and-configure-wordpress). Look for:

- Missing commands
- Typographical errors
- Missing `-y`, `-e`, or other required flags
- Incorrect file paths

### Note on Salt Keys

The automated setup does not replace the WordPress salt keys — this step requires fetching unique values from an external URL, which is difficult to script reliably in a learning environment. The site will function without it, but for any production deployment the salt keys should be replaced in `wp-config.php` after provisioning.

## 7. Troubleshooting

### Provisioning Stops Mid-Way

Most likely a heredoc error — the closing `EOF` has a leading space. Open the Vagrantfile, find the `EOF` marker, and ensure it sits at the very start of the line with no indentation.

### WordPress Site Does Not Load

SSH into the VM and check each component manually:

```bash
vagrant ssh
sudo -i

systemctl status apache2          # Should be active (running)
systemctl status mysql            # Should be active (running)
ls /srv/www/wordpress/            # Should contain WordPress files
ls /etc/apache2/sites-enabled/   # Should show wordpress.conf, not 000-default
cat /srv/www/wordpress/wp-config.php | grep DB_
# DB_NAME, DB_USER, DB_PASSWORD should match MySQL credentials
```

### Re-Run Provisioning After Fixing

```bash
vagrant reload --provision   # Reboot VM and re-run provisioning
# or
vagrant provision            # Re-run without rebooting
```

## 8. Reusability and What Comes Next

```bash
vagrant destroy   # Delete the VM
vagrant up        # Recreate it — full WordPress site in minutes
```

The Vagrantfile is the asset. As long as it exists, the entire environment — OS, LAMP stack, WordPress configuration — can be recreated anywhere with one command.

The same provisioning shell commands written here are directly transferable to:

- **AWS EC2** — as user data scripts that run on instance launch
- **Ansible** — as tasks in a playbook
- **Docker** — as steps in a Dockerfile

## 9. Summary

| Step | What Gets Automated |
|------|-------------------|
| Install dependencies | `apt install -y` for all LAMP packages |
| Download WordPress | `curl` + `tar` into `/srv/www` |
| Create Apache config | `cat > file <<EOF ... EOF` heredoc |
| Enable site | `a2ensite`, `a2enmod`, `a2dissite`, `service apache2 reload` |
| Configure MySQL | `mysql -u root -e "..."` for each query |
| Configure WordPress | `cp` sample config, three `sed` replacements |
| Restart services | `service mysql restart`, `service apache2 restart` |

### Key Rules

1. The closing `EOF` in a heredoc must have **no leading or trailing spaces** — any whitespace causes a provisioning failure.
2. Use `mysql -u root -e "..."` to run SQL queries non-interactively from a shell script.
3. Use double quotes to wrap MySQL `-e` commands that contain single-quoted values (e.g. passwords).
4. All commands must be non-interactive — include `-y`, `-o`, `-p`, and `-e` flags wherever needed.
5. Delete the `.vagrant` folder when copying a project folder — it contains old VM state that causes conflicts.
6. The Vagrantfile is the deliverable — the VM is disposable.
