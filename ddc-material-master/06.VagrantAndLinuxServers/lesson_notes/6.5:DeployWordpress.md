# Setting Up WordPress on Ubuntu

---

## Prerequisites

- Ubuntu VM running (e.g. `ubuntu/focal64`)
- Logged in as root (`sudo -i`)
- Reference: search **"WordPress on Ubuntu"** and follow the official Ubuntu documentation

WordPress requires a **LAMP stack** to run:

| Component | Package | Role |
|-----------|---------|------|
| **L**inux | Ubuntu 20.04 | Operating system |
| **A**pache | `apache2` | Web server |
| **M**ySQL | `mysql-server` | Database |
| **P**HP | `php` + libraries | Server-side scripting |

---

## Step 1 — Install Dependencies

```bash
sudo apt update

sudo apt install -y \
  apache2 \
  ghostscript \
  libapache2-mod-php \
  mysql-server \
  php \
  php-bcmath \
  php-curl \
  php-imagick \
  php-intl \
  php-json \
  php-mbstring \
  php-mysql \
  php-xml \
  php-zip -y
```

> Long commands can be split across lines using a space and backslash (`\`) at the end of each line — Linux treats it as one continuous command.

---

## Step 2 — Download WordPress

Create the web root directory, assign it to the Apache user, then download and extract WordPress:

```bash
sudo mkdir -p /srv/www
sudo chown www-data: /srv/www
curl https://wordpress.org/latest.tar.gz | sudo -u www-data tar zx -C /srv/www
```

| Command | Purpose |
|---------|---------|
| `sudo mkdir -p /srv/www` | Creates the directory (including any missing parents) |
| `sudo chown www-data: /srv/www` | Gives ownership to `www-data` — the user Apache runs as |
| `curl ... \| sudo -u www-data tar zx` | Downloads and extracts WordPress directly into `/srv/www` |

Verify:

```bash
ls -ld /srv/www                  # Should show www-data as owner
ls -l /srv/www/wordpress/        # Should contain index.php and WordPress files
```

> `/srv/www/wordpress` is the **document root** — it plays the same role as `/var/www/html` in a standard Apache setup.

---

## Step 3 — Configure Apache

### Create the WordPress Site Config File

```bash
sudo vim /etc/apache2/sites-available/wordpress.conf
```

Enter insert mode (`i`) and paste:

```apache
<VirtualHost *:80>
    DocumentRoot /srv/www/wordpress
    <Directory /srv/www/wordpress>
        Options FollowSymLinks
        AllowOverride Limit Options FileInfo
        DirectoryIndex index.php
        Require all granted
    </Directory>
    <Directory /srv/www/wordpress/wp-content>
        Options FollowSymLinks
        Require all granted
    </Directory>
</VirtualHost>
```

Save and quit (`:wq`).

`DocumentRoot /srv/www/wordpress` tells Apache to serve WordPress instead of the default site.

**Alternative — use ServerName instead of disabling the default site:**

If you want to keep the default Apache page alongside WordPress, add a `ServerName` directive to the VirtualHost block instead of running `a2dissite`. The hostname must be resolvable via DNS or an entry in your `/etc/hosts` file:

```apache
<VirtualHost *:80>
    ServerName hostname.example.com
    DocumentRoot /srv/www/wordpress
    ...
</VirtualHost>
```

### Enable WordPress, Disable Default Site

```bash
sudo a2ensite wordpress        # Creates a symlink to enable the WordPress config
sudo a2enmod rewrite           # Enables URL rewriting — required by WordPress
sudo a2dissite 000-default     # Removes the symlink for the default Apache page
sudo service apache2 reload    # Applies all changes without a full restart
```

Verify:

```bash
ls -l /etc/apache2/sites-enabled/
# Should show: wordpress.conf -> ../sites-available/wordpress.conf
# The default site symlink should no longer appear
```

## Step 4 — Configure MySQL Database

Log into MySQL:

```bash
sudo mysql -u root
```

You are now at the `mysql>` prompt. All commands here are **SQL queries** and must end with a semicolon (`;`).

Run the following queries one at a time:

```sql
CREATE DATABASE wordpress;

CREATE USER wordpress@localhost IDENTIFIED BY '<your-password>';

GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, DROP, ALTER
  ON wordpress.*
  TO wordpress@localhost;

FLUSH PRIVILEGES;

quit
```

| Query | Purpose |
|-------|---------|
| `CREATE DATABASE wordpress` | Creates the database for WordPress to use |
| `CREATE USER ... IDENTIFIED BY` | Creates a dedicated database user with a password |
| `GRANT ... ON wordpress.*` | Gives that user full permissions on the WordPress database |
| `FLUSH PRIVILEGES` | Refreshes the privilege tables so changes take effect |
| `quit` | Exits the MySQL prompt |

> Replace `<your-password>` with a strong password and note it down — it must match exactly in the next step. Use a longer alphanumeric password in any real environment.

After exiting, ensure MySQL is running:

```bash
sudo service mysql start
```

Verify the database was created:

```sql
SHOW DATABASES;
-- Should include: wordpress
```

## Step 5 — Connect WordPress to the Database

### Copy the Sample Config

```bash
sudo -u www-data cp /srv/www/wordpress/wp-config-sample.php \
                    /srv/www/wordpress/wp-config.php
```

This creates the active config file WordPress reads at runtime.

### Update Database Credentials

Use `sed` to find and replace the placeholder values. Do not change `database_name_here`, `username_here`, or `password_here` in the commands themselves — only replace `<your-password>` with the password you set in Step 4:

```bash
sudo -u www-data sed -i 's/database_name_here/wordpress/' /srv/www/wordpress/wp-config.php
sudo -u www-data sed -i 's/username_here/wordpress/'      /srv/www/wordpress/wp-config.php
sudo -u www-data sed -i 's/password_here/<your-password>/' /srv/www/wordpress/wp-config.php
```

`sed -i 's/find/replace/' file` — searches for a string and replaces it directly in the file.

Verify the changes were applied:

```bash
cat /srv/www/wordpress/wp-config.php | grep DB_
# DB_NAME should be: wordpress
# DB_USER should be: wordpress
# DB_PASSWORD should be: your chosen password
```

If anything is wrong, open the file directly and correct it:

```bash
sudo -u www-data vim /srv/www/wordpress/wp-config.php
```

### Replace Security (Salt) Keys

Salt keys are unique security tokens that protect user session cookies and prevent "known secrets" attacks. This step is important.

1. Go to: [https://api.wordpress.org/secret-key/1.1/salt/](https://api.wordpress.org/secret-key/1.1/salt/)  
   *(This URL generates completely random keys every time it is opened)*
2. Copy all the generated text

3. Open `wp-config.php` in nano as the `www-data` user:

```bash
sudo -u www-data nano /srv/www/wordpress/wp-config.php
```

4. Find the existing placeholder block that looks like this:

```php
define( 'AUTH_KEY',         'put your unique phrase here' );
define( 'SECURE_AUTH_KEY',  'put your unique phrase here' );
define( 'LOGGED_IN_KEY',    'put your unique phrase here' );
define( 'NONCE_KEY',        'put your unique phrase here' );
define( 'AUTH_SALT',        'put your unique phrase here' );
define( 'SECURE_AUTH_SALT', 'put your unique phrase here' );
define( 'LOGGED_IN_SALT',   'put your unique phrase here' );
define( 'NONCE_SALT',       'put your unique phrase here' );
```

5. Delete each of those lines using `Ctrl + K` (deletes one line per press)
6. Paste the copied salt keys in their place
7. Save and close: press `Ctrl + X`, then `Y`, then `Enter`

> If using **vim** instead of nano: press `dd` to delete lines one at a time, press `i` to enter insert mode before pasting, then `Escape` and `:wq` to save.

## Step 6 — Configure WordPress (Browser Setup Wizard)

Open a browser and navigate to your VM's IP address:

```bash
ip addr show
# Use a 192.x.x.x address — not the 10.0.x.x NAT address
```

```
http://192.168.56.26
```

You will see the WordPress installation wizard asking for:

| Field | Notes |
|-------|-------|
| **Site Title** | The name of your WordPress site (e.g. `Ubuntu Tutorial`) |
| **Username** | Your WordPress admin username — alphanumeric characters, spaces, underscores, hyphens, periods, and `@` only |
| **Password** | WordPress generates a strong password — you can use it or set your own. Store it securely |
| **Your Email** | Used for admin notifications — double-check before continuing |
| **Search Engine Visibility** | Optional — tick to discourage search engines from indexing the site |

> ⚠️ The WordPress username and password are **separate** from your MySQL credentials and your server login. Use different credentials for each.

Click **Install WordPress**. Once complete, log in at:

```
http://<VM-IP>/wp-login.php
```

You should see the **WordPress Dashboard** — the admin interface for managing your site.

---

## Step 7 — Write Your First Post

### Delete the Default "Hello World!" Post

From the Dashboard, hover over the **Posts** icon in the left sidebar and click **All Posts**. You will see the default "Hello world!" post that WordPress creates automatically.

Mouse over the post title and click **Trash** to delete it.

### Create a New Post

Click **Add New** at the top of the Posts page. You will see the WordPress post editor — a WYSIWYG (What You See Is What You Get) editor with text formatting options similar to a word processor.

- Type a title in the title field
- Write your content in the main editor area
- Use the toolbar to format text (bold, italic, lists, links, etc.)
- Switch to **Text** mode (top right of editor) if you prefer to write in raw HTML

When ready, click **Publish**. Your post is now live and can be viewed from the front end of your site.

## Step 8 — What's Next

WordPress is a highly extensible platform. Once your basic setup is working you can:

- Install **themes** to change the appearance of your site
- Install **plugins** to add functionality — thousands are available free at [wordpress.org/plugins](https://wordpress.org/plugins/)
- Common plugins include:
    - **JetPack** — performance and security features
    - **WooCommerce** — turns WordPress into an eCommerce store
    - **bbPress** — adds forum functionality
    - **BuddyPress** — adds social network / microblogging features
    - **TinyMCE Advanced** — extends the post editor

- [Ubuntu WordPress Documentation](https://ubuntu.com/tutorials/install-and-configure-wordpress)

## Troubleshooting

### Browser shows default Apache page or a blank page

```bash
ls -l /etc/apache2/sites-enabled/   # wordpress.conf should be here, 000-default should not
sudo service apache2 restart
```

### "Error establishing a database connection"

```bash
# Check credentials in wp-config.php
cat /srv/www/wordpress/wp-config.php | grep DB_

# Log into MySQL and verify the database exists
sudo mysql -u root
SHOW DATABASES;   -- should include: wordpress
quit

# Ensure MySQL is running
sudo service mysql start
```

Make sure `DB_NAME`, `DB_USER`, and `DB_PASSWORD` in `wp-config.php` exactly match what you set in MySQL.

### Something was skipped or went wrong

```bash
history   # Shows every command run — scan for any step you may have missed
```

Re-run the database steps if needed, restart Apache, and try again from the browser.

## Key Points

1. WordPress needs Apache, MySQL, and PHP all configured correctly — all three must be working before the site will load.
2. `a2ensite`, `a2enmod`, and `a2dissite` are Ubuntu/Debian-specific Apache commands — they don't exist on CentOS.
3. The database name, username, and password must match **exactly** between MySQL and `wp-config.php` — this is the most common source of errors.
4. Always run `service apache2 reload` or `restart` after any configuration change.
5. Paste commands into a text editor before the terminal — especially SQL queries, where typos are hard to spot.
6. `sudo -u www-data` runs a command as the Apache web user — important for file ownership when editing WordPress config files.
