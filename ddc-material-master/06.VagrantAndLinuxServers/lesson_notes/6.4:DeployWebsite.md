# Deploying a Website on CentOS

---

## 1. Overview

This covers how to manually install and manage a web server on a CentOS Linux VM, then deploy a real HTML website template to it. The same process will later be automated using Vagrant provisioning.

The general workflow for any server deployment has four steps:

1. **Install dependencies** — packages the service needs to run
2. **Start and manage the service** — start, enable, and verify it
3. **Apply configuration changes** — if any are required
4. **Deploy the data** — put your website content in the right place

---

## 2. Set Up the CentOS VM

Create a dedicated project folder, initialise a Vagrantfile, and configure a static IP:

```bash
# Create and enter the project folder
mkdir finance
cd finance

# Check available boxes
vagrant box list

# Initialise with your CentOS box
vagrant init eurolinux-vagrant/centos-stream-9
```

Edit the Vagrantfile to add a static private IP and set RAM:

```ruby
Vagrant.configure("2") do |config|
  config.vm.box = "eurolinux-vagrant/centos-stream-9"
  config.vm.network "private_network", ip: "192.168.56.22"
  config.vm.network "public_network"

  config.vm.provider "virtualbox" do |vb|
    vb.memory = 1024
  end
end
```

> Make sure the static IP doesn't clash with any other running VMs.

Bring up the VM and log in:

```bash
vagrant up
vagrant ssh
sudo -i
```

Optionally set a hostname for clarity:

```bash
vi /etc/hostname       # Replace content with: finance
hostname finance       # Apply immediately without rebooting
# Log out and back in to see the new prompt
```

## 3. Install Dependencies

Before starting the service, install everything it needs:

```bash
yum install -y httpd wget vim unzip zip
```

| Package | Purpose |
|---------|---------|
| `httpd` | The Apache web server (CentOS/RHEL package name) |
| `wget` | Downloads files from the internet via the command line |
| `vim` | Text editor for modifying files |
| `unzip` | Extracts `.zip` archives |
| `zip` | Creates `.zip` archives (optional but useful) |

> On Ubuntu/Debian, the web server package is called `apache2`, not `httpd`.

---

## 4. Start and Enable the Service

```bash
systemctl start httpd    # Start the service now
systemctl enable httpd   # Ensure it starts automatically on reboot
systemctl status httpd   # Verify it's running
```

> Always **enable** a service if you want it to survive a reboot. Starting without enabling means the service won't come back up after restart.

Check the VM's IP address:

```bash
ip addr show
```

Use any `192.x.x.x` address (not the `10.0.x.x` NAT address) to access the VM from your browser. Open `http://192.168.56.22` — you should see the default Apache test page, confirming the service is running.

---

## 5. How Apache Serves Content

Apache serves files from a specific directory on the filesystem:

```
/var/www/html/
```

Whatever you place in this folder is served to the browser. The entry point is always a file named **`index.html`**.

### Quick Test

```bash
vi /var/www/html/index.html
# Add any text, e.g.: This is my first website setup.
```

Restart the service to pick up the change:

```bash
systemctl restart httpd
```

Refresh the browser — your text now appears instead of the default page.

> **Rule of thumb:** Whenever you make changes to a service's files or configuration, always restart (or at minimum reload) the service for changes to take effect.

## 6. Deploy an HTML Website Template

Rather than building a site from scratch, download a ready-made HTML template from [tooplate.com](https://www.tooplate.com).

### Step 1 — Get the Direct Download Link

Tooplate's Download button doesn't always give a direct `.zip` URL. To find it:

1. Open the template page in **Brave browser** (avoids marketing popups)
2. Press **F12** to open DevTools
3. Go to the **Network** tab
4. Click the **Download** button on the page
5. Find the `.zip` entry in the network log, click it
6. Go to **Headers** and copy the full download URL

### Step 2 — Download the Template Inside the VM

Always download to `/tmp` — it's a temporary location that won't clutter other directories:

```bash
cd /tmp
wget https://www.tooplate.com/zip-templates/2135_mini_finance.zip
```

### Step 3 — Extract the Archive

```bash
unzip 2135_mini_finance.zip
ls               # Confirm the extracted folder exists
cd 2135_mini_finance
ls               # You should see index.html and associated assets
```

### Step 4 — Copy Content to the Web Root

```bash
cp -r * /var/www/html/
# -r copies directories recursively
# * copies everything in the current folder
```

If prompted to overwrite the test `index.html` you created earlier, confirm with `y`.

Verify the files are in place:

```bash
ls /var/www/html/
```

### Step 5 — Restart Apache

```bash
systemctl restart httpd
```

Refresh the browser at `http://192.168.56.22` — the full website template now loads.

## 7. Firewall Considerations

On CentOS VMs running on **Windows with VirtualBox**, the firewall (`firewalld`) is usually inactive by default.

On **macOS with VMware** (or Fedora-based systems), it may be active and will block browser access to the VM:

```bash
systemctl status firewalld      # Check if it's running

# If active, stop and disable it:
systemctl stop firewalld
systemctl disable firewalld
```

> Disabling the firewall is acceptable in a local learning environment. In production, you would configure firewall rules properly rather than disabling it entirely.

---

## 8. Validation Checklist

Before testing in the browser, confirm each of these:

```bash
systemctl status httpd          # Service should show: active (running)
ls /var/www/html/               # Should contain index.html and template assets
systemctl status firewalld      # Should show: inactive (or stopped if you disabled it)
ip addr show                    # Note the 192.x.x.x IP to use in the browser
```

## 9. Summary of Commands

```bash
# Install packages
yum install -y httpd wget vim unzip zip

# Manage the service
systemctl start httpd
systemctl enable httpd
systemctl restart httpd
systemctl status httpd

# Download and deploy a template
cd /tmp
wget <download-url>
unzip <filename>.zip
cd <extracted-folder>
cp -r * /var/www/html/

# Firewall (if blocking access)
systemctl stop firewalld
systemctl disable firewalld

# Check IP
ip addr show
```

---

## 10. Key Takeaways

1. The four-step server deployment pattern — **install → start/manage → configure → deploy** — applies to almost every service you'll work with.
2. Apache on CentOS is `httpd`; on Ubuntu it's `apache2` — the package and service names differ.
3. Always **enable** a service so it survives reboots — starting alone is not enough.
4. Apache serves content from `/var/www/html/` — the entry point is always `index.html`.
5. **Restart the service** after any file or configuration change.
6. Download temporary files to `/tmp` to keep the filesystem tidy.
7. This entire manual process will be automated with Vagrant provisioning — the manual steps map directly to provisioning shell commands.
