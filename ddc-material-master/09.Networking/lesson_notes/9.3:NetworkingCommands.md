## Overview

Networking commands are essential tools for diagnosing connectivity issues, scanning open ports, resolving DNS names, and tracing the path packets take across a network. This session uses five virtual machines defined in the Vagrantfile below to demonstrate these commands in a real environment:

| VM | Hostname | IP Address | OS | Service | Port | Memory |
|----|---------|-----------|-----|---------|------|--------|
| `web01` | web01 | `192.168.56.11` | Ubuntu Jammy 64 | Nginx (web server) | 80 | 800 MB |
| `app01` | app01 | `192.168.56.12` | CentOS Stream 9 | Tomcat (app server) | 8080 | 800 MB |
| `rmq01` | rmq01 | `192.168.56.13` | CentOS Stream 9 | RabbitMQ (message queue) | 5672 | 600 MB |
| `mc01` | mc01 | `192.168.56.14` | CentOS Stream 9 | Memcache (caching) | 11211 | 600 MB |
| `db01` | db01 | `192.168.56.15` | CentOS Stream 9 | MariaDB (database) | 3306 | 600 MB |

All VMs sit on the same private network (`192.168.56.0/24`) and can communicate with each other directly by IP or hostname (handled automatically by the `hostmanager` plugin).

## 1. `ifconfig` / `ip addr show` — View Network Interfaces

**Purpose:** Display all active network interfaces, their names, and IP addresses.

```bash
ifconfig
```

**Example output:**
```
eth0: inet 10.0.2.15       ← NAT network (internet access via VirtualBox NAT)
eth1: inet 192.168.56.11   ← Static IP on private network (web01)
lo:   inet 127.0.0.1       ← Loopback address (the machine refers to itself)
```

If `ifconfig` is not available on your system, use the modern equivalent:

```bash
ip addr show
```

**Key addresses to know:**

| Address | Meaning |
|---------|---------|
| `127.0.0.1` | Loopback — the machine referring to itself |
| `192.168.x.x` | Private network IP assigned to this machine |
| `10.0.2.x` | NAT network (used by VirtualBox for internet access) |

> A machine connected to two networks will show two active interfaces, as in the example above — `eth0` for internet and `eth1` for the private VM network.

## 2. `ping` — Test Network Connectivity

**Purpose:** Send ICMP packets to a target IP address to check whether there is a network connection between two machines.

```bash
# Ping db01 by IP address
ping 192.168.56.15

# Ping app01 by IP address
ping 192.168.56.12

# Ping by hostname (works automatically via the hostmanager plugin)
ping db01
ping app01
```

**Example output:**
```
12 packets transmitted, 12 received, 0% packet loss
```

**Behaviour difference between OS:**

| OS | Behaviour |
|----|----------|
| Windows | Sends 4 packets and stops |
| Linux | Sends unlimited packets — press `Ctrl+C` to stop |

**What ping tells you:**
- ✅ Replies received → there is network connectivity
- ❌ No replies → the target is unreachable or blocking ICMP
- ⚠️ Packet loss → unstable connection between the two machines

### Resolving Hostnames with `/etc/hosts`

Because the Vagrantfile uses `config.hostmanager.enabled = true`, hostnames are automatically registered on every VM. You can also add entries manually:

```bash
# Edit the hosts file
sudo nano /etc/hosts

# Add entries for each VM
192.168.56.11   web01
192.168.56.12   app01
192.168.56.13   rmq01
192.168.56.14   mc01
192.168.56.15   db01
```

Now you can use hostnames directly:
```bash
ping db01      # Resolves to 192.168.56.15
ping app01     # Resolves to 192.168.56.12
```

## 3. `traceroute` / `tracert` — Trace the Network Path

**Purpose:** Show every hop (router) a packet passes through on its way to the destination, along with the latency at each hop.

```bash
# Linux
traceroute www.google.com

# Windows (Command Prompt or PowerShell)
tracert www.google.com
```

**Example output:**
```
1   192.168.1.1     1ms    1ms    1ms    ← your local router
2   10.20.30.1      5ms    4ms    5ms    ← ISP router
3   172.16.x.x     12ms   12ms   11ms
...
8   216.58.x.x    256ms    1ms    1ms    ← Google server
```

**How to read the output:**
- Each row is one **hop** (a router along the path)
- Three columns of latency show three separate test packets
- High latency at a specific hop → the bottleneck is at that router, not your local network or the destination server
- `* * *` at a hop → that router is not responding to probe packets (firewall or configuration)

> **Note:** `traceroute` does not work reliably inside VirtualBox VMs due to how NAT networking is set up. Run it from your **host machine** instead.

## 4. `netstat` — View Open Ports and Connections

**Purpose:** Display all open TCP ports on the current machine, along with the process using each port.

```bash
netstat -antp
```

| Flag | Meaning |
|------|---------|
| `-a` | Show all sockets (listening and established) |
| `-n` | Show numeric addresses (no DNS resolution) |
| `-t` | Show TCP connections only |
| `-p` | Show the process ID (PID) and process name |

**Example output on `web01`:**
```
Proto  Local Address   State   PID/Program
tcp    0.0.0.0:22      LISTEN  1025/sshd
tcp    0.0.0.0:80      LISTEN  333/apache2
```

- Port `22` → SSH service (`sshd`)
- Port `80` → Web server (`apache2`)

**Finding what port a process is using:**

```bash
# Find all processes
ps -ef | grep apache2

# Then find what port that PID is using
netstat -antp | grep 333
```

## 5. `ss` — Socket Statistics (Modern `netstat`)

**Purpose:** A faster, more detailed alternative to `netstat` for viewing open ports and active connections.

```bash
ss -tunlp
```

| Flag | Meaning |
|------|---------|
| `-t` | Show TCP sockets |
| `-u` | Show UDP sockets |
| `-n` | Numeric addresses (no DNS) |
| `-l` | Show only listening sockets |
| `-p` | Show process name and PID |

**Example output:**
```
Netid  State   Local Address:Port  Process
tcp    LISTEN  0.0.0.0:22          sshd
tcp    LISTEN  0.0.0.0:80          apache2
```

> `ss` is the recommended replacement for `netstat` on modern Linux systems.

## 6. `nmap` — Network Port Scanner

**Purpose:** Scan open ports on a target machine. Primarily used to check whether a specific port is accessible from another machine.

```bash
# Install if not present
apt install nmap        # Ubuntu (web01)
dnf install nmap        # CentOS Stream 9 (db01, app01, mc01, rmq01)

# Scan localhost
nmap localhost

# Scan db01 (MariaDB server)
nmap 192.168.56.15      # or: nmap db01

# Scan app01 (Tomcat server)
nmap 192.168.56.12      # or: nmap app01
```

**Example output when scanning `db01`:**
```
PORT     STATE  SERVICE
22/tcp   open   ssh
111/tcp  open   rpcbind
3306/tcp open   mysql
```

**Example output when scanning `app01`:**
```
PORT     STATE  SERVICE
22/tcp   open   ssh
8080/tcp open   http-proxy
```

**When to use nmap:**
- Two machines cannot connect → scan whether the target port is actually open
- Verify which services are exposed on a server
- Troubleshoot firewall rules

> ⚠️ **Warning:** Use `nmap` responsibly. Running it against public websites or machines you do not own is illegal in many countries. Use it only for your own infrastructure and troubleshooting purposes.

## 7. `dig` / `nslookup` — DNS Lookup

**Purpose:** Query DNS records to verify that a hostname resolves to the correct IP address and that DNS resolution is working from your machine.

```bash
# dig — modern, detailed output
dig www.google.com

# nslookup — older but widely available
nslookup www.google.com
```

**Example `dig` output:**
```
;; ANSWER SECTION:
www.google.com.    300   IN   A   142.250.x.x

;; SERVER: 8.8.8.8#53   ← DNS server used to resolve the query
```

**What to look for:**
- **A record** → IPv4 address the hostname resolves to
- **AAAA record** → IPv6 address
- **SERVER** → which DNS server answered the query
- No answer → DNS resolution is broken from this machine

| Command | Best used for |
|---------|--------------|
| `dig` | Detailed DNS debugging, checking specific record types |
| `nslookup` | Quick lookups, available on both Linux and Windows |

## 8. `route` — View the Routing Table and Gateway

**Purpose:** Display the kernel routing table, including the default gateway used to reach external networks.

```bash
# Show routing table with numeric addresses
route -n

# Or just
route
```

**Example output on `web01`:**
```
Destination      Gateway          Genmask        Iface
0.0.0.0          192.168.56.1     0.0.0.0        eth1   ← default gateway
192.168.56.0     0.0.0.0          255.255.255.0  eth1
10.0.2.0         0.0.0.0          255.255.255.0  eth0   ← NAT interface
```

The `0.0.0.0` destination row shows the **default gateway** — the router that all traffic is sent to when no more specific route matches.

## 9. `arp` — View the ARP Table

**Purpose:** Display the kernel's ARP (Address Resolution Protocol) table, which maps IP addresses to MAC addresses of machines on the local network.

```bash
arp
```

**Example output on `web01`:**
```
Address          HWtype  HWaddress          Iface
192.168.56.15    ether   08:00:27:xx:xx:xx  eth1   ← db01
192.168.56.12    ether   08:00:27:yy:yy:yy  eth1   ← app01
192.168.56.14    ether   08:00:27:zz:zz:zz  eth1   ← mc01
192.168.56.13    ether   08:00:27:ww:ww:ww  eth1   ← rmq01
```

Useful for confirming that a machine on the local network has been seen and its MAC address is known to your machine.

## 10. `mtr` — Live Traceroute with Packet Loss

**Purpose:** A dynamic, continuously updating combination of `ping` and `traceroute`. It shows every hop to the destination and highlights where packet loss is occurring in real time.

```bash
mtr www.google.com
```

**Example output (live, updates every second):**
```
Host                Loss%   Avg
192.168.1.1          0.0%   1.0ms
10.20.30.1           0.0%   5.2ms
172.16.x.x          15.0%  12.4ms   ← packet loss here
...
216.58.x.x           0.0%  22.1ms
```

**Reading the output:**
- `Loss%` → percentage of packets lost at that hop
- A hop with high loss and everything beyond it also showing loss → problem is **at that hop**
- A hop with loss but hops beyond it are fine → that router is just deprioritising probe packets (not a real problem)

Press `Ctrl+C` to stop.

> **Note:** `mtr` works better from a host machine than inside a VM due to VirtualBox networking limitations.

## 11. `telnet` — Test if a Specific Port is Open

**Purpose:** Attempt a TCP connection to a specific port on a target machine to verify the port is reachable.

```bash
# From web01 — test if MariaDB port on db01 is reachable
telnet 192.168.56.15 3306

# Test Tomcat on app01
telnet 192.168.56.12 8080

# Test RabbitMQ on rmq01
telnet 192.168.56.13 5672

# Test Memcache on mc01
telnet 192.168.56.14 11211

# Test SSH port on any VM
telnet 192.168.56.15 22
```

**Possible outcomes:**

| Output | Meaning |
|--------|---------|
| `Connected to ...` | The port is open and accepting connections |
| `Connection refused` | The port is closed or the service is not running |
| `No route to host` | Network connectivity issue — the machine is unreachable |
| `Connection timed out` | A firewall is silently dropping packets |

Press `Ctrl + ]` then type `quit` to exit telnet.

> If `nmap` is unavailable, `telnet` is a quick and lightweight alternative to check whether a specific port is open on a remote machine.

## Troubleshooting Workflow

```
Cannot connect to a service?
         │
         ▼
ping <target IP>
  e.g. ping 192.168.56.15   (db01)
  e.g. ping 192.168.56.12   (app01)
  ├── No reply → network connectivity problem → check route, firewall
  └── Reply received
         │
         ▼
nmap <target IP>  OR  telnet <target IP> <port>
  e.g. nmap db01
  e.g. telnet 192.168.56.15 3306
  ├── Port closed → service not running or firewall blocking
  └── Port open
         │
         ▼
netstat -antp  (run on the target machine)
  ├── Port not listed → service not started
  └── Port listed → check application logs
         │
         ▼
dig <hostname>  OR  ping <hostname>
  e.g. dig db01
  ├── No answer → DNS/hostmanager resolution broken → check /etc/hosts
  └── Resolves correctly → application-level issue
```
