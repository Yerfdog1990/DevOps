# VProfile Project on Docker

## Overview

Previously, the VProfile project required **5 separate VMs** — one for each service. With Docker, all 5 services run as **containers on a single VM**, making setup faster, lighter, and easier to manage.

| Service | Role |
|---|---|
| **Nginx** | Web server / reverse proxy (routes to Tomcat) |
| **Tomcat** | Application server (serves the VProfile app) |
| **MySQL** | Database |
| **RabbitMQ** | Message broker |
| **MemCached** | Caching layer |

---

## 1. Setup: Vagrantfile

Use the same Vagrantfile from the Docker Hands-On lecture. It provisions an **Ubuntu 20 (focal64)** VM with Docker Engine pre-installed.

```ruby
Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/focal64"

  config.vm.network "private_network", ip: "192.168.56.82"
  config.vm.network "public_network"

  config.vm.provider "virtualbox" do |vb|
    vb.memory = "2048"
  end

  config.vm.provision "shell", inline: <<-SHELL
    sudo apt-get update
    sudo apt-get install ca-certificates curl gnupg -y

    sudo install -m 0755 -d /etc/apt/keyrings
    curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
    sudo chmod a+r /etc/apt/keyrings/docker.gpg

    echo \
      "deb [arch="$(dpkg --print-architecture)" signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu \
      "$(. /etc/os-release && echo "$VERSION_CODENAME")" stable" | \
      sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

    sudo apt-get update
    sudo apt-get install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin -y
  SHELL
end
```

> **Before bringing up the VM**, make sure all other VMs are shut down to free up resources:
> ```bash
> vagrant global-status --prune   # list and clean all vagrant VMs
> vagrant halt                    # in each VM folder, power it off
> ```

Bring up the VM:

```bash
vagrant up
vagrant ssh
sudo -i          # switch to root
```

## 2. What is Docker Compose?

Running 5 containers one by one with `docker run` would be tedious. **Docker Compose** solves this by letting you define and run **multiple containers together** using a single `docker-compose.yml` file.

| Command | Action |
|---|---|
| `docker compose up -d` | Start all containers in the background |
| `docker compose ps` | List containers managed by compose |
| `docker compose stop` | Stop all containers |
| `docker compose down` | Stop **and remove** all containers |

---

## 3. The docker-compose.yml File

The compose file defines all 5 services. The container images are pre-built and hosted on Docker Hub under the `vprocontainers` account.

```yaml
services:
  vprodb:
    build:
      context: ./Docker-files/db
    image: vprocontainers/vprofiledb
    container_name: vprodb
    ports:
      - "3306:3306"
    volumes:
      - vprodbdata:/var/lib/mysql
    environment:
      - MYSQL_ROOT_PASSWORD=vprodbpass

  vprocache01:
    image: memcached
    ports:
      - "11211:11211"

  vpromq01:
    image: rabbitmq
    ports:
      - "5672:5672"
    environment:
      - RABBITMQ_DEFAULT_USER=guest
      - RABBITMQ_DEFAULT_PASS=guest

  vproapp:
    build:
      context: ./Docker-files/app
    image: vprocontainers/vprofileapp
    container_name: vproapp
    ports:
      - "8080:8080"
    volumes:
      - vproappdata:/usr/local/tomcat/webapps

  vproweb:
    build:
      context: ./Docker-files/web
    image: vprocontainers/vprofileweb
    container_name: vproweb
    ports:
      - "80:80"

volumes:
  vprodbdata: {}
  vproappdata: {}
```

### Key Fields Explained

| Field | Description |
|---|---|
| `build: context` | Path to the Dockerfile used to build the image locally |
| `image` | Name/tag for the built or pulled image |
| `container_name` | Explicit name given to the running container |
| `ports` | `host:container` port mapping |
| `volumes` | Mounts a named volume for **persistent data** |
| `environment` | Sets environment variables inside the container |

### Service Breakdown

| Service | Image | Port | Notes |
|---|---|---|---|
| `vprodb` | `vprocontainers/vprofiledb` | `3306` | MySQL; data persisted in `vprodbdata` volume |
| `vprocache01` | `memcached` (official) | `11211` | No custom build needed |
| `vpromq01` | `rabbitmq` (official) | `5672` | Default guest/guest credentials |
| `vproapp` | `vprocontainers/vprofileapp` | `8080` | Tomcat; webapps persisted in `vproappdata` volume |
| `vproweb` | `vprocontainers/vprofileweb` | `80` | Nginx; entry point for all browser traffic |

### Named Volumes

Two persistent volumes are declared at the bottom:

- **`vprodbdata`** — stores MySQL database files at `/var/lib/mysql` so data survives container restarts
- **`vproappdata`** — stores Tomcat web application files at `/usr/local/tomcat/webapps`

> The full file is available in the project repository under the `docker` branch → `compose/` folder, or from the resource section as a zip file.

## 4. Deploy the VProfile Containers

### Step 1 — Create a working directory

```bash
mkdir compose
cd compose/
```

### Step 2 — Check Docker Compose is available

```bash
docker-compose
```

This should display the available options and subcommands, confirming Docker Compose is installed.

### Step 3 — Download the docker-compose.yml file

```bash
wget https://raw.githubusercontent.com/hkhcoder/vprofile-project/refs/heads/docker/docker-compose.yml
ls
vim docker-compose.yml    # review the file contents
```

> If the download fails (e.g. due to network restrictions), get the file from the resource section, copy its content, and create the file manually:
> ```bash
> vim docker-compose.yml
> # Paste the content, then save and quit (:wq)
> ```

### Step 4 — Start all containers

```bash
docker-compose up -d
```

- `-d` runs everything in the **background**
- Docker will **pull all images** from Docker Hub on the first run — this takes a few minutes

### Step 5 — Verify containers are running

```bash
docker ps
```

All 5 containers should show as **running**:

```
NAME          IMAGE                        STATUS
vproweb       vprocontainers/vprofileweb   Up
vproapp       vprocontainers/vprofileapp   Up
vprodb        vprocontainers/vprofiledb    Up
vprocache01   memcached                    Up
vpromq01      rabbitmq                     Up
```

```bash
docker images    # View all 5 pulled images
```

## 5. Access the Application

```bash
ip addr show     # Find the VM IP address (look for 192.168.x.x, e.g. 192.168.56.82)
```

Open browser → `http://<VM-IP>:80`

**Request flow:**

```
Browser → VM:80 → Nginx container → Tomcat container → Login page
```

### Validate Each Service

| Service | How to Validate |
|---|---|
| **Nginx + Tomcat** | Login page loads at `http://<VM-IP>` |
| **MySQL** | Log in with `admin_vp` / `admin_vp` — successful login = DB working |
| **RabbitMQ** | Click on a user → "All Users" → RabbitMQ queue generated |
| **MemCached** | Click same user again → data loads from cache (faster) |

---

## 6. Cleanup

When done, stop and remove all containers:

```bash
docker compose down          # stop and remove all containers
docker system prune -a       # remove all stopped containers and unused images
```

Then exit and power off the VM:

```bash
exit
vagrant halt
```

> To bring the project back up anytime, just `vagrant up`, `vagrant ssh`, navigate to the `compose/` folder, and run `docker compose up -d`.

## 7. VProfile: VMs vs. Containers

| | VMs (previous setup) | Containers (this setup) |
|---|---|---|
| **Number of machines** | 5 VMs | 1 VM |
| **RAM required** | ~6–8 GB total | ~2 GB |
| **Setup time** | Long (provision each VM) | Fast (one `docker compose up`) |
| **Startup time** | Minutes per VM | Seconds per container |
| **Teardown** | `vagrant destroy` each VM | `docker compose down` |
| **Portability** | Low | High |
