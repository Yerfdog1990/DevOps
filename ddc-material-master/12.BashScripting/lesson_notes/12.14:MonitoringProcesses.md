# Monitoring Processes

## Overview

This section combines `if`/`else`, exit codes (`$?`), file test operators (`-f`), and nested conditions to build a real process monitoring script. The script checks whether Apache (`httpd`) is running, starts it if it is not, and reports the outcome. It is then scheduled to run automatically every minute using cron — turning it into an actual monitoring tool.

---

## The Concept — How to Detect if a Process Is Running

When `httpd` is running, it creates a **PID file** at `/var/run/httpd/httpd.pid`. This file contains the process ID. When the process stops, the file is removed.

There are two ways to check this:

### Method 1 — Check Exit Code of `ls`

```bash
ls /var/run/httpd/httpd.pid &> /dev/null

if [ $? -eq 0 ]
then
    echo "Httpd process is running."
```

- `ls` tries to list the file
- `&> /dev/null` discards all output (stdout and stderr) — we only care about the exit code
- `$?` is `0` if the file exists, non-zero if it does not

### Method 2 — Use the `-f` File Test Operator (Cleaner)

```bash
if [ -f /var/run/httpd/httpd.pid ]
then
    echo "Httpd process is running."
```

`-f` directly tests whether the file exists and is a regular file — no extra command needed. This is the preferred approach because it avoids running an unnecessary `ls` command.

Both methods produce identical results. The `-f` approach is cleaner and more idiomatic.

## The Monitoring Script (`11_monit.sh`)

### Version 1 — Using Exit Code of `ls`

```bash
#!/bin/bash

echo "#######################################"
date

ls /var/run/httpd/httpd.pid &> /dev/null

if [ $? -eq 0 ]
then
    echo "Httpd process is running."
else
    echo "Httpd process is NOT running."
    echo "Starting the process ....."

    systemctl start httpd

    if [ $? -eq 0 ]
    then
        echo "Processes started successfully!"
    else
        echo "Process failed to start. Please contact the admin."
    fi
fi

echo "#######################################"
```

### Version 2 — Using `-f` File Test Operator (Preferred)

```bash
#!/bin/bash

echo "#######################################"
date

if [ -f /var/run/httpd/httpd.pid ]
then
    echo "Httpd process is running."
else
    echo "Httpd process is NOT running."
    echo "Starting the process ....."

    systemctl start httpd

    if [ $? -eq 0 ]
    then
        echo "Httpd process started successfully."
    else
        echo "Failed to start Httpd process. Please contact the admin."
    fi
fi

echo "#######################################"
```

## Understanding Nested `if` Statements

The script contains a condition **inside** another condition's `else` block. This is called a **nested `if`**:

```
if [ process is running ]
then
    print "running"
else
    print "not running"
    try to start the process

    if [ start was successful ]   ← nested if
    then
        print "started successfully"
    else
        print "failed to start"
    fi                             ← closes inner if

fi                                 ← closes outer if
```

Each `if` has its own `fi`. Make sure they are properly paired — a missing or misplaced `fi` is a common source of script errors.

### Flow Diagram

```
Script runs
    │
    ├── PID file exists?
    │       │
    │      YES → "Httpd process is running."
    │       │
    │       NO  → "Httpd process is NOT running."
    │             └── systemctl start httpd
    │                     │
    │                 $? = 0? → "Started successfully."
    │                 $? ≠ 0? → "Failed to start. Contact admin."
    │
    └── print separator line (#####)
```

## Scheduling with Cron — Running Every Minute

The script becomes a real monitoring tool when scheduled to run automatically. **Cron** is the Linux task scheduler. **Crontab** is the file where scheduled tasks (cron jobs) are defined.

### Cron Schedule Format

```
MM  HH  DOM  MON  DOW  COMMAND
│   │    │    │    │
│   │    │    │    └── Day of Week (0=Sun, 1=Mon ... 6=Sat)
│   │    │    └─────── Month (1-12)
│   │    └──────────── Day of Month (1-31)
│   └───────────────── Hour (0-23)
└───────────────────── Minute (0-59)
```

`*` means "every" — every minute, every hour, every day, etc.

**Examples:**

| Schedule | Meaning |
|----------|---------|
| `* * * * *` | Every minute |
| `30 20 * * 1-5` | 8:30 PM, Monday–Friday |
| `0 2 * * *` | 2:00 AM every day |
| `0 0 1 * *` | Midnight on the 1st of every month |

### Adding the Cron Job

Edit the crontab for the current user:

```bash
crontab -e
```

Add the following line:

```bash
# MM  HH  DOM  MON  DOW  COMMAND
# 30  20   *    *   1-5  COMMAND  ← example: 8:30 PM Mon-Fri
* * * * * /opt/scripts/11_monit.sh &>> /var/log/monit_httpd.log
```

Save and exit (`:wq` in vim). Cron installs the job immediately.

### Output Redirection — `&>>`

```bash
&>> /var/log/monit_httpd.log
```

| Operator | Meaning |
|----------|---------|
| `>>` | Append stdout to file |
| `&>>` | Append **both stdout and stderr** to file |

This ensures every line of output from the script — including error messages — is appended to the log file without overwriting previous entries.

### Verifying the Cron Job

```bash
# List current cron jobs:
crontab -l

# Check the cron daemon is running:
systemctl status crond

# Start cron if needed:
systemctl start crond
systemctl enable crond

# Watch the log file update in real time:
tail -f /var/log/monit_httpd.log
```

## Alternative — Check Using `systemctl` Directly

Since `httpd` is managed by `systemd`, the most reliable check is:

```bash
if systemctl is-active --quiet httpd
then
    echo "Httpd process is running."
else
    echo "Httpd process is NOT running."
    systemctl start httpd
fi
```

**Why this is more reliable:** A PID file may sometimes be stale (the file exists but the process has actually crashed). `systemctl is-active` queries the service manager directly and reflects the true current state. The `--quiet` flag suppresses output — we only care about the exit code.

## Summary

This script demonstrates how scripting concepts combine to solve a real operational problem:

1. **Detect** if a process is running (PID file check or `systemctl`)
2. **React** if it is not (start the process)
3. **Verify** the reaction succeeded (nested `if` on exit code)
4. **Log** all output to a file for audit and debugging
5. **Automate** the entire loop with cron to run every minute

This is the foundation of how actual monitoring tools like **Monit**, **Nagios**, and **Zabbix** work — the difference is they do it at scale with alerting, dashboards, and integrations. The logic is the same.
