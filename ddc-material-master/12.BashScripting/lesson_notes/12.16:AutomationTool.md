# Building an Automation Tool 

## Overview

This is the culmination of everything covered in the bash scripting section. All the concepts — variables, command substitution, `if`/`elif`, `for` loops, SSH key authentication, remote execution, and `scp` — come together to build a real automation framework that deploys a website to multiple servers across different operating systems with a single command.

This is the same approach that tools like **Ansible** use at their core. Understanding it here means you already understand the foundation of those tools.

---

## The Architecture

```
scriptbox (control node)
    │
    ├── remoteHost        ← inventory file (list of target servers)
    ├── multios_websetup.sh  ← deployment script (CentOS + Ubuntu aware)
    └── webdeploy.sh      ← orchestrator (loops through hosts, pushes and runs)
         │
         ├── scp → web01 → execute → cleanup
         ├── scp → web02 → execute → cleanup
         └── scp → web03 → execute → cleanup
```

---

## Directory Structure

Create a dedicated directory for the remote web setup:

```bash
mkdir /opt/scripts/remote_websetup
cd /opt/scripts/remote_websetup
```

The directory will contain:

```
remote_websetup/
├── remoteHost           ← target server list
├── multios_websetup.sh  ← the deployment script
└── webdeploy.sh         ← the orchestrator script
```

## File 1 — `remoteHost` (Inventory File)

This file is the equivalent of an Ansible inventory. It lists the target servers — one per line:

```
web01
web02
web03
```

You can use hostnames (as long as `/etc/hosts` has the mappings) or IP addresses. Add as many servers as you need — 10, 100, 500 — the loop handles all of them the same way.

### Testing the Inventory

Before deploying, verify the file and connectivity:

```bash
# Print each host from the file:
for host in $(cat remoteHost); do echo $host; done
# Output: web01 web02 web03

# Test SSH connection to each:
for host in $(cat remoteHost); do ssh devops@$host hostname; done
# Output: web01 web02 web03

# Test uptime on each:
for host in $(cat remoteHost); do ssh devops@$host uptime; done
# Output: uptime from each server, no password prompts
```

## File 2 — `multios_websetup.sh` (Multi-OS Deployment Script)

This script is the key innovation. The same script runs on both CentOS and Ubuntu — it detects the OS and uses the correct package manager and service name automatically.

### The OS Detection Logic

```bash
yum --help &> /dev/null
if [ $? -eq 0 ]
then
    # CentOS/RHEL — yum is available
    PACKAGE="httpd wget unzip"
    SVC="httpd"
    ...
else
    # Ubuntu — yum not found
    PACKAGE="apache2 wget unzip"
    SVC="apache2"
    ...
fi
```

`yum --help` is run and all output is discarded (`&> /dev/null`). The exit code tells us everything:
- Exit code `0` → `yum` exists → CentOS/RHEL system
- Non-zero exit code → `yum` not found → Ubuntu system

### The Complete Script

```bash
#!/bin/bash

# OS Detection
yum --help &> /dev/null

if [ $? -eq 0 ]
then
    # ============================================
    # CentOS / RHEL Setup
    # ============================================
    echo "Running setup on CentOS"

    PACKAGE="httpd wget unzip"
    SVC="httpd"
    URL='https://www.tooplate.com/zip-templates/2098_health.zip'
    ART_NAME='2098_health'
    TEMPDIR='/tmp/webfiles'

    echo "########################################"
    echo "Installing packages."
    echo "########################################"
    sudo yum install $PACKAGE -y > /dev/null
    echo

    echo "########################################"
    echo "Start & Enable $SVC Service"
    echo "########################################"
    sudo systemctl start $SVC
    sudo systemctl enable $SVC
    echo

    echo "########################################"
    echo "Starting Artifact Deployment"
    echo "########################################"
    mkdir -p $TEMPDIR
    cd $TEMPDIR

    wget $URL > /dev/null
    unzip $ART_NAME.zip > /dev/null
    sudo cp -r $ART_NAME/* /var/www/html/
    echo

    echo "########################################"
    echo "Restarting HTTPD service"
    echo "########################################"
    systemctl restart $SVC
    echo

    echo "########################################"
    echo "Removing Temporary Files"
    echo "########################################"
    rm -rf $TEMPDIR
    echo

    sudo systemctl status $SVC
    ls /var/www/html/

else
    # ============================================
    # Ubuntu Setup
    # ============================================
    echo "Running setup on Ubuntu"

    PACKAGE="apache2 wget unzip"
    SVC="apache2"
    URL='https://www.tooplate.com/zip-templates/2098_health.zip'
    ART_NAME='2098_health'
    TEMPDIR='/tmp/webfiles'

    echo "########################################"
    echo "Installing packages."
    echo "########################################"
    sudo apt update -y > /dev/null
    sudo apt install $PACKAGE -y > /dev/null
    echo

    echo "########################################"
    echo "Start & Enable $SVC Service"
    echo "########################################"
    sudo systemctl start $SVC
    sudo systemctl enable $SVC
    echo

    echo "########################################"
    echo "Starting Artifact Deployment"
    echo "########################################"
    mkdir -p $TEMPDIR
    cd $TEMPDIR

    wget $URL > /dev/null
    unzip $ART_NAME.zip > /dev/null
    sudo cp -r $ART_NAME/* /var/www/html/
    echo

    echo "########################################"
    echo "Restarting HTTPD service"
    echo "########################################"
    systemctl restart $SVC
    echo

    echo "########################################"
    echo "Removing Temporary Files"
    echo "########################################"
    rm -rf $TEMPDIR
    echo

    sudo systemctl status $SVC
    ls /var/www/html/
fi
```

### Power of Variables Demonstrated

Notice that `SVC`, `PACKAGE`, `URL`, `ART_NAME`, and `TEMPDIR` are set inside the `if`/`else` blocks based on the OS, but all the deployment commands below are **identical** — they just reference the variables. This is why variables matter:

```bash
# Same command works for both CentOS (httpd) and Ubuntu (apache2):
systemctl restart $SVC
sudo apt install $PACKAGE   # Ubuntu
sudo yum install $PACKAGE   # CentOS
```

Change the variable, reuse the logic.

### Testing Locally First

Before pushing to remote servers, test the script on `scriptbox` itself:

```bash
chmod +x multios_websetup.sh
./multios_websetup.sh
```

Since `scriptbox` is CentOS, it should print "Running setup on CentOS" and proceed with `httpd`.

## File 3 — `webdeploy.sh` (Orchestrator Script)

This script reads the host list, copies `multios_websetup.sh` to each server using `scp`, executes it via SSH, then cleans up the script file from the remote server.

### `scp` — Secure Copy

`scp` transfers files between machines using the SSH protocol. Since SSH key authentication is already set up, `scp` also works without a password:

```bash
scp source_file user@host:/destination/path/

# Example:
scp multios_websetup.sh devops@web01:/tmp/
```

To fetch a file (reverse direction):

```bash
scp devops@web01:/tmp/somefile ./local/
```

### The Complete Orchestrator Script

```bash
#!/bin/bash

USR="devops"

for host in $(cat remoteHost)
do
    echo
    echo "###############################################"
    echo "Connecting to $host"

    scp multios_websetup.sh $USR@$host:/tmp/

    echo "Executing script on $host"
    ssh $USR@$host "sudo bash /tmp/multios_websetup.sh"

    ssh $USR@$host "sudo rm -rf /tmp/multios_websetup.sh"

    echo "###############################################"
    echo
done
```

### Line-by-Line Breakdown

| Line | What it does |
|------|-------------|
| `USR="devops"` | Stores the remote username as a variable |
| `for host in $(cat remoteHost)` | Reads the host file and loops through each host |
| `scp multios_websetup.sh $USR@$host:/tmp/` | Copies the deployment script to `/tmp/` on the remote server |
| `ssh $USR@$host "sudo bash /tmp/multios_websetup.sh"` | Executes the script on the remote server with `sudo` |
| `ssh $USR@$host "sudo rm -rf /tmp/multios_websetup.sh"` | Deletes the script from `/tmp/` after execution |

### Make Both Scripts Executable

```bash
chmod +x multios_websetup.sh
chmod +x webdeploy.sh
```

## Note on `sudo: yum: command not found` on `web03`

When running `sudo yum install git` on `web03` in an earlier test, the output ended with:

```
sudo: yum: command not found
```

This is expected — `web03` is Ubuntu and does not have `yum`. The `multios_websetup.sh` script handles this by detecting the OS first and using `apt` on Ubuntu. The `webdeploy.sh` script pushes the same script to all servers and it adapts automatically.

## The Full Deployment Workflow

```
1. Create remoteHost inventory file
   └── web01, web02, web03

2. Write multios_websetup.sh
   └── Detects OS (yum exit code)
   └── Sets variables based on OS (httpd vs apache2)
   └── Installs, deploys, starts service

3. Write webdeploy.sh
   └── Loops through remoteHost
   └── scp script to /tmp/ on each server
   └── ssh to execute script
   └── ssh to delete script

4. Run: ./webdeploy.sh
   └── All servers provisioned automatically
```

## What This Is

This framework — a control node, an inventory file, a script that adapts per OS, and an orchestrator that distributes and runs it — **is exactly what Ansible does**, just with more sophistication:

| This framework | Ansible equivalent |
|---------------|-------------------|
| `remoteHost` file | Ansible inventory |
| `multios_websetup.sh` | Ansible playbook tasks |
| OS detection with `if/elif` | Ansible `when:` conditionals and `ansible_os_family` |
| `scp` + `ssh` + `for` loop | Ansible's connection plugin |
| Variables (`$SVC`, `$PACKAGE`) | Ansible variables |

The difference is scale, error handling, idempotency, and tooling. The concepts are identical.

## Summary — All Scripting Concepts Used

| Concept | Where used |
|---------|-----------|
| Variables | `USR`, `PACKAGE`, `SVC`, `URL`, `ART_NAME`, `TEMPDIR` |
| Command substitution | `$(cat remoteHost)` — reads file into loop |
| `for` loop | Iterates through each host in the inventory |
| `if`/`else` | OS detection and different code paths |
| Exit code `$?` | Checking if `yum` is available |
| `&> /dev/null` | Discarding output while keeping exit code |
| SSH key authentication | Passwordless login to all web servers |
| `scp` | Pushing script files to remote servers |
| `ssh "command"` | Executing commands on remote servers |
| `sudo` | Running privileged commands as `devops` user |
| `NOPASSWD: ALL` | Enabling `sudo` without password prompts |
| `/etc/hosts` | Hostname resolution without DNS |
