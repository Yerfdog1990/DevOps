# Exporting Variables

## The Problem: Variable Scope

Variables you create in a shell session are **local to that process**. When you close the shell or log out, the variable is gone. And even while the shell is running, a variable is only visible to that specific shell — child processes (like scripts you run) cannot see it unless it is explicitly exported.

---

## Shell Variable vs Exported Variable

### Without Export — Child Cannot See It

```bash
SEASON="Monsoon"
echo $SEASON
# Output: Monsoon    ← available in the current shell
```

Now run a script that references `$SEASON`:

```bash
# textvars.sh
#!/bin/bash
echo "The $SEASON season is more than expected, this time."
```

```bash
./textvars.sh
# Output: The  season is more than expected, this time.
#                ↑ empty — script cannot see the variable
```

The script runs in a **separate child process**. A plain shell variable is private to the parent shell — it is not inherited.

### With Export — Child Can See It

```bash
export SEASON="Monsoon"
./textvars.sh
# Output: The Monsoon season is more than expected, this time.
```

`export` marks the variable so it is included in the **environment** passed to every child process spawned from this shell.

---

## What `export` Actually Does

`export` does **not** write anything to a file. It marks the variable as part of the shell's **environment** — an in-memory data structure associated with the running process.

```bash
SEASON="Monsoon"         # shell variable only (private)
export SEASON            # promoted to environment variable (inherited by children)
```

You can verify the difference:

```bash
SEASON="Monsoon"

# Check shell variables — SEASON appears:
set | grep SEASON
# Output: SEASON=Monsoon

# Check environment variables — SEASON does NOT appear yet:
env | grep SEASON
# Output: (nothing)

# Now export it:
export SEASON

# Check environment again — SEASON now appears:
env | grep SEASON
# Output: SEASON=Monsoon
```

**Think of it this way:**

| Analogy | Meaning |
|---------|---------|
| Shell variable | A note on your desk that only you can see |
| Exported variable | The note is attached to every document you hand to child processes |
| `.bashrc` / `/etc/profile` | A permanent instruction manual that recreates the note every time you start work |

---

## Export Is Still Temporary

Export solves the **child process problem** — not the **persistence problem**. An exported variable lives only as long as the shell process that exported it.

### Terminal Proof

```bash
[root@scriptbox scripts]# export SEASON="Monsoon"
[root@scriptbox scripts]# env | grep SEASON
SEASON=Monsoon

[root@scriptbox scripts]# ./textvars.sh
The Monsoon season is more than expected, this time.

[root@scriptbox scripts]# exit
logout

[vagrant@scriptbox ~]$ sudo -i
[root@scriptbox ~]# env | grep SEASON
                          ← empty — new shell has no SEASON

[root@scriptbox scripts]# ./textvars.sh
The  season is more than expected, this time.
                          ← empty because SEASON is gone
```

**What happened:**
1. `export SEASON="Monsoon"` — adds `SEASON` to Root Shell #1's environment ✅
2. `./textvars.sh` — child script inherits it and prints correctly ✅
3. `exit` — Root Shell #1 is terminated; its in-memory environment is destroyed
4. `sudo -i` — starts Root Shell #2 with a **fresh environment** — no `SEASON`
5. `./textvars.sh` — `SEASON` is empty; prints blank ✅ (confirms variable is gone)
6. `cd /opt/scripts` — changing directories has **no effect** on environment variables

> **Key rule:** An exported variable lives only as long as the shell process that created it. It disappears the moment that shell exits.

## Demonstrating Scope: Local vs Exported Variable in a Script

```bash
# In your shell:
var1=foo
export var1
```

```bash
# script1.sh
#!/bin/bash
# demonstrate variable scope

var2=foobar

echo "Printing exported variable from bash shell:"
echo $var1         # accessible — exported by parent

echo "Printing variable defined in the script:"
echo $var2         # accessible — defined locally in this script
```

```bash
./script1.sh
# Output:
# Printing exported variable from bash shell:
# foo
# Printing variable defined in the script:
# foobar
```

`var1` is visible in the script because it was exported from the parent shell. `var2` is visible because it was defined inside the script itself. A variable defined inside a script is **not** visible back in the parent shell after the script finishes.

---

## What Problem Does `export` Actually Solve?

Since exported variables are still temporary, you might wonder why bother. The answer: `export` solves **inter-process communication through the environment** — not persistence.

| Scenario | `export` needed? | Why |
|----------|-----------------|-----|
| Use a variable in the same shell | No | Already visible |
| Pass a variable to a script you run | **Yes** | Script is a child process |
| Configure `JAVA_HOME` for Maven | **Yes** | `mvn` is a child process |
| Set `DB_HOST` for an app script | **Yes** | App script is a child process |
| Pass AWS profile to `aws` CLI | **Yes** | `aws` is a child process |

### Real-World Examples

```bash
# Java applications need JAVA_HOME:
export JAVA_HOME=/usr/lib/jvm/java-17
export PATH=$JAVA_HOME/bin:$PATH
mvn package        # mvn inherits JAVA_HOME and PATH

# Database credentials:
export DB_HOST=dbserver
export DB_USER=admin
./start-app.sh     # app reads these from environment

# AWS CLI profile:
export AWS_PROFILE=production
aws s3 ls          # uses the production profile
```

## Making Variables Permanent

To make a variable survive logout and persist across sessions, add the `export` command to one of the shell startup files. These files are automatically executed (sourced) when a new shell starts.

### Startup File Options

| File | Who it affects | When sourced |
|------|---------------|-------------|
| `~/.bashrc` | Current user only | Every interactive shell |
| `~/.bash_profile` or `~/.profile` | Current user only | Login shells |
| `/etc/profile` | **All users** system-wide | Every login shell |

### How to Add a Permanent Variable

**For the current user (root):**

```bash
vim ~/.bashrc
# Add at the end:
export SEASON="Monsoon"
```

Save and exit. Apply immediately without logging out:

```bash
source ~/.bashrc
```

**For all users (system-wide):**

```bash
vim /etc/profile
# Add at the end:
export SEASON="Winter"
```

### Understanding Startup File Priority

Both `/etc/profile` and `~/.bashrc` are sourced on login — `/etc/profile` first, then `~/.bashrc`. If the same variable is set in both, the user's `~/.bashrc` value **wins** (it is sourced last and overrides).

In this example, `/etc/profile` has `SEASON="Monsoon"` and vagrant's `~/.bashrc` has `SEASON="Summer"`.

### Live Terminal Demonstration

After adding `SEASON="Summer"` to vagrant's `~/.bashrc` and `SEASON="Monsoon"` to `/etc/profile`:

```bash
[vagrant@scriptbox ~]$ echo $SEASON
Summer
```

Vagrant's `~/.bashrc` sets `SEASON="Summer"`. Since `~/.bashrc` is sourced after `/etc/profile`, it overrides the global value. The vagrant user sees `Summer`.

```bash
[vagrant@scriptbox ~]$ sudo -i
[root@scriptbox ~]# echo SEASON
SEASON
```

> **Notice:** `echo SEASON` (without the `$`) prints the literal word `SEASON` — not the value. Always use `$SEASON` to reference a variable.

```bash
[root@scriptbox ~]# echo $SEASON
Monsoon
```

Root's `~/.bashrc` does not have a `SEASON` entry, so only `/etc/profile` applies. Root sees `Monsoon` — the global value.

```bash
[root@scriptbox ~]# env | grep SEASON
SEASON=Monsoon
```

Confirms `SEASON` is in root's environment as an exported variable, with value `Monsoon`.

```bash
[root@scriptbox ~]# set | grep SEASON
SEASON=Monsoon
_=SEASON
```

`set` lists all shell variables. `SEASON=Monsoon` confirms the value. The `_=SEASON` line is Bash's internal `$_` variable, which stores the last argument of the previous command — in this case `SEASON` (the argument to the previous `echo`). It is not related to `SEASON`.

```bash
[root@scriptbox ~]# /opt/scripts/textvars.sh
The Monsoon season is more than expected, this time.
```

The script is run as a child process of the root shell. It inherits root's environment — including `SEASON=Monsoon` from `/etc/profile` — and prints correctly.

### Startup File Priority Summary

| User | `/etc/profile` | `~/.bashrc` | Final value of `$SEASON` |
|------|---------------|------------|--------------------------|
| `vagrant` | `Monsoon` | `Summer` | **`Summer`** — `.bashrc` wins (sourced last) |
| `root` | `Monsoon` | *(not set)* | **`Monsoon`** — only `/etc/profile` applies |

### Writing to a Startup File with `echo`

Instead of opening the file with `vim`, you can append directly:

```bash
echo 'export SEASON="Monsoon"' >> ~/.bash_profile
```

**What this does:**
- `echo 'export SEASON="Monsoon"'` — produces the text `export SEASON="Monsoon"`
- `>>` — appends it to the file (does not overwrite)
- `~/.bash_profile` — the startup file

This is two separate operations:
- `echo ... >> file` — **writes text to a file** (not an environment variable)
- On next login, Bash reads the file and executes `export SEASON="Monsoon"` — **that** creates the environment variable

## Complete Reference

### Commands

```bash
# Set a local shell variable:
var1=foo

# Export it (make it available to child processes):
export var1

# Set and export in one step:
export var1=foo

# Check if a variable is in the environment:
env | grep VAR_NAME

# List all environment variables:
env
printenv

# Unset a variable:
unset var1
```

### Startup Files

```bash
# Apply changes immediately (without logout):
source ~/.bashrc
source ~/.bash_profile
source /etc/profile
```

## Summary

| Concept | Detail |
|---------|--------|
| **Shell variable** | Visible only in current shell; not passed to child processes |
| **`export`** | Marks variable for inclusion in child process environments |
| **Scope of exported variable** | Current shell + all child processes |
| **Lifetime of exported variable** | Until the exporting shell exits |
| **Changing directories** | Has no effect on environment variables |
| **`sudo -i`** | Creates a new shell with a fresh environment — exported variables are lost |
| **Make permanent for one user** | Add `export VAR=value` to `~/.bashrc` or `~/.bash_profile` |
| **Make permanent for all users** | Add `export VAR=value` to `/etc/profile` |
| **Apply without logout** | Run `source ~/.bashrc` |
