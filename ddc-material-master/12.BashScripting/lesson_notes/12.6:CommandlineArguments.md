# Command Line Arguments

## What Are Command Line Arguments?

You have already been using arguments with Linux commands — when you type `ls /etc`, the path `/etc` is an argument. When you type `cp source destination`, both paths are arguments. Bash scripts can accept arguments the same way, making them flexible and reusable.

Instead of hardcoding values like a URL or a filename inside the script, you pass them in at runtime — the script uses whatever the user provides.

---

## Automatic Argument Variables

When a script runs, Bash automatically sets several variables based on what was passed on the command line:

| Variable | Value |
|----------|-------|
| `$0` | The name (or path) of the script itself |
| `$1` – `$9` | The first through ninth command-line arguments |
| `$#` | How many arguments were passed to the script |
| `$*` | All arguments as a single string |
| `$@` | All arguments as separate items |

These variables do **not** need to be declared — Bash sets them automatically. If an argument is not passed, accessing its variable returns empty (no error, just blank output).

## Demonstrating Argument Variables

### Understanding `$0` Through `$3`

Create a script `4_args.sh`:

```bash
#!/bin/bash

echo "Value of 0 is: $0"
echo "Value of 1 is: $1"
echo "Value of 2 is: $2"
echo "Value of 3 is: $3"
```

Make it executable and run it with no arguments first:

```bash
chmod +x 4_args.sh
./4_args.sh
```

Output:

```text
Value of 0 is: ./4_args.sh
Value of 1 is:
Value of 2 is:
Value of 3 is:
```

- `$0` is always the script name/path — it is **reserved** and cannot be used for user input
- `$1`, `$2`, `$3` are empty because no arguments were passed — Bash does not throw an error for undefined argument variables

Now run it with three arguments:

```bash
./4_args.sh Linux DevOps Scripting
```

Output:

```text
Value of 0 is: ./4_args.sh
Value of 1 is: Linux
Value of 2 is: DevOps
Value of 3 is: Scripting
```

The arguments are assigned in order: the first word after the script name goes into `$1`, the second into `$2`, and so on up to `$9`.

### Using `$#`, `$*`, and `$@`

```bash
#!/bin/bash
# morevariables.sh — demonstrates argument variables

echo "My name is $0 and I have been given $# command line arguments"
echo "Here they are: $*"
echo "The 2nd command line argument is: $2"
```

Run it:

```bash
./morevariables.sh bob fred sally
```

Output:

```text
My name is morevariables.sh and I have been given 3 command line arguments
Here they are: bob fred sally
The 2nd command line argument is: fred
```

## Applying Arguments to the Web Setup Script

The real power of command line arguments is making scripts **reusable**. The variables-based web setup script (`3_vars_websetup.sh`) had the URL and artifact name hardcoded as variables at the top. With command line arguments, the user can pass any URL and artifact name — deploying a completely different website without editing the script at all.

### What Changes

In `3_vars_websetup.sh`, these two lines defined the URL and artifact name:

```bash
URL='https://www.tooplate.com/zip-templates/2098_health.zip'
ART_NAME='2098_health'
```

In `5_args_websetup.sh`, these are replaced by command line arguments:

```bash
# URL='https://www.tooplate.com/zip-templates/2098_health.zip'  ← commented out
# ART_NAME='2098_health'                                         ← commented out
```

And wherever `$URL` and `$ART_NAME` were used, they are now replaced by `$1` and `$2`:

```bash
wget $1 > /dev/null          # $1 = the URL argument
unzip $2.zip > /dev/null     # $2 = the artifact name argument
sudo cp -r $2/* /var/www/html/
```

### The Complete `5_args_websetup.sh`

```bash
#!/bin/bash

# ########################################
# Variables
# ########################################
PACKAGE="httpd wget unzip"
SVC="httpd"
# $1 = URL of the zip file to download
# $2 = Name of the artifact (directory name after unzip, without .zip)
TEMP_DIR='/tmp/webfiles'

# Installing Dependencies
echo "#############################################"
echo "Installing packages."
echo "#############################################"
sudo yum install $PACKAGE -y > /dev/null
echo

# Start & Enable Service
echo "#############################################"
echo "Start & Enable $SVC Service"
echo "#############################################"
sudo systemctl start $SVC
sudo systemctl enable $SVC
echo

# Creating Temp Directory & Deploying Artifact
echo "#############################################"
echo "Starting Artifact Deployment"
echo "#############################################"
mkdir -p $TEMP_DIR
cd $TEMP_DIR
echo

wget $1 > /dev/null
unzip $2.zip > /dev/null
sudo cp -r $2/* /var/www/html/
echo

# Bounce Service
echo "#############################################"
echo "Restarting $SVC service"
echo "#############################################"
systemctl restart $SVC
echo

# Clean Up
echo "#############################################"
echo "Removing Temporary Files"
echo "#############################################"
rm -rf $TEMP_DIR
echo

echo "#############################################"
echo "Deployment Complete. Service Status:"
echo "#############################################"
sudo systemctl status $SVC
echo
echo "Contents of /var/www/html:"
ls /var/www/html/
```

## Running the Script with Arguments

### Syntax

```bash
./5_args_websetup.sh <URL> <ARTIFACT_NAME>
```

- `$1` receives the URL
- `$2` receives the artifact name (the folder name that appears after unzipping — without the `.zip` extension)

### Example — Deploying a Different Website

After running the dismantle script to clean up, deploy the *Split Portfolio* template:

```bash
./5_args_websetup.sh \
  https://www.tooplate.com/zip-templates/2154_split_portfolio.zip \
  2154_split_portfolio
```

## How to Find the Artifact Name

When using this script with a new tooplate.com template, you need to know the artifact name (`$2`). The easiest way:

1. Look at the download URL — `2154_split_portfolio.zip`
2. Remove the `.zip` extension — `2154_split_portfolio`
3. That is your `$2` argument

Alternatively, check the Network tab (F12) when clicking Download on tooplate.com. The filename in the URL is the artifact name.

## Script Evolution Summary

This script has gone through three iterations, each teaching a new concept:

| Script | Key Concept | Limitation |
|--------|------------|------------|
| `2_websetup.sh` | Commands in a file | Hardcoded everything — must edit to change |
| `3_vars_websetup.sh` | Variables | Values at the top — easier to change, but still requires editing the script |
| `5_args_websetup.sh` | Command line arguments | Fully reusable — pass any URL and artifact at runtime, no editing needed |

---

## What Happens If Arguments Are Missing?

If the user runs the script without providing the required arguments:

```bash
./5_args_websetup.sh
```

`$1` and `$2` will be empty. This causes:

```text
wget: missing URL
```

And the unzip and copy commands will also fail. For now, the user simply must remember to pass both arguments. Later, with conditionals (`if` statements), you can add validation that checks whether the required arguments were provided and prints a usage message if they weren't.

## Summary

| Concept | Syntax | Notes |
|---------|--------|-------|
| Script name | `$0` | Always the script path — reserved, not for user input |
| First argument | `$1` | First word after script name |
| Second argument | `$2` | Second word after script name |
| Up to ninth | `$9` | Maximum positional arguments without special syntax |
| Argument count | `$#` | Number of arguments passed |
| All arguments | `$*` | All arguments as one string |
| Unset argument | (empty) | No error — just blank; validate with `if` later |
