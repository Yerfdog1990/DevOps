# Writing Your First Bash Script

## Setup — Create a Scripts Directory

All scripts in this session will be stored in a dedicated directory. Create it first:

```bash
mkdir -p /opt/scripts
cd /opt/scripts
```

---

## Install vim

On the CentOS Stream 9 box, `vim` is not installed by default. Install it before writing any scripts:

```bash
dnf install vim -y
```

> A script is just a text file containing bash commands. Any text editor works, but `vim` is what is used throughout this session.

---

## Writing the First Script

Create a new file called `firstscript.sh`. The `.sh` extension is the conventional extension for shell scripts — it is not mandatory, but it is good practice as it makes scripts immediately recognisable:

```bash
vim firstscript.sh
```

Enter the following content:

```bash
#!/bin/bash
# ###############################################
# This script prints system info
# ###############################################

echo "####################################################"
echo "System uptime:"
echo "####################################################"
uptime

echo

echo "####################################################"
# Checking system uptime
echo "Memory utilization:"
echo "####################################################"
free -m

echo

echo "####################################################"
# Memory utilization
echo "Disk utilization:"
echo "####################################################"
df -h

echo
```

Save and exit: press `Esc`, then type `:wq` and press `Enter`.

## Understanding the Script Line by Line

### The Shebang — Line 1

```bash
#!/bin/bash
```

The very first line of every bash script must be the **shebang** (`#!`). It tells the operating system which interpreter to use to execute the file.

- `#!` — the shebang character (hash + exclamation — one unit, not a comment)
- `/bin/bash` — the path to the bash interpreter

When the script runs, the OS opens `/bin/bash` and passes all the commands in the file to it. If it were a Python script, this line would be `#!/usr/bin/python3`. If it were Ruby, `#!/usr/bin/ruby`.

> **Important:** The `#!` on line 1 is a shebang — it is **not** a comment, even though comments also use `#`. Every other line starting with `#` is ignored by the interpreter. The shebang on line 1 is a special instruction to the OS.

### Comments — `#`

```bash
# This script prints system info
```

Any line starting with `#` (other than the shebang on line 1) is a **comment** — the interpreter ignores it completely. Comments exist for humans, not the computer.

**Why comments matter:**
- When you revisit a script a month later, comments tell you what each section does without having to read and analyse every command
- They make scripts readable for other people on your team
- They are a habit worth building from the very beginning

```bash
# Good comment examples:
# Checking system uptime
# Memory utilization
# This section installs required packages
```

### `echo` — Printing Output

```bash
echo "System uptime:"
echo
```

`echo` prints text to the terminal. A plain `echo` with no argument prints a **blank line**, which is used to add visual spacing between sections of output.

### System Commands

The three commands used in the script are standard Linux utilities. In a script, they work exactly the same as when typed directly in the terminal — the script just runs them all in sequence automatically.

#### `uptime`

```bash
uptime
```

Displays how long the system has been running, the number of logged-in users, and the system load averages over the last 1, 5, and 15 minutes.

Example output:

```text
10:05:42 up  2:13,  1 user,  load average: 0.00, 0.01, 0.05
```

---

#### `free -m`

```bash
free -m
```

- `free` displays information about the system's memory usage
- `-m` shows values in **megabytes** instead of bytes (easier to read)

Example output:

```text
              total        used        free      shared  buff/cache   available
Mem:            990         112         701           6         176         731
Swap:          2047           0        2047
```

| Column | Meaning |
|--------|---------|
| `total` | Total installed memory |
| `used` | Memory currently in use |
| `free` | Completely unused memory |
| `shared` | Memory shared between processes |
| `buff/cache` | Memory used for buffers and cache (can be freed if needed) |
| `available` | Memory available for new processes without swapping |

---

#### `df -h` — Disk Utilization

```bash
# Disk Utilization
echo "##########################################"
echo "Disk Utilization"
df -h
```

Breaking down each line:

**`# Disk Utilization`**
- `#` starts a comment in Bash
- Comments are ignored when the script runs
- This line is simply a note for humans reading the script, indicating that the next section is about disk usage

**`echo "##########################################"`**
- `echo` prints text to the terminal
- This prints a row of `#` characters as a visual separator, making the output easier to read:

```text
##########################################
```

**`echo "Disk Utilization"`**
- Prints a section heading:

```text
Disk Utilization
```

**`df -h`**
- `df` stands for **disk filesystem**
- Displays information about mounted filesystems and how much disk space they are using
- `-h` means **human-readable** — sizes are shown in KB, MB, GB, or TB instead of raw bytes

Example output:

```text
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1       100G   60G   35G  64% /
tmpfs           2.0G     0  2.0G   0% /dev/shm
```

| Column | Meaning |
|--------|---------|
| `Filesystem` | Disk or partition name |
| `Size` | Total size of the filesystem |
| `Used` | Space currently used |
| `Avail` | Free space available |
| `Use%` | Percentage of disk used |
| `Mounted on` | Directory where the filesystem is attached |

**Complete output for the disk section:**

```text
##########################################
Disk Utilization
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1       100G   60G   35G  64% /
tmpfs           2.0G     0  2.0G   0% /dev/shm
```

This is a common pattern in monitoring and system info scripts:
1. Print a separator line
2. Print a section title
3. Run the command that displays the information

## Running the Script

### Step 1: Check Permissions

Try running the script with its relative path first:

```bash
./firstscript.sh
```

You will get:

```
-bash: ./firstscript.sh: Permission denied
```

Check the file permissions:

```bash
ls -l firstscript.sh
```

Output:

```
-rw-r--r-- 1 root root 245 Jun 03 10:00 firstscript.sh
```

The file has **no execute permission** (`-rw-r--r--`). A script file must have execute permission before it can be run.

### Step 2: Add Execute Permission

```bash
chmod +x firstscript.sh
```

Verify:

```bash
ls -l firstscript.sh
```

```
-rwxr-xr-x 1 root root 245 Jun 03 10:00 firstscript.sh
```

The `x` bits confirm execute permission is now set for user, group, and others.

### Step 3: Execute the Script

**Using relative path** (from the same directory):

```bash
./firstscript.sh
```

**Using absolute path** (from anywhere):

```bash
/opt/scripts/firstscript.sh
```

Both work. The dot-slash (`./`) in the relative path means "in the current directory." When you give an absolute path, you can run the script from any directory on the system.

## Key Takeaways

| Concept | What to Remember |
|---------|-----------------|
| **Shebang (`#!/bin/bash`)** | Must be the first line; tells the OS which interpreter to use |
| **Comments (`#`)** | Ignored by the interpreter; write them to explain what your script does |
| **`echo`** | Prints text to the terminal; plain `echo` prints a blank line |
| **Execute permission** | Scripts need `chmod +x` before they can be run |
| **Relative path (`./`)** | Run the script from the directory it is in |
| **Absolute path** | Run the script from anywhere using its full path |
| **Script = commands in a file** | Any command that works in the terminal works in a script |
