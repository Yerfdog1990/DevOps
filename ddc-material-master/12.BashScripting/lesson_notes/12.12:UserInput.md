# Conditional Statements

## Overview

All scripts written so far execute commands in sequence from top to bottom — they cannot make decisions. `if` statements give scripts intelligence: they test a condition and execute different blocks of code depending on whether the test is true or false.

```
if condition is true → do this
if condition is false → do something else (or do nothing)
```

---

## Basic `if` Statement Syntax

```bash
if [ condition ]
then
    # commands to run if condition is true
fi
```

**Key syntax rules:**
- `if` opens the statement
- `fi` closes it (`fi` is `if` spelled backwards)
- `then` separates the condition from the commands
- The condition goes inside **square brackets** `[ ]`
- There **must be a space** after `[` and before `]`
- Commands between `then` and `fi` run only if the condition is true
- Any code after `fi` always runs regardless of the result

---

## The `if`/`else` Statement

```bash
if [ condition ]
then
    # runs if condition is TRUE
else
    # runs if condition is FALSE
fi
```

---

## Script 8 — Basic `if` Statement (`8_ifStatement.sh`)

```bash
#!/bin/bash

read -p "Enter a number: " NUM
echo

if [ $NUM -gt 100 ]
then
        echo "We have entered in IF block."
        sleep 3
        echo "Your number is greater than 100"
        echo
        date
fi

echo "Script execution completed!"
```

### What It Does

- Takes a number from the user with `read -p`
- Tests whether `$NUM` is greater than 100 using `-gt`
- If true: prints a message, pauses 3 seconds (`sleep 3`), prints the number message, and runs `date`
- If false: skips the entire `if` block
- Always prints "Script execution completed!" — this line is outside the `if` block

### Live Terminal Output

**Number greater than 100:**

```bash
[root@scriptbox scripts]# ./8_ifStatement.sh
Enter a number: 120

We have entered in IF block.
Your number is greater than 100

Fri Jun  5 07:40:14 PM UTC 2026
Script execution completed!
```

Condition was true (`120 > 100`) → entire `if` block executed.

**Number less than 100:**

```bash
[root@scriptbox scripts]# ./8_ifStatement.sh
Enter a number: 24

Script execution completed!
```

Condition was false (`24 > 100` is false) → `if` block skipped entirely. Only the line outside the `if` block ran.

## Using Command Line Arguments Instead of `read`

Instead of prompting the user inside the script, you can pass the value as an argument:

```bash
#!/bin/bash

if [ $1 -gt 100 ]
then
    echo "Hey, that's a large number."
    pwd
fi

date
```

Run it:

```bash
./if_example.sh 150
# Output:
# Hey, that's a large number.
# /opt/scripts
# Sun Oct 30 16:19:28 IST 2026
```

- `$1` is the first argument passed to the script
- `pwd` and `date` demonstrate that you can have as many commands as you like inside the `if` block
- `date` is **outside** the `if` block — it runs regardless of the condition result

## Comparison Operators

### Numeric Comparison Operators

| Operator | Meaning | Example |
|----------|---------|---------|
| `-eq` | Equal to | `[ $A -eq $B ]` |
| `-ne` | Not equal to | `[ $A -ne $B ]` |
| `-gt` | Greater than | `[ $A -gt 100 ]` |
| `-lt` | Less than | `[ $A -lt 100 ]` |
| `-ge` | Greater than or equal to | `[ $A -ge 100 ]` |
| `-le` | Less than or equal to | `[ $A -le 100 ]` |

> **Use numeric operators (`-eq`, `-gt`, etc.) for numbers** — not `==`, `>`, or `<`. Those are string or shell operators and behave differently.

### String Comparison Operators

| Operator | Meaning | Example |
|----------|---------|---------|
| `=` | Strings are equal | `[ "$A" = "$B" ]` |
| `!=` | Strings are not equal | `[ "$A" != "$B" ]` |
| `-z` | String is empty (zero length) | `[ -z "$A" ]` |
| `-n` | String is not empty | `[ -n "$A" ]` |

> **Important:** `=` does a **character-by-character string comparison**, while `-eq` does a **numeric comparison**. So `[ 001 = 1 ]` returns false (different strings), but `[ 001 -eq 1 ]` returns true (same number).

### File Test Operators

| Operator | Meaning |
|----------|---------|
| `-e FILE` | File exists (any type) |
| `-f FILE` | File exists and is a regular file |
| `-d FILE` | File exists and is a directory |
| `-r FILE` | File exists and is readable |
| `-w FILE` | File exists and is writable |
| `-x FILE` | File exists and is executable |
| `-s FILE` | File exists and is not empty (size > 0) |

### File Test Example

```bash
if [ -f /etc/hosts ]; then
    echo "File exists!"
else
    echo "Does not exist"
fi
```

## Multiple Conditions — `elif`

When you have more than two possible outcomes, use `elif` (else if) to test additional conditions. Each `elif` is checked in order — the first one that is true executes its block, and the rest are skipped. If none match, the `else` block runs as the fallback.

```bash
if [ condition1 ]
then
    # runs if condition1 is true
elif [ condition2 ]
then
    # runs if condition1 is false AND condition2 is true
elif [ condition3 ]
then
    # runs if condition1 and 2 are false AND condition3 is true
else
    # runs if ALL conditions above are false
fi
```

**Example — number comparison:**

```bash
#!/bin/bash

read -p "Enter a number: " NUM

if [ $NUM -gt 100 ]
then
    echo "Number is greater than 100"
elif [ $NUM -eq 100 ]
then
    echo "Number is exactly 100"
else
    echo "Number is less than 100"
fi
```

## Script 10 — `elif` with Network Interface Detection (`10_ifElifStatement.sh`)

This is a real-world example that uses `elif` to count active network interfaces and take different action depending on how many are found.

### The Problem

Running `ip addr show` lists all network interfaces. The loopback interface (`lo`) is not a real network adapter — it needs to be excluded. The remaining interfaces each contain the text `mtu` — counting occurrences of `mtu` (excluding the loopback line) gives the number of active network adapters.

```bash
[root@scriptbox scripts]# ip addr show | grep -v LOOPBACK | grep -ic mtu
2
```

**Breaking down the pipeline:**

| Step | Command | Purpose |
|------|---------|---------|
| 1 | `ip addr show` | Show all network interfaces |
| 2 | `grep -v LOOPBACK` | **Exclude** lines containing `LOOPBACK` — removes the loopback interface |
| 3 | `grep -ic mtu` | Count lines containing `mtu` — `-i` ignores case, `-c` returns count instead of the matching lines |

The result `2` tells us there are 2 active non-loopback network interfaces.

From the `ip addr show` output:
- `lo` — loopback (excluded by `-v LOOPBACK`)
- `enp0s3` — first real network interface ← counted
- `enp0s8` — second real network interface ← counted

### The Script

```bash
#!/bin/bash

value=$(ip addr show | grep -v LOOPBACK | grep -ic mtu)

if [ $value -eq 1 ]
then
        echo "1 active network interface found."
elif [ $value -gt 1 ]
then
        echo "Found multiple active network interfaces."
else
        echo "No active network interface found."
fi
```

### How the Logic Works

```
value = 2

Is value == 1?  →  No  →  check elif
Is value > 1?   →  Yes →  print "Found multiple active network interfaces."
(else block never reached)
```

Three possible outcomes:

| Value | Condition matched | Output |
|-------|------------------|--------|
| `0` | `else` | No active network interface found. |
| `1` | `if [ $value -eq 1 ]` | 1 active network interface found. |
| `2` or more | `elif [ $value -gt 1 ]` | Found multiple active network interfaces. |

### Live Terminal Output

```bash
[root@scriptbox scripts]# ./10_ifElifStatement.sh
Found multiple active network interfaces.
```

The script correctly identified 2 active interfaces and executed the `elif` block.

### Key Technique — Command Substitution in `if` Logic

```bash
value=$(ip addr show | grep -v LOOPBACK | grep -ic mtu)
```

This combines command substitution, piping, and filtering to produce a single number that drives the entire decision tree. This is the pattern for writing intelligent monitoring scripts — collect data, store it in a variable, make decisions based on it.

## Spacing — A Critical Syntax Requirement

Spacing inside `[ ]` is mandatory. Missing spaces cause syntax errors.

```bash
# Correct — spaces after [ and before ]:
if [ $NUM -gt 100 ]

# Wrong — no space after [:
if [$NUM -gt 100]
# Error: [120: command not found

# Wrong — missing spaces around operator:
if [ $NUM-gt 100 ]
# Error: unexpected results
```

---

## Indentation — Optional but Recommended

In Bash, indentation is not required (unlike Python). Commands inside `if`/`then`/`else`/`fi` work with or without indentation. However, indenting makes scripts much more readable — especially as they grow in complexity:

```bash
# Hard to read without indentation:
if [ $NUM -gt 100 ]
then
echo "greater"
date
fi

# Easy to read with indentation:
if [ $NUM -gt 100 ]
then
    echo "greater"
    date
fi
```

## `sleep` — Pause Execution

Used in the example scripts, `sleep` pauses execution for a specified number of seconds:

```bash
sleep 3      # pause for 3 seconds
sleep 0.5    # pause for half a second
```

Useful for adding a delay between steps, simulating waiting, or giving the user time to read a message before the script continues.

## Summary

| Concept | Syntax |
|---------|--------|
| Basic `if` | `if [ condition ]; then ... fi` |
| `if`/`else` | `if [ condition ]; then ... else ... fi` |
| `if`/`elif`/`else` | `if [ c1 ]; then ... elif [ c2 ]; then ... else ... fi` |
| Numeric greater than | `[ $A -gt $B ]` |
| Numeric equal | `[ $A -eq $B ]` |
| Numeric less than | `[ $A -lt $B ]` |
| String equal | `[ "$A" = "$B" ]` |
| String not equal | `[ "$A" != "$B" ]` |
| File exists | `[ -f /path/to/file ]` |
| Directory exists | `[ -d /path/to/dir ]` |
| Closing keyword | `fi` |
| Required spacing | Spaces inside `[ ]` are mandatory |
