# Introduction to Bash Scripting

## Why Learn Bash Scripting?

Bash scripting is one of the most practical skills in this course — especially if you are new to scripting or programming. Before diving in, two important mindset points:

## What Is a Bash Script?

A **bash script** is a plain text file containing a sequence of commands that the Bash program executes line by line. Instead of manually typing commands one at a time into the terminal, you put them all in a file and let the system execute the file for you.

```bash
# Instead of running these one at a time:
cd /var/log
mkdir backup
cp *.log backup/
echo "Backup complete"

# You put them all in a file: backup.sh
# And run: bash backup.sh
```

The word **bash** comes from **Bourne-Again SHell** — a specific shell program available on virtually every Linux and Unix system. When we say "bash scripting" we mean scripts written specifically for the bash shell, as opposed to sh, ksh, zsh, or other shells.

---

## What Problem Does Scripting Solve?

System administrators perform many tasks repeatedly — daily, weekly, or on a schedule:

- Regular OS patching
- Taking backups
- Checking disk usage
- Restarting services
- Monitoring logs
- Cleaning up old files

These are sometimes called **robotic tasks** — repetitive, predictable, and time-consuming when done manually. Bash scripting automates them. You write the commands once, save them in a file, and the system can execute them on demand or on a schedule without human intervention.

## Shell vs Bash — What Is the Difference?

The terms "shell" and "bash" are often used interchangeably, but there is a distinction:

| Term | Meaning |
|------|---------|
| **Shell** | A broad term for any program that provides a command-line interface to interact with the operating system |
| **Bash** | A specific type of shell — the most widely used one on Linux systems |

There are several shells available on Linux and Unix:

| Shell | Name | Notes |
|-------|------|-------|
| `sh` | Bourne Shell | The original Unix shell, developed by Stephen Bourne |
| `bash` | Bourne-Again SHell | Improved version of `sh`; default shell on most Linux distributions |
| `ksh` | Korn Shell | Combines features of `sh` and `csh`; advanced scripting capabilities |
| `csh` | C Shell | C-like syntax; popular for interactive use |
| `zsh` | Z Shell | Extended version of bash with additional features; default on macOS |

When someone says "shell scripting," they could mean any shell. When they say "bash scripting," they mean specifically the bash shell.

You can check which shell you are currently using:

```bash
ps
```

Or:

```bash
echo $SHELL
```

## The Shell Prompt

When you open a terminal, you see a **shell prompt** — the shell waiting for your input:

```bash
zaira@hostname:~$
```

| Prompt Character | Meaning |
|-----------------|---------|
| `$` | Regular user — waiting for a command |
| `#` | Root user (administrator) — elevated privileges |

```bash
# Regular user prompt:
user@hostname:~$

# Root user prompt:
[root@host ~]#
```

## How a Bash Script Works

A bash script is executed **line by line, top to bottom**. The bash program reads each line, interprets it as a command, and executes it. If a line fails and the script is not configured to stop on errors, it moves to the next line.

### The Shebang Line

Every bash script should start with a **shebang** (`#!`) followed by the path to the bash interpreter:

```bash
#!/bin/bash
```

This tells the operating system: *use the bash program at `/bin/bash` to execute this file.* Without it, the system may use a different shell to run the script, which can cause unexpected behaviour.

### A Simple Example

```bash
#!/bin/bash
echo "Starting backup..."
cd /var/log
mkdir -p /backup/logs
cp *.log /backup/logs/
echo "Backup complete."
```

Save this as `backup.sh`, make it executable, and run it:

```bash
chmod +x backup.sh
./backup.sh
```

Every time you run `./backup.sh`, all those commands execute in sequence automatically.

## Tips for Success

- **Write every script yourself** — do not copy-paste from resources. Typing it forces you to read every character.
- **When you get an error, look for typos first** — a missing space, wrong quotation mark, or misspelled variable name causes the majority of script failures.
- **Compare with the reference script** — if you cannot find the error, open the reference script side by side and compare line by line.
- **Keep practising** — scripting is a skill built through repetition. By the end of this session, writing scripts will feel natural.
- **Comments are your friend** — use `#` to add notes explaining what each section of your script does. It makes debugging and revisiting scripts much easier.

```bash
#!/bin/bash
# This script performs a log backup
# Author: Your Name
# Date: 2026

echo "Starting log backup..."   # Inform the user
cd /var/log                     # Move to log directory
cp *.log /backup/               # Copy all log files
echo "Done."
```
