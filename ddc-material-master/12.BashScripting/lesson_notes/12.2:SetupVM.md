# Setting Up the Virtual Machines 

## Overview

This session uses a dedicated set of virtual machines for practising and running bash scripts. There are four VMs defined in the Vagrantfile — `scriptbox`, `web01`, `web02`, and `web03`. For now, only `scriptbox` is needed. The web VMs will be used later when scripts are pushed to remote machines.

---

## The Vagrantfile

Download the Vagrantfile from the resources section and place it in a dedicated directory for this bash scripting session. The file defines four VMs:

```ruby
Vagrant.configure("2") do |config|

  config.vm.define "scriptbox" do |scriptbox|
    scriptbox.vm.box = "eurolinux-vagrant/centos-stream-9"
    scriptbox.vm.network "private_network", ip: "192.168.10.12"
    scriptbox.vm.hostname = "scriptbox"
    scriptbox.vm.provider "virtualbox" do |vb|
      vb.memory = "1024"
    end
  end

  config.vm.define "web01" do |web01|
    web01.vm.box = "eurolinux-vagrant/centos-stream-9"
    web01.vm.network "private_network", ip: "192.168.10.13"
    web01.vm.hostname = "web01"
  end

  config.vm.define "web02" do |web02|
    web02.vm.box = "eurolinux-vagrant/centos-stream-9"
    web02.vm.network "private_network", ip: "192.168.10.14"
    web02.vm.hostname = "web02"
  end

  config.vm.define "web03" do |web03|
    web03.vm.box = "ubuntu/bionic64"
    web03.vm.network "private_network", ip: "192.168.10.15"
    web03.vm.hostname = "web03"
  end

end
```

### VM Reference Table

| VM | Box (OS) | IP Address | Purpose |
|----|----------|------------|---------|
| `scriptbox` | CentOS Stream 9 | `192.168.10.12` | Main scripting VM — write and run all scripts here |
| `web01` | CentOS Stream 9 | `192.168.10.13` | Target VM — used later when pushing scripts remotely |
| `web02` | CentOS Stream 9 | `192.168.10.14` | Target VM — used later when pushing scripts remotely |
| `web03` | Ubuntu Bionic 64 | `192.168.10.15` | Target VM — Ubuntu variant for cross-distro scripting |

> All scripts in the first part of the session are written and executed on `scriptbox`. The web VMs come into play later when you practice deploying scripts to remote machines.

## Setup Steps

### 1. Create a Directory for This Session

Create a dedicated folder for the bash scripting session and place the Vagrantfile inside it. Keep it separate from other Vagrant projects.

```bash
# Example on Windows (Git Bash):
mkdir /d/bash-scripts
cp ~/Downloads/Vagrantfile /d/bash-scripts/
cd /d/bash-scripts/
```

### 2. Review the Vagrantfile

Open the Vagrantfile to confirm the VM definitions:

```bash
vim Vagrantfile
# or use Notepad++ on Windows
```

You will see the four VM definitions. For now, focus on `scriptbox`.

### 3. Bring Up Only `scriptbox`

Do **not** run `vagrant up` by itself — that would bring up all four VMs at once, which is unnecessary and resource-heavy. Bring up only `scriptbox`:

```bash
vagrant up scriptbox
```

This boots only the `scriptbox` VM. The web VMs remain off.

### 4. Log Into `scriptbox`

```bash
vagrant ssh scriptbox
```

### 5. Set the Hostname

The hostname identifies which machine you are connected to in the shell prompt — important when you are logged into multiple VMs simultaneously. Set it now:

```bash
sudo vi /etc/hostname
```

Replace the existing content with:

```
scriptbox
```

Save and exit (`:wq`). Then apply the hostname immediately without rebooting:

```bash
sudo hostname scriptbox
```

Log out and log back in:

```bash
exit
vagrant ssh scriptbox
```

Your prompt should now show `scriptbox`:

```
[vagrant@scriptbox ~]$
```

### 6. Switch to Root User

All scripts in this session are written and run as root:

```bash
sudo -i
```

Your prompt changes to:

```
[root@scriptbox ~]#
```

You are now ready to start writing bash scripts.

## Notes on the Web VMs

You do not need `web01`, `web02`, or `web03` yet. They will be used later in the session when you write scripts that connect to and configure remote machines over SSH. When that time comes, bring them up individually:

```bash
vagrant up web01
vagrant up web02
vagrant up web03
```

Their hostnames are already set in the Vagrantfile (`vm.hostname`), so no manual hostname configuration is needed for those machines.

The same hostname-setting process should be repeated when you log into each web VM, so you can clearly identify which machine your terminal is connected to at any point.
