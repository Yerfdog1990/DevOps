# Single and Double Quotes

## Overview

Bash uses two types of quotes: **single quotes** (`'`) and **double quotes** (`"`). Most of the time they look the same, but they behave very differently when your string contains variables or special characters. Understanding the difference is essential for writing scripts that produce the output you actually intend.

---

## The Problem Quotes Solve

Without quotes, Bash treats spaces as separators between items. This means multi-word values break:

```bash
myvar=Hello World
# Output: World: command not found
```

Bash interprets `Hello` as the variable value and tries to run `World` as a command. Quotes tell Bash to treat everything between them as a single item.

---

## Single Quotes `'...'`

Single quotes treat **every character literally**. No substitution of any kind occurs inside single quotes — variables are not expanded, special characters lose their meaning, and what you type is exactly what gets printed.

```bash
NAME='Yerfdog'
SKILL="DevOps"

echo 'My name is $NAME and I have a skill in $SKILL'
# Output: My name is $NAME and I have a skill in $SKILL
```

The `$NAME` and `$SKILL` are printed as plain text — not replaced with their values. The `$` has no special meaning inside single quotes.

---

## Double Quotes `"..."`

Double quotes allow **variable substitution** (and command substitution). Variables are expanded to their values; the string is treated as a single item but special characters like `$` retain their meaning.

```bash
NAME='Yerfdog'
SKILL="DevOps"

echo "My name is $NAME and I have a skill in $SKILL"
# Output: My name is Yerfdog and I have a skill in DevOps
```

`$NAME` and `$SKILL` are replaced with their values because they are inside double quotes.

---

## Side-by-Side Comparison

```bash
SKILL="DevOps"

echo $SKILL           # Output: DevOps
echo "$SKILL"         # Output: DevOps
echo '$SKILL'         # Output: $SKILL  ← literal, not expanded
```

| Quote Type | Variable `$VAR` | Output |
|------------|-----------------|--------|
| None | `echo $SKILL` | `DevOps` |
| Double quotes | `echo "$SKILL"` | `DevOps` |
| Single quotes | `echo '$SKILL'` | `$SKILL` |

---

## The Problem with `$` as a Literal Character

`$` is a **special character** in Bash — it signals that what follows is a variable name or argument number. This causes unexpected behaviour when you want to print a dollar sign as part of text.

### The Problem

```bash
NAME='Yerfdog'
SKILL="DevOps"

echo "My name is $NAME and with my skills in $SKILL and hope to get a salary of $120000 per annum as a junior"
# Output: My name is Yerfdog and with my skills in DevOps and hope to get a salary of 20000 per annum as a junior
```

The `$120000` was interpreted as `$12` (the 12th argument, which is empty) followed by `0000`. Since `$12` has no value, it disappears — the output shows `20000` instead of `$120000`.

### Attempted Fix with Single Quotes — Doesn't Work Either

```bash
echo 'My name is $NAME and with my skills in $SKILL and hope to get a salary of $120000 per annum as a junior'
# Output: My name is $NAME and with my skills in $SKILL and hope to get a salary of $120000 per annum as a junior
```

Now the dollar sign in `$120000` is preserved, but `$NAME` and `$SKILL` are also printed literally — their values are lost.

### The Correct Solution — Backslash Escape

Use **double quotes** (so variables expand) and prefix the literal `$` with a **backslash** (`\`):

```bash
echo "My name is $NAME and with my skills in $SKILL and hope to get a salary of \$120000 per annum as a junior"
# Output: My name is Yerfdog and with my skills in DevOps and hope to get a salary of $120000 per annum as a junior
```

The `\$` tells Bash: *the next character (`$`) is not special — print it literally.* The variables `$NAME` and `$SKILL` still expand normally because they are not preceded by a backslash.

---

## The Backslash — Escape Character

A **backslash** (`\`) removes the special meaning of the character immediately following it. This is called **escaping** a character.

```bash
echo "Cost: \$50"       # Output: Cost: $50
echo "Tab\there"        # Output: Tab    here  (actual tab)
echo "Line1\nLine2"     # Output: Line1\nLine2  (without -e flag, \n not interpreted)
echo -e "Line1\nLine2"  # Output:
                        # Line1
                        # Line2
```

Common characters that need escaping inside double quotes:

| Character | Meaning in Bash | Escaped version | Prints |
|-----------|----------------|-----------------|--------|
| `$` | Variable / argument | `\$` | `$` |
| `"` | End of double-quoted string | `\"` | `"` |
| `\` | Escape character itself | `\\` | `\` |
| `` ` `` | Command substitution (backtick) | `` \` `` | `` ` `` |

## Storing Multi-Word Values in Variables

```bash
# Single word — quotes optional
SKILL=DevOps
echo $SKILL         # Output: DevOps

# Multi-word — quotes required
DESCRIPTION="Senior DevOps Engineer"
echo $DESCRIPTION   # Output: Senior DevOps Engineer

# Single quotes — no variable expansion inside the value
GREETING='Hello $USER'
echo $GREETING      # Output: Hello $USER   ← $USER not expanded

# Double quotes — variable expansion inside the value
GREETING="Hello $USER"
echo $GREETING      # Output: Hello root    ← $USER expanded at assignment time
```

## Decision Guide — Which Quotes to Use

| Situation | Use | Example |
|-----------|-----|---------|
| Simple single-word value | No quotes needed | `VAR=hello` |
| Multi-word value | Either quote type | `VAR="hello world"` |
| Value contains variables | Double quotes | `VAR="Hello $USER"` |
| Value must be completely literal | Single quotes | `VAR='$HOME is not expanded'` |
| Mix: variables + literal `$` | Double quotes + backslash | `echo "$NAME earns \$120000"` |
| Value contains a single quote | Double quotes | `VAR="it's working"` |
| Value contains a double quote | Single quotes or backslash | `VAR='say "hello"'` or `VAR="say \"hello\""` |

---

## Summary

| Quote Type | Variable Expansion | Special Characters | Use When |
|------------|-------------------|-------------------|----------|
| **Double `""`** | Yes — `$VAR` is replaced with its value | `$`, `` ` ``, `\`, `"` retain meaning | You need variables to expand |
| **Single `''`** | No — everything is literal | All characters printed as-is | You need completely literal output |
| **Backslash `\`** | N/A — escapes the next character only | Removes special meaning of next character | You need one literal special character inside double quotes |
