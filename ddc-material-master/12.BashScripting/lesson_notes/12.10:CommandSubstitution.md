# Command Substitution

## What Is Command Substitution?

Command substitution captures the **output of a command** and stores it directly into a variable. Without command substitution, a variable can only hold text you type — with it, a variable can hold the live output of any Linux command, making your scripts dynamic and intelligent.

This is one of the most important concepts for writing useful scripts.

---

## Two Syntaxes

There are two ways to perform command substitution:

### 1. Backticks `` `command` ``

```bash
UPT=`uptime`
echo $UPT
# Output: 13:22:08 up 15 min, 1 user, load average: 0.00, 0.02, 0.00
```

### 2. Dollar-Parentheses `$(command)` — Preferred

```bash
UPTI=$(uptime)
echo $UPTI
# Output: 13:23:20 up 16 min, 1 user, load average: 0.00, 0.02, 0.00
```

Both do the same thing. **`$(...)` is the modern, preferred form** because:
- It is easier to read
- It can be nested: `$(command1 $(command2))`
- Backticks can be confused with single quotes at a glance

---

## The Difference: Storing a Command Name vs Its Output

This distinction is crucial:

```bash
# Storing the text "uptime" — not the output:
UP="uptime"
echo $UP
# Output: uptime    ← just the word

# Storing the OUTPUT of uptime:
UPT=$(uptime)
echo $UPT
# Output: 13:22:08 up 15 min, 1 user, load average: 0.00, 0.02, 0.00
```

Double or single quotes store the text as-is. `$(...)` or backticks execute the command and store its output.

## Combining with Pipes — Filtering Command Output

Command substitution becomes powerful when combined with pipes to extract exactly the data you need. The pattern is:

```
variable=$(command | filter | extract_field)
```

### Example: Extracting Free RAM

**Step 1 — `free -m`** — show memory usage in megabytes:

```bash
free -m
```

```text
               total        used        free      shared  buff/cache   available
Mem:            7825        2150        1024         120        4650        5200
Swap:           2047           0        2047
```

**Step 2 — `grep Mem`** — filter to just the memory line:

```bash
free -m | grep Mem
```

```text
Mem:            7825        2150        1024         120        4650        5200
```

**Step 3 — `awk '{print $4}'`** — extract the 4th field (free memory):

```bash
free -m | grep Mem | awk '{print $4}'
```

`awk` splits the line by whitespace and numbers each field:

```text
$1 = Mem:
$2 = 7825   (total)
$3 = 2150   (used)
$4 = 1024   (free)     ← this is what we want
$5 = 120    (shared)
$6 = 4650   (buff/cache)
$7 = 5200   (available)
```

Output: `1024`

## Understanding `awk`

`awk` is a full text-processing programming language, not just a simple filter like `grep` or `cat`. It requires you to tell it what to do — it does not have a default action.

### The General Pattern

```bash
awk 'pattern { action }'
```

- **pattern** — optional: only process lines that match this condition
- **action** — what to do with each matching line (must be in curly braces `{}`)

### Why `awk` Always Needs a Program

Unlike `grep` (which knows its job is to search for a pattern), `awk` could do many things: print columns, sum numbers, filter rows, reformat text, calculate averages, generate reports. So it always needs an explicit program to know what to do.

Running `awk` with no program just prints its usage message.

### Common `awk` Examples

```bash
# Print every line (equivalent to cat)
echo "John went to school on Monday" | awk '{print}'
# Output: John went to school on Monday

# Print just the first field
echo "John went to school on Monday" | awk '{print $1}'
# Output: John

# Print the second field
echo "John went to school on Monday" | awk '{print $2}'
# Output: went

# Print lines containing "school"
echo "John went to school on Monday" | awk '/school/ {print}'
# Output: John went to school on Monday

# $0 means the entire line
echo "John went to school on Monday" | awk '{print $0}'
# Output: John went to school on Monday
```

### Using `awk` with a Pattern Match (no `grep` needed)

Instead of piping through `grep` first, `awk` can filter and extract in one step:

```bash
# grep then awk (two steps):
free -m | grep Mem | awk '{print $4}'

# awk with pattern match (one step — preferred):
free -m | awk '/Mem:/ {print $4}'
```

`/Mem:/` is a regular expression pattern — `awk` only processes lines that contain `Mem:`, then prints field 4.

### Why Single Quotes Are Required for `awk`

`awk` uses `$1`, `$2`, `$NF` etc. to refer to fields — the same `$` syntax that Bash uses for variables. If you use double quotes, Bash will try to expand `$1` as a shell variable **before** `awk` ever sees it:

```bash
# Wrong — Bash expands $1 as a shell positional argument first:
echo "John went to school" | awk "{print $1}"
# Result: awk "{print }"   ← $1 was replaced with empty string

# Correct — single quotes protect $1 so awk receives it unchanged:
echo "John went to school" | awk '{print $1}'
# Output: John
```

**Rule:** Always use single quotes around `awk` programs so that `$1`, `$2`, etc. reach `awk` unchanged.

### What Happens with Backticks Around the `awk` Program

Backticks mean **command substitution** in Bash — the contents are executed as a shell command:

```bash
# Wrong — Bash tries to run {print} as a shell command:
echo "John went to school on Monday" | awk `{print}`
# Error: -bash: {print}: command not found
```

Bash sees `` `{print}` `` and tries to execute `{print}` as a command. Since no such command exists, it fails with "command not found" and `awk` receives no program — displaying its usage message.

### `awk` Quote Syntax Summary

| Syntax | What happens | Works? |
|--------|-------------|--------|
| `awk '{print $1}'` | Shell passes `{print $1}` literally to awk | ✅ Correct |
| `awk "{print $1}"` | Shell expands `$1` as a shell variable first | ⚠️ Usually wrong |
| `awk "{print}"` | No `$` variables — shell and awk agree | ✅ Works but not recommended |
| `` awk `{print}` `` | Shell tries to run `{print}` as a command | ❌ Always fails |

**Standard practice:** Always use **single quotes** with `awk` programs.

**Step 4 — Store in a variable using command substitution:**

```bash
FREE_RAM=$(free -m | grep Mem | awk '{print $4}')
echo "Free RAM is $FREE_RAM MB."
# Output: Free RAM is 1024 MB.
```

---

## Common Mistake — Invalid Syntax

This is **not** valid command substitution:

```bash
FREE_RAM= free -m | grep Mem | awk '{print $4}'
```

Bash interprets `FREE_RAM=` as setting an **empty environment variable** for the `free` command — not storing the output. The result is unexpected behaviour.

**Always use `$(...)` or backticks:**

```bash
# Correct:
FREE_RAM=$(free -m | grep Mem | awk '{print $4}')
```

## More Examples

### Current logged-in users

```bash
CURRENT_USER=$(who)
echo $CURRENT_USER
```

### Count files in a directory

```bash
FILE_COUNT=$(ls /etc | wc -l)
echo "There are $FILE_COUNT entries in /etc"
# Output: There are 249 entries in /etc
```

### Today's date

```bash
TODAY=$(date +%Y-%m-%d)
echo "Today is $TODAY"
# Output: Today is 2026-06-03
```

### Files in current directory

```bash
FILES=$(ls)
echo $FILES
# Output: 1_firstscript.sh  2_websetup.sh  3_vars_websetup.sh  ...
```

> **Note:** When a multi-line command output is stored in a variable, newlines are removed and all output is placed on a single line.

## System Health Script — `6_command_subs.sh`

This script uses command substitution to collect live system information and print a health summary. It is a practical demonstration of combining system variables, command substitution, and output filtering.

### The Script

```bash
#!/bin/bash

echo "Welcome $USER on $HOSTNAME."
echo "########################################################"

FREERAM=$(free -m | grep Mem | awk '{print $4}')
LOAD=`uptime | awk '{print $9}'`
ROOTFREE=$(df -h | grep '/dev/sda1' | awk '{print $4}')

echo "########################################################"
echo "Available free RAM is $FREERAM MB"
echo "########################################################"
echo "Current Load Average $LOAD"
echo "########################################################"
echo "Free ROOT partition size is $ROOTFREE"
```

### What Each Variable Does

**`FREERAM`**

```bash
FREERAM=$(free -m | grep Mem | awk '{print $4}')
```

Extracts the free (unused) memory in MB from the `free -m` output.

**`LOAD`**

```bash
LOAD=`uptime | awk '{print $9}'`
```

Extracts the 1-minute load average from `uptime`. Uses backtick syntax — both forms work identically.

**`ROOTFREE`**

```bash
ROOTFREE=$(df -h | grep '/dev/sda1' | awk '{print $4}')
```

Finds the available disk space on the root partition `/dev/sda1`. `df -h` shows disk usage in human-readable format; `grep` filters to the right partition; `awk '{print $4}'` extracts the available column.

### Example Output

```text
Welcome root on scriptbox.
########################################################
########################################################
Available free RAM is 590 MB
########################################################
Current Load Average 0.01,
########################################################
Free ROOT partition size is 18G
```

## Understanding `awk` — The Text Processing Tool

`awk` is used throughout command substitution examples to extract specific fields from command output. Unlike `grep` or `cat`, which can do something useful with no instructions, `awk` is a **programming language** — it always requires a program telling it what to do with the input.

### Basic `awk` Syntax

```bash
awk 'pattern { action }'
```

- **pattern** — optional condition; if it matches, the action runs
- **action** — what to do with the matching line (e.g. print a field)

### The Smallest Valid `awk` Program

```bash
echo "John went to school on Monday" | awk '{print}'
# Output: John went to school on Monday
```

`{print}` alone prints the entire line (equivalent to `{print $0}`). Without any program, `awk` does not know what to do and displays a usage message.

### Field References — `$1`, `$2`, `$N`

`awk` automatically splits each line by whitespace and numbers each word as a field:

```bash
echo "John went to school on Monday" | awk '{print $1}'
# Output: John

echo "John went to school on Monday" | awk '{print $2}'
# Output: went
```

Applied to `free -m` output:

```text
Mem:   7825   2150   1024   120   4650   5200
$1     $2     $3     $4     $5    $6     $7
```

So `awk '{print $4}'` extracts the 4th field — the free memory value.

### Pattern Matching in `awk`

`awk` can filter lines by a pattern before applying the action:

```bash
free -m | awk '/Mem:/ {print $4}'
```

`/Mem:/` is a **regex pattern** — only lines containing `Mem:` are processed. This replaces the need for a separate `grep` step:

```bash
# Two-step (older style):
free -m | grep Mem | awk '{print $4}'

# One-step (modern style):
free -m | awk '/Mem:/ {print $4}'
```

### Custom Field Separators — `-F`

By default `awk` splits on whitespace. The `-F` option sets a custom delimiter:

```bash
LOAD=$(uptime | awk -F'load average: ' '{print $2}')
```

This splits the `uptime` output on the string `load average: ` and prints the second part — the actual load values. This is more reliable than using a fixed field number like `$9`, which can vary.

Another common use:

```bash
awk -F: '{print $1}' /etc/passwd
```

Splits `/etc/passwd` on `:` and prints the first field (usernames).

---

### Quote Rules for `awk`

This is a common source of errors. `awk` programs must be quoted correctly to prevent the shell from interfering.

| Syntax | What the shell does | Works? |
|--------|---------------------|--------|
| `awk '{print $1}'` | Passes `{print $1}` literally to awk | ✅ Correct |
| `awk "{print $1}"` | Shell expands `$1` as a shell variable first | ⚠️ Risky |
| `awk {print}` | Shell tries to run `{print}` as a command | ❌ Fails |
| `` awk `{print}` `` | Backticks: shell tries to run `{print}` as a command | ❌ Fails |

**Always use single quotes for `awk` programs.** This is because `awk` uses `$1`, `$2`, `$NF` etc. as its own field variables. Inside double quotes, Bash sees `$1` first and tries to expand it as a shell argument — `awk` never receives the intended program.

```bash
# Shell expands $1 before awk runs — likely produces wrong result:
echo "John went to school" | awk "{print $1}"

# Shell leaves $1 untouched — awk receives '{print $1}' correctly:
echo "John went to school" | awk '{print $1}'
# Output: John
```

**What happens with no quotes or backticks:**

```bash
echo "John went to school on Monday" | awk {print}
# -bash: {print}: command not found
# (awk usage message printed)
```

Bash sees `{print}` without quotes and tries to run it as a shell command. It fails, and `awk` is left with no program.

```bash
awk `{print}`
# -bash: {print}: command not found
```

Backticks trigger **command substitution** — Bash tries to execute `{print}` as a shell command. Compare with valid backtick use:

```bash
echo `date`     # Bash runs 'date' and substitutes its output — works
echo `{print}`  # Bash tries to run '{print}' — no such command
```

### `awk` Reference Summary

| Command | Output |
|---------|--------|
| `awk '{print}'` | Print every line |
| `awk '{print $1}'` | Print first field of each line |
| `awk '{print $4}'` | Print fourth field |
| `awk '/Mem:/ {print $4}'` | Print fourth field of lines matching `Mem:` |
| `awk -F: '{print $1}'` | Use `:` as separator, print first field |
| `awk -F'load average: ' '{print $2}'` | Split on string, print second part |
| `awk '$1=="Mem:" {print $4}'` | Match exact first field value |

## Modernised Version

The script above uses `grep` + `awk` in two steps. A cleaner, more efficient approach uses `awk` alone with a pattern match, and uses `$(...)` consistently:

```bash
#!/bin/bash

echo "Welcome $USER on $HOSTNAME."
echo "########################################################"

FREERAM=$(free -m | awk '/Mem:/ {print $4}')
LOAD=$(uptime | awk -F'load average: ' '{print $2}')
ROOTFREE=$(df -h | awk '$1=="/dev/sda1" {print $4}')

echo "########################################################"
echo "Available free RAM is $FREERAM MB"
echo "########################################################"
echo "Current Load Average $LOAD"
echo "########################################################"
echo "Free ROOT partition size is $ROOTFREE"
```

**What changed and why:**

| Original | Modern | Reason |
|----------|--------|--------|
| `free -m \| grep Mem \| awk '{print $4}'` | `free -m \| awk '/Mem:/ {print $4}'` | Removes the extra `grep` step — `awk` can match patterns directly |
| `` uptime \| awk '{print $9}' `` | `uptime \| awk -F'load average: ' '{print $2}'` | Field position `$9` can vary; splitting on `load average:` is more reliable |
| `df -h \| grep '/dev/sda1' \| awk '{print $4}'` | `df -h \| awk '$1=="/dev/sda1" {print $4}'` | Removes the extra `grep` step |
| Backtick `` ` `` | `$(...)` | Modern preferred syntax — more readable and supports nesting |

---

## Summary

| Method | Syntax | Notes |
|--------|--------|-------|
| Backtick | `` VAR=`command` `` | Works but looks like single quotes; older style |
| Dollar-parentheses | `VAR=$(command)` | Preferred; cleaner; supports nesting |
| With pipes | `VAR=$(cmd \| grep x \| awk '{print $N}')` | Filter output before storing |
| Store text (not output) | `VAR="command"` | Stores the word "command", not its output |

**Key rule:** If you want the **output** of a command in a variable, use `$(...)`. If you want the **text** of a command name, use quotes.
