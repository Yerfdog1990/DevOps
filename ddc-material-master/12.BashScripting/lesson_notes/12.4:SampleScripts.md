# Website Setup Automation Script

## Overview

Instead of manually running commands to set up a web server and deploy a website, we write a script that does it all in one execution. This is the core value of scripting: record the commands once, run them whenever needed.

The use case here is setting up an Apache (`httpd`) web server and deploying a free HTML template downloaded from [tooplate.com](https://www.tooplate.com). This is the same process covered in the Linux section — now automated with a bash script.

---

## Getting the Template Download URL

Before writing the script you need the direct download URL of the zip file from tooplate.com:

1. Go to [tooplate.com](https://www.tooplate.com) and pick a template (e.g. *Health Center* — template `2098_health`)
2. Open browser developer tools: press `F12` → go to the **Network** tab
3. Click the **Download** button on the template page
4. Watch the Network tab — you will see a `.zip` request appear
5. Copy that URL (e.g. `https://www.tooplate.com/zip-templates/2098_health.zip`)

Use this URL in the `wget` command in the script.

## The Complete Script

```bash
#!/bin/bash

# Installing Dependencies
echo "#############################################"
echo "Installing packages."
echo "#############################################"
sudo yum install wget unzip httpd -y > /dev/null
echo

# Start & Enable Service
echo "#############################################"
echo "Start & Enable HTTPD Service"
echo "#############################################"
sudo systemctl start httpd
sudo systemctl enable httpd
echo

# Creating Temp Directory & Deploying Artifact
echo "#############################################"
echo "Starting Artifact Deployment"
echo "#############################################"
mkdir -p /tmp/webfiles
cd /tmp/webfiles
echo

wget https://www.tooplate.com/zip-templates/2098_health.zip > /dev/null
unzip 2098_health.zip > /dev/null
sudo cp -r 2098_health/* /var/www/html/
echo

# Bounce Service
echo "#############################################"
echo "Restarting HTTPD service"
echo "#############################################"
systemctl restart httpd
echo

# Clean Up
echo "#############################################"
echo "Removing Temporary Files"
echo "#############################################"
rm -rf /tmp/webfiles
echo

echo "#############################################"
echo "Deployment Complete. Service Status:"
echo "#############################################"
sudo systemctl status httpd

echo
echo "Contents of /var/www/html:"
ls /var/www/html/
```

## Line-by-Line Explanation

### Shebang

```bash
#!/bin/bash
```

Called the **shebang**. Tells Linux to execute the script using the Bash shell located at `/bin/bash`. Must always be the first line of any bash script.

---

### Section 1 — Installing Dependencies

```bash
# Installing Dependencies
```

A comment for documentation — ignored by Bash entirely. It tells anyone reading the script that this section handles package installation.

```bash
echo "#############################################"
echo "Installing packages."
echo "#############################################"
```

Prints a visual separator and a heading so the user watching the script run knows what stage is being executed:

```text
#############################################
Installing packages.
#############################################
```

```bash
sudo yum install wget unzip httpd -y > /dev/null
```

| Part | Meaning |
|------|---------|
| `sudo` | Runs the command with administrator privileges |
| `yum` | Package manager for CentOS, RHEL, and Amazon Linux |
| `install` | Tells yum to install the named packages |
| `wget` | Tool for downloading files from the internet |
| `unzip` | Tool for extracting ZIP archives |
| `httpd` | Apache web server |
| `-y` | Automatically answers "yes" to all prompts — without this the script would pause and wait for input |
| `> /dev/null` | Redirects all standard output to `/dev/null` (discards it) — keeps the terminal clean; errors still appear on screen |

```bash
echo
```

Prints a blank line for visual spacing in the output.

---

### Section 2 — Start & Enable HTTPD Service

```bash
# Start & Enable Service
```

Comment — marks the beginning of the service management section.

```bash
echo "#############################################"
echo "Start & Enable HTTPD Service"
echo "#############################################"
```

Displays:

```text
#############################################
Start & Enable HTTPD Service
#############################################
```

```bash
sudo systemctl start httpd
```

Starts the Apache web server immediately. The server begins listening for HTTP requests as soon as this command runs.

You can verify manually:

```bash
systemctl status httpd
```

```bash
sudo systemctl enable httpd
```

Enables Apache to start **automatically on every system boot**. Without this, Apache would stop after a reboot and the website would go offline.

Verify it is enabled:

```bash
systemctl is-enabled httpd
# Output: enabled
```

```bash
echo
```

Blank line spacing.

---

### Section 3 — Creating Temp Directory & Deploying Artifact

```bash
# Creating Temp Directory
echo "#############################################"
echo "Starting Artifact Deployment"
echo "#############################################"
```

An **artifact** in this context refers to the website files — the ZIP archive downloaded from tooplate.com that will be extracted and deployed to the server.

```bash
mkdir -p /tmp/webfiles
```

| Part | Meaning |
|------|---------|
| `mkdir` | Creates a directory |
| `-p` | Creates parent directories if they don't exist; if `/tmp/webfiles` already exists, no error is thrown |

Result: `/tmp/webfiles` is created as a clean temporary workspace.

```bash
cd /tmp/webfiles
```

Changes the working directory to `/tmp/webfiles`. Any files downloaded or extracted by subsequent commands will land in this folder.

```bash
echo
```

Blank line.

```bash
wget https://www.tooplate.com/zip-templates/2098_health.zip > /dev/null
```

- `wget` downloads files from the internet
- Downloads `2098_health.zip` into the current directory (`/tmp/webfiles`)
- Output is redirected to `/dev/null` to suppress the download progress bar

Directory state after this command:

```text
/tmp/webfiles
└── 2098_health.zip
```

```bash
unzip 2098_health.zip > /dev/null
```

Extracts the ZIP archive into a folder with the same name (without the `.zip` extension):

```text
/tmp/webfiles
├── 2098_health.zip
└── 2098_health/
    ├── index.html
    ├── css/
    ├── js/
    └── images/
```

Output is redirected to `/dev/null` to suppress the file listing.

> **Common mistake:** Using `2098_health.zip/` (with the `.zip` extension) in the next `cp` command. After unzipping, the folder is `2098_health/` — no `.zip`. Using the wrong name causes a "No such file or directory" error.

```bash
sudo cp -r 2098_health/* /var/www/html/
```

| Part | Meaning |
|------|---------|
| `cp` | Copy files |
| `-r` | Recursive — copies directories and all their contents |
| `2098_health/*` | Everything inside the extracted website directory (source) |
| `/var/www/html/` | Apache's default web root (destination) |

Result — Apache's web root now contains the website:

```text
/var/www/html/
├── index.html
├── css/
├── js/
└── images/
```

When a user visits `http://server-ip`, Apache serves files from `/var/www/html/` — so the website is now live.

```bash
echo
```

Blank line.

---

### Section 4 — Bounce Service (Restart Apache)

```bash
# Bounce Service
echo "#############################################"
echo "Restarting HTTPD service"
echo "#############################################"
systemctl restart httpd
echo
```

**"Bounce"** is a system administration term meaning **stop → start** (i.e. restart). After deploying new files, Apache must be restarted to:

- Reload the website files
- Re-read any configuration changes
- Begin serving the newly deployed content

Without restarting, users may still see old content cached by Apache.

---

### Section 5 — Clean Up

```bash
# Clean Up
echo "#############################################"
echo "Removing Temporary Files"
echo "#############################################"
rm -rf /tmp/webfiles
echo
```

```bash
rm -rf /tmp/webfiles
```

| Part | Meaning |
|------|---------|
| `rm` | Remove files or directories |
| `-r` | Recursive — removes directories and all their contents |
| `-f` | Force — no confirmation prompts |

Deletes the entire `/tmp/webfiles` directory including the ZIP file and extracted folder:

```text
/tmp/webfiles      ← deleted
├── 2098_health.zip
└── 2098_health/
```

This is safe because all the needed files have already been copied to `/var/www/html/`. Removing the temp files frees disk space.

---

### Section 6 — Final Verification

```bash
echo "#############################################"
echo "Deployment Complete. Service Status:"
echo "#############################################"
sudo systemctl status httpd

echo
echo "Contents of /var/www/html:"
ls /var/www/html/
```

Confirms two things at the end of the script:
1. Apache is `active (running)` — the service is healthy
2. The web root contains the deployed files — the deployment succeeded

## Complete Workflow

```text
1. Install required packages
   ├── wget
   ├── unzip
   └── httpd

2. Start Apache immediately
   └── systemctl start httpd

3. Enable Apache at boot
   └── systemctl enable httpd

4. Create temp working directory
   └── /tmp/webfiles

5. Download website template
   └── wget → 2098_health.zip

6. Extract template
   └── unzip → 2098_health/

7. Deploy website files to web root
   └── cp → /var/www/html/

8. Restart Apache (bounce service)
   └── systemctl restart httpd

9. Remove temporary files
   └── rm -rf /tmp/webfiles

10. Verify service and web root
    ├── systemctl status httpd
    └── ls /var/www/html/
```

## Making the Script Executable and Running It

Save the script as `websetup.sh` in `/opt/scripts/`:

```bash
chmod +x /opt/scripts/websetup.sh
```

Run using the absolute path:

```bash
/opt/scripts/websetup.sh
```

Or from within the directory:

```bash
cd /opt/scripts
./websetup.sh
```

## Output Redirection — Why `>` and Not `> /dev/null 2>&1`

Three commands in the script use `> /dev/null`:

```bash
yum install ... > /dev/null
wget ...        > /dev/null
unzip ...       > /dev/null
```

| Redirection | What it does |
|-------------|-------------|
| `> /dev/null` | Discards standard output only; **errors still appear on screen** |
| `> /dev/null 2>&1` | Discards both standard output AND errors — hides everything |

Using `>` alone is intentional: installation progress, download progress bars, and file listing from unzip are noise the user does not need to see. But if something actually goes wrong — a network failure, a permission error, a missing package — the error message still appears so you can diagnose and fix it.

---

## Common Errors and Fixes

| Error | Cause | Fix |
|-------|-------|-----|
| `Permission denied` when running the script | Missing execute permission | Run `chmod +x websetup.sh` |
| `No such file or directory` on the `cp` command | Folder referenced as `2098_health.zip/` instead of `2098_health/` | Remove `.zip` from the folder name in the `cp` command |
| `wget` fails | Incorrect URL | Double-check the URL from the browser Network tab |
| Website shows default Apache page | Files not copied to `/var/www/html/` | Check `ls /var/www/html/` and re-run the `cp` command |
| Service not running | `httpd` failed to start | Run `systemctl status httpd` and read the error message |

## Script Writing Best Practices Demonstrated

| Practice | How it is applied in this script |
|----------|----------------------------------|
| **Shebang on line 1** | `#!/bin/bash` — always required |
| **Comments for every section** | `# Installing Dependencies`, `# Clean Up` etc. |
| **Print statements for the user** | `echo "Installing packages."` — keeps the user informed |
| **Output redirection for noisy commands** | `> /dev/null` on yum, wget, and unzip |
| **Cleanup at the end** | Remove temp files after they are no longer needed |
| **Verification at the end** | `systemctl status` and `ls` confirm the deployment succeeded |
