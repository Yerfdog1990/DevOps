# Variables

## What Is a Variable?

A **variable** is temporary storage in memory. When a process runs, it lives in RAM — and variables store data within that process. When the process ends, the variable and its value are gone.

Think of it this way:
- **Hard disk** = permanent storage
- **Variable** = temporary storage inside a running process

Variables are one of the most useful features in scripting. They allow you to:
- Store a value once and reuse it multiple times
- Make a script adaptable by changing one value at the top rather than hunting through the entire file
- Store the output of commands for later use

---

## Setting and Reading Variables

### Setting a Variable

```bash
SKILL=DevOps
```

- The variable name is on the left: `SKILL`
- The value is on the right: `DevOps`
- **No spaces** on either side of the `=` sign — this is important syntax in Bash

```bash
# Wrong — Bash will try to run "DevOps" as a command:
SKILL = DevOps

# Correct:
SKILL=DevOps
```

### Reading a Variable

To use (read) a variable, prefix its name with `$`:

```bash
echo $SKILL
# Output: DevOps
```

Without the `$`, Bash treats the word as plain text, not a variable reference:

```bash
echo SKILL
# Output: SKILL    ← just the text, not the value
```

### Variable Name Conventions

- Variable names can be uppercase, lowercase, or mixed — it is your preference
- Many scripters use **UPPERCASE** for variables so they stand out in the code
- Bash is **case-sensitive** — `PACKAGE`, `Package`, and `package` are three different variables
- Always use **descriptive names** so the purpose is clear when you read the script later

---

## Variables with Multi-Word Values — Quotes

If the value contains spaces, it must be enclosed in quotes. Without quotes, Bash interprets each space-separated word as a separate item:

```bash
# Wrong:
PACKAGE=httpd wget unzip
# Bash tries to run "wget" as a command

# Correct:
PACKAGE="httpd wget unzip"
```

### Single Quotes vs Double Quotes

| Quote Type | Behaviour |
|------------|-----------|
| `"double quotes"` | Allows **variable substitution** — `$VARIABLE` is replaced with its value |
| `'single quotes'` | **Literal** — everything inside is treated as plain text; `$VARIABLE` is not expanded |

```bash
myvar='Hello World'
echo $myvar
# Output: Hello World

newvar="More $myvar"
echo $newvar
# Output: More Hello World

newvar='More $myvar'
echo $newvar
# Output: More $myvar    ← $ not expanded inside single quotes
```

## Using Variables in Commands

Once a variable is set, you can use it anywhere the value would normally appear:

```bash
PACKAGE="httpd wget unzip"
yum install $PACKAGE -y
```

Before Bash runs the line, it substitutes `$PACKAGE` with `httpd wget unzip`, so the actual command that executes is:

```bash
yum install httpd wget unzip -y
```

This is called **variable interpolation** or **variable substitution**.

## Practical Example — Applying Variables to the Web Setup Script

Without variables, values like the service name and package list appear multiple times in the script. If they need to change, you must find and update every occurrence. With variables, you change one line at the top and the rest of the script updates automatically.

### Declaring Variables at the Top

```bash
#!/bin/bash

# ########################################
# Variables
# ########################################
PACKAGE="httpd wget unzip"
SVC="httpd"
URL='https://www.tooplate.com/zip-templates/2098_health.zip'
ART_NAME='2098_health'
TMPDIR='/tmp/webfiles'
```

**Which values make good variables?**

1. **Values that change between environments or use cases** — the URL, the package list, the service name. If you swap this script to deploy a different website, you only update the variables at the top.
2. **Values repeated multiple times in the script** — `httpd` appears in `yum install`, `systemctl start`, `systemctl enable`, and `systemctl restart`. Declaring it as `SVC` means one change updates all four places.

### Using Variables in the Script

```bash
#!/bin/bash

# ########################################
# Variables
# ########################################
PACKAGE="httpd wget unzip"
SVC="httpd"
URL='https://www.tooplate.com/zip-templates/2098_health.zip'
ART_NAME='2098_health'
TMPDIR='/tmp/webfiles'

# Installing Dependencies
echo "#############################################"
echo "Installing packages."
echo "#############################################"
sudo yum install $PACKAGE -y > /dev/null
echo

# Start & Enable Service
echo "#############################################"
echo "Start & Enable $SVC Service"
echo "#############################################"
sudo systemctl start $SVC
sudo systemctl enable $SVC
echo

# Creating Temp Directory & Deploying Artifact
echo "#############################################"
echo "Starting Artifact Deployment"
echo "#############################################"
mkdir -p $TMPDIR
cd $TMPDIR
echo

wget $URL > /dev/null
unzip $ART_NAME.zip > /dev/null
sudo cp -r $ART_NAME/* /var/www/html/
echo

# Bounce Service
echo "#############################################"
echo "Restarting $SVC service"
echo "#############################################"
systemctl restart $SVC
echo

# Clean Up
echo "#############################################"
echo "Removing Temporary Files"
echo "#############################################"
rm -rf $TMPDIR
echo

echo "#############################################"
echo "Deployment Complete. Service Status:"
echo "#############################################"
sudo systemctl status $SVC

echo
echo "Contents of /var/www/html:"
ls /var/www/html/
```

Notice how `$ART_NAME` is used in two ways:

```bash
unzip $ART_NAME.zip      # becomes: unzip 2098_health.zip
cp -r $ART_NAME/*        # becomes: cp -r 2098_health/*
```

The same variable works for both the zip filename and the extracted folder name — the `.zip` extension is added inline where needed.

## Command Substitution

Variables can also store the **output of a command**. This is called **command substitution** and uses `$( )` syntax:

```bash
myvar=$( ls /etc | wc -l )
echo "There are $myvar entries in /etc"
```

The command inside `$( )` runs first, and its output becomes the value of the variable. This is useful for capturing dynamic information like dates, file counts, or system details:

```bash
CURRENT_DATE=$( date +%Y-%m-%d )
echo "Today is $CURRENT_DATE"
# Output: Today is 2026-06-03

HOSTNAME_VAR=$( hostname )
echo "Running on: $HOSTNAME_VAR"
```

If the command produces multiple lines of output, newlines are removed and all output is placed on a single line in the variable.

## Special Built-in Variables

Bash automatically provides several special variables. You do not set these — Bash sets them for you:

| Variable | Value |
|----------|-------|
| `$0` | The name of the script itself |
| `$1` – `$9` | The first through ninth command-line arguments passed to the script |
| `$#` | The number of arguments passed to the script |
| `$@` | All arguments passed to the script |
| `$?` | The exit status of the most recently run command (0 = success, non-zero = failure) |
| `$$` | The process ID (PID) of the current script |
| `$USER` | The username of the user running the script |
| `$HOSTNAME` | The hostname of the machine |
| `$SECONDS` | Number of seconds since the script started |
| `$RANDOM` | A different random number each time it is referenced |
| `$LINENO` | The current line number in the script |

### Example — Command Line Arguments

```bash
#!/bin/bash
# mycopy.sh — copies a file and verifies the copy

cp $1 $2
echo "Details for $2:"
ls -lh $2
```

Run it as:

```bash
./mycopy.sh /projects/file1.data ./results.data
```

- `$1` = `/projects/file1.data` (source)
- `$2` = `./results.data` (destination)

### Example — Using `$?` for Exit Status

```bash
ping -c 1 google.com > /dev/null
echo $?
# Output: 0   (success — host is reachable)

ping -c 1 nonexistenthost > /dev/null
echo $?
# Output: 1   (failure — host not found)
```

`$?` is very useful in conditional logic later — you can check whether the previous command succeeded before proceeding.

## Variable Scope and Exporting

By default, variables are only available in the **current process** (the script that set them). If your script calls another script, the child script cannot see the parent's variables unless they are **exported**:

```bash
var1=hello
export var1
./child_script.sh   # child_script.sh can now use $var1
```

**Important:** Exporting is one-way. The child script gets a **copy** of the variable. Any changes the child makes do not affect the variable in the parent script.

For most scripts you write, exporting variables is not necessary. It becomes relevant when you break large tasks into multiple scripts that call each other.

## Summary

| Concept | Syntax | Notes |
|---------|--------|-------|
| Set a variable | `NAME=value` | No spaces around `=` |
| Read a variable | `$NAME` or `${NAME}` | `$` prefix required |
| Multi-word value | `NAME="word1 word2"` | Use quotes |
| Double quotes | `"$NAME"` | Variable is expanded |
| Single quotes | `'$NAME'` | Treated as literal text |
| Command substitution | `VAR=$( command )` | Stores command output |
| Script arguments | `$1`, `$2`, ... `$9` | Set automatically |
| Number of arguments | `$#` | Set automatically |
| All arguments | `$@` | Set automatically |
| Last exit code | `$?` | 0 = success |
| Export to child | `export VAR` | One-way copy to child process |

## The Dismantle Script

Before testing the variables-based web setup script, run a **dismantle script** that removes everything installed by the previous version of the script. This ensures you are testing a clean setup — not just verifying that an already-installed system still works.

```bash
#!/bin/bash

# Stop the service
systemctl stop httpd

# Remove web content
rm -rf /var/www/html/*

# Remove installed packages
yum remove httpd wget unzip -y
```

Save as `dismantle.sh`, make it executable, and run it:

```bash
chmod +x dismantle.sh
./dismantle.sh
```

When it completes you will see output confirming 14 packages were removed (httpd and its dependencies). After the dismantle script finishes, the environment is clean and ready for a fresh test run.

> You can also rename your scripts with numeric prefixes to keep them organised and easy to identify:
> ```bash
> mv firstscript.sh 1_firstscript.sh
> mv websetup.sh 2_websetup.sh
> # The variables version becomes:
> # 3_vars_websetup.sh
> ```

## When to Use Variables — Decision Guide

Use a variable when:

- A value is **used more than once** in the script — change it in one place instead of many
- A value is **likely to change** between environments, projects, or use cases (URLs, package names, service names, directory paths)
- You want to **store the output of a command** for use later
- The value makes the script **more readable** — `$SVC` is clearer than repeating `httpd` five times
