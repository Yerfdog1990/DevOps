# Environment Variables

## What Are Environment Variables?

Environment variables are **global system variables** accessible by all processes and users running under the operating system. Unlike regular variables that exist only within a single script or shell session, environment variables are available system-wide — any program, script, or user on the system can read them.

They are useful for storing system-wide values such as:
- `PATH` — where to look for executable programs
- `HOME` — the current user's home directory
- `USER` — the current username
- `HOSTNAME` — the machine's network name

---

## Environment Variables vs Local Variables

| Type | Scope | How to Set | Example |
|------|-------|-----------|---------|
| **Local variable** | Current process/script only | `varname=value` | `NAME=John` |
| **Environment variable** | Available to current process and all child processes | `export varname=value` | `export JAVA_HOME=/usr/lib/jvm/java` |

In Linux/macOS, environment variables are **case-sensitive** and are conventionally named in **UPPERCASE** with words joined by underscores (e.g., `JAVA_HOME`, `MY_VAR`).

## Viewing Environment Variables

### List All Environment Variables

```bash
env
# or
printenv
```

Both commands print all currently active environment variables and their values.

### View a Specific Variable

```bash
echo $VARIABLE_NAME

# Examples:
echo $PATH
echo $HOME
echo $USER
echo $HOSTNAME
```

### Using `set` to View All Variables

```bash
set
```

`set` lists all variables — including local variables and environment variables — available in the current shell session.

## The `PATH` Variable

`PATH` is the most important and most frequently used environment variable. It contains a **colon-separated list of directories** that Bash searches when you type a command.

```bash
echo $PATH
# Example output:
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

When you type a command like `wget` or `python3`, Bash searches each directory in `PATH` from left to right until it finds an executable with that name. If it is not found in any of the listed directories, you get:

```text
bash: abc: command not found
```

> **Important:** Unlike Windows, Linux/macOS does **not** automatically search the current directory. That is why you must use `./scriptname.sh` to run a script in the current directory — the `./` explicitly tells Bash to look here, not in `PATH`.

### Adding a Directory to `PATH`

To add a directory to `PATH` for the **current session only**:

```bash
export PATH=/new/directory:$PATH
```

This prepends `/new/directory` to the existing `PATH`. The new directory is searched first.

To verify:

```bash
echo $PATH
# Output: /new/directory:/usr/local/sbin:/usr/local/bin:...
```

### Making `PATH` Changes Permanent

To make the change persist across sessions and reboots, add the `export` line to one of the shell startup files:

| File | Who it affects |
|------|---------------|
| `~/.bashrc` | Current user, interactive non-login shells |
| `~/.bash_profile` or `~/.profile` | Current user, login shells |
| `/etc/profile` | All users system-wide |

```bash
# Add to the end of ~/.bashrc
export PATH=/usr/local/myapp/bin:$PATH
```

After editing the file, apply the changes to the current session without restarting:

```bash
source ~/.bashrc
# or
source ~/.bash_profile
```

## Setting and Exporting Environment Variables

### Setting a Local Variable

```bash
NAME=John
echo $NAME
# Output: John
```

This variable exists only in the current shell process. Child processes (scripts called from this shell) cannot see it.

### Exporting to Make It an Environment Variable

```bash
export NAME=John
# or export an already-set variable:
NAME=John
export NAME
```

After `export`, the variable is available to any child process spawned from the current shell.

### Unsetting a Variable

```bash
# Set to empty string:
NAME=

# Or remove it entirely:
unset NAME
```

## Variable Scope and Child Processes

Variables are limited to the process that created them by default. When a script runs another script, the child script cannot see the parent's local variables — only exported ones.

```bash
# script1.sh
var1=hello
var2=world
export var1          # exported — child can see this
./script2.sh         # run child script
```

```bash
# script2.sh
echo $var1           # Output: hello   (exported — available)
echo $var2           # Output:         (empty — not exported)
```

**Exporting is one-way.** The child gets a **copy** of the variable. Any changes the child makes to that copy have no effect on the parent's variable.

## Common Important Environment Variables

| Variable | Purpose |
|----------|---------|
| `$PATH` | Directories searched for executable programs |
| `$HOME` | Current user's home directory |
| `$USER` | Current username |
| `$SHELL` | Path to the current shell (`/bin/bash`) |
| `$HOSTNAME` | Machine's network name |
| `$PWD` | Current working directory |
| `$OLDPWD` | Previous working directory |
| `$UID` | Numeric user ID (root = 0) |
| `$JAVA_HOME` | JDK installation directory (used by Java applications) |
| `$CLASSPATH` | Directories/JARs for Java class lookup |

## `JAVA_HOME` — A Real-World Example

Many Java applications (including Tomcat, Maven, and Jenkins) require a `JAVA_HOME` environment variable pointing to the JDK installation directory. This is a practical example of why environment variables matter in DevOps.

### Check if `JAVA_HOME` is set

```bash
echo $JAVA_HOME
```

If empty, the variable is not set.

### Set `JAVA_HOME` for the current session

```bash
export JAVA_HOME=/usr/lib/jvm/java-11-openjdk
```

### Set `JAVA_HOME` permanently

Add to `~/.bashrc` or `/etc/profile`:

```bash
export JAVA_HOME=/usr/lib/jvm/java-11-openjdk
export PATH=$JAVA_HOME/bin:$PATH
```

Apply immediately:

```bash
source ~/.bashrc
```

Verify:

```bash
echo $JAVA_HOME
# Output: /usr/lib/jvm/java-11-openjdk
```

## Differences Between Linux and Windows Environment Variables

| Feature | Linux/macOS | Windows |
|---------|-------------|---------|
| Case sensitivity | **Case-sensitive** (`PATH` ≠ `path`) | Not case-sensitive |
| Variable reference syntax | `$VARNAME` | `%VARNAME%` |
| Path separator | Colon `:` | Semicolon `;` |
| Directory separator | Forward slash `/` | Backslash `\` |
| Current directory in PATH | **Not included automatically** (use `./`) | Included automatically |
| List all variables | `env` or `printenv` | `set` |
| Set permanently | Edit `~/.bashrc` or `/etc/profile` | Control Panel → System → Environment Variables |
| Apply changes without restart | `source ~/.bashrc` | Restart CMD required |

## Practical Example

```bash
#!/bin/bash

# Print system environment information
echo "Running as user: $USER"
echo "Home directory: $HOME"
echo "Current shell: $SHELL"
echo "Hostname: $HOSTNAME"
echo "Current directory: $PWD"
echo
echo "PATH directories:"
echo $PATH | tr ':' '\n'   # Print each PATH directory on its own line
```

Output:

```text
Running as user: root
Home directory: /root
Current shell: /bin/bash
Hostname: scriptbox
Current directory: /opt/scripts

PATH directories:
/usr/local/sbin
/usr/local/bin
/usr/sbin
/usr/bin
/sbin
/bin
```
