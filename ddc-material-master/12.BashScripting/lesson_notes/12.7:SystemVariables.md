# System Variables

## What Are System Variables?

System variables (also called **environment variables** or **built-in variables**) are predefined variables that Bash and the operating system set and maintain automatically. Unlike user-defined variables that you declare yourself, these exist without any declaration — Bash populates them before your script even runs.

They fall into three categories:
1. **Core environment variables** — information about the system and current user session
2. **Positional parameters** — arguments passed to the script at runtime
3. **Internal runtime variables** — execution tracking and status information

---

## Core Environment Variables

These provide information about your system, the current user, and the shell session:

| Variable | What it contains |
|----------|-----------------|
| `$HOME` | Home directory of the current user (e.g. `/home/vagrant` or `/root`) |
| `$USER` | Username of the user running the script |
| `$PATH` | Colon-separated list of directories where Bash looks for executable files |
| `$PWD` | Absolute path of the current working directory |
| `$OLDPWD` | The previous working directory (before the last `cd`) |
| `$SHELL` | Path to the current shell binary (e.g. `/bin/bash`) |
| `$HOSTNAME` | Network name of the local machine |
| `$UID` | Numeric User ID of the current user (root = 0) |

```bash
echo $USER       # vagrant or root
echo $HOME       # /root
echo $HOSTNAME   # scriptbox
echo $PWD        # /opt/scripts
```

---

## Positional Parameters and Script Arguments

These were introduced in the previous lecture and are set automatically when arguments are passed to the script:

| Variable | What it contains |
|----------|-----------------|
| `$0` | The name of the script itself |
| `$1` – `$9` | The first through ninth arguments passed to the script |
| `${10}` and above | Arguments past the ninth — curly braces required |
| `$#` | The total number of arguments supplied |
| `$@` | All arguments as **separate individual strings** |
| `$*` | All arguments as a **single conjoined string** |

```bash
./myscript.sh one two three
# $0 = ./myscript.sh
# $1 = one
# $2 = two
# $3 = three
# $# = 3
# $@ = one two three (each as separate item)
# $* = one two three (as one string)
```

## Internal Runtime Variables

These track what is happening during script execution:

| Variable | What it contains |
|----------|-----------------|
| `$?` | Exit status of the most recently executed command (`0` = success, non-zero = failure) |
| `$$` | Process ID (PID) of the current shell or script |
| `$IFS` | Internal Field Separator — the character(s) used to split words and lines (default: space, tab, newline) |
| `$SECONDS` | Number of seconds elapsed since the script started |
| `$RANDOM` | A pseudo-random integer between 0 and 32767, different each time it is referenced |
| `$LINENO` | The line number currently being executed in the script |

---

## The Exit Status — `$?`

`$?` is one of the most important and frequently used system variables. It holds the **exit code** of the last command that was run:

- **`0`** — the command succeeded
- **Non-zero** — the command failed (different values indicate different types of failure)

### Demonstrating `$?`

```bash
free -m
echo $?
# Output: 0    ← command succeeded
```

```bash
freeeee -m
echo $?
# Output: 127  ← command not found
```

```bash
ls /nonexistent_folder 2>/dev/null
echo $?
# Output: 2    ← file or directory not found
```

```bash
free -m blahblah
echo $?
# Output: 1    ← command ran but with an error (wrong argument)
```

### Common Exit Codes

| Exit Code | Meaning |
|-----------|---------|
| `0` | Success |
| `1` | General error |
| `2` | Misuse of shell command or missing file/directory |
| `127` | Command not found |
| `126` | Command found but not executable |
| `130` | Script terminated by Ctrl+C |

> **Important:** `$?` only holds the exit status of the **most recently run command**. If you need to check whether a specific command succeeded, read `$?` immediately after that command — the very next command will overwrite it.

### Why `$?` Matters

Later in the scripting session, `$?` is used heavily in **conditional logic**:

```bash
# Example of how $? will be used with if statements:
yum install httpd -y
if [ $? -eq 0 ]; then
    echo "Installation succeeded"
else
    echo "Installation failed"
fi
```

This pattern — run a command, check `$?`, take action based on the result — is the foundation of error handling in bash scripts.

## `$RANDOM` — Random Numbers

```bash
echo $RANDOM
# Output: 17382   (different every time)

echo $RANDOM
# Output: 4291

echo $RANDOM
# Output: 29847
```

`$RANDOM` generates a pseudo-random integer between 0 and 32767 each time it is referenced. Useful for generating unique filenames, random delays, or test data in scripts.

---

## `$USER` and `$HOSTNAME` in Practice

These are useful for making script output more informative:

```bash
echo "Running as: $USER on $HOSTNAME"
# Output: Running as: root on scriptbox
```

You can also use them in log files or notifications to record which user ran a script and on which machine.

## Practical Example Script

```bash
#!/bin/bash

echo "Hello, $USER!"
echo "This script is named: $0"
echo "You provided $# arguments to this script."
echo "Running on host: $HOSTNAME"
echo "Current directory: $PWD"
echo

# Run a command and check its exit status
ls /nonexistent_folder_test 2>/dev/null
echo "The previous command exited with code: $?"

echo
echo "A random number: $RANDOM"
echo "Script has been running for $SECONDS seconds."
```

Run it:

```bash
./sysvar_demo.sh arg1 arg2
```

Output:

```text
Hello, root!
This script is named: ./sysvar_demo.sh
You provided 2 arguments to this script.
Running on host: scriptbox
Current directory: /opt/scripts

The previous command exited with code: 2

A random number: 14823
Script has been running for 0 seconds.
```

## Listing All Environment Variables

To see all currently active environment and system variables in your shell session:

```bash
env
# or
printenv
```

This outputs a full list of all variables — useful for seeing what is available in the current environment, especially when debugging scripts that depend on environment settings.
