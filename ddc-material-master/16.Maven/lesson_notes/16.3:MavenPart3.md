## 1. AWS CloudShell (Amazon Linux 2023)

Terminate the previous EC2 instance — once you know how to build from scratch on an OS, you can do it anywhere (VM, container, CloudShell, Jenkins).

Open **AWS CloudShell** from the console (expand or open in new tab).

```bash
cat /etc/os-release        # Amazon Linux 2023 — RPM-based → use yum/dnf
```

### Install JDK 21 and Maven

Package naming differs from Ubuntu — packages start with `java`, and AWS ships its own JDK build called **Corretto**:

```bash
sudo dnf search java | grep 21
sudo dnf install java-21-amazon-corretto -y
sudo dnf install maven -y
mvn -version                # 3.8.4
```

### Build the project

```bash
git clone https://github.com/<user>/vprofile-project.git
cd vprofile-project
mvn install                 # BUILD SUCCESS
ls target                   # artifact (WAR), reports, etc.
```

Same workflow as the Ubuntu EC2 instance. Later this runs from the **Jenkins UI**.

> **Key point:** on any OS/VM/container, you must know the tool versions and dependencies and how to install them. Use AI tools (ChatGPT, Grok, Amazon Q) to get commands — you don't need to memorize commands, just know what information you need and how to execute.

## 2. NodeJS Build Example

Source: `github.com/<user>/node` — one service from the **eMart microservice application**, written in NodeJS.

Scenario: you've never seen NodeJS. Approach — give the repo URL to generative AI and ask how to build it. (For private repos, use in-IDE assistants: GitHub Copilot, Amazon Q Developer in VS Code.)

### Java ↔ Node analogy

| Java world | Node world |
|------------|-----------|
| JDK | Node.js |
| Maven (`mvn`) | npm |
| `pom.xml` | `package.json` |
| Maven phases (validate, test...) | `scripts` in package.json (test, start, dev) |
| Dependencies in pom.xml | `dependencies` in package.json |
| `~/.m2/repository` | `node_modules/` folder |
| `mvn install` | `npm install` |
| `~/.m2` cache | `~/.npm` cache (+ logs) |

### Install Node on Amazon Linux 2023

AL2023 doesn't include NodeJS/npm by default — ask AI for the install commands, then verify:

```bash
node -v      # e.g., v20
npm -v
```

### Build the service

```bash
git clone https://github.com/<user>/node.git
cd <node-folder>
npm install          # downloads dependencies into node_modules/
```

Notes:

- **`package.json`** — name, version, description, main file, `scripts` (phase-like commands), dependencies with versions.
- **`package-lock.json`** — lock file, created by `npm install` (this repo already had one committed; npm cleared the old one).
- Fix reported vulnerabilities:

```bash
npm audit fix    # fix vulnerabilities
npm audit        # verify none remain
```

- Artifact = everything **except** `node_modules/` and the lock file.

### Running the app (for context — not done here)

- Needs a MongoDB backend: `touch .env` with port, MongoDB URL, secret → `node app.js`.
- **nodemon** (`npm install -g nodemon`) auto-reloads the app on source changes at runtime — used by developers during testing so they don't rebuild/redeploy after every change.

## 3. Key Takeaways

- Once you know one build tool, others are easy to relate to — no sharp learning curve.
- Understand: what a build tool is, how to install it, how to run it, how to manage versions.
- Developers will always tell you required versions and build steps; use generative AI for command details.
- Experiment with the source code yourself before doing CI/CD or deploying to servers.
- These lectures are **prerequisites for the CI/CD (Jenkins) sections and projects**.
