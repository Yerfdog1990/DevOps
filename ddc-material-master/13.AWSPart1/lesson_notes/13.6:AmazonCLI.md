# Amazon Command Line Interface (AWS CLI)

---

## 1. What is AWS CLI?

> **AWS CLI (Command Line Interface)** is a unified, open-source tool that enables you to **interact with and manage AWS services using commands in your terminal** — instead of clicking through the browser-based AWS Management Console.

- Everything you can do in the AWS Console **can also be done from the command line**
- Works on **Windows, macOS, and Linux**
- With minimal configuration, you can start running commands equivalent to the console
- Enables **automation through scripts** — critical for DevOps, CI/CD pipelines, and programmatic workflows

```
Browser (AWS Console)
        ↕
   Same result
        ↕
AWS CLI (Terminal / Command Line)
```

---

## 2. How It Works

The AWS CLI communicates with AWS services via **API calls** authenticated with **Access Keys** (not username/password).

```
Your Terminal
     │
     │  aws ec2 describe-instances
     ↓
  AWS CLI
     │
     │  Authenticated API request (Access Key + Secret Key)
     ↓
  AWS Service (EC2)
     │
     ↓
  JSON Response → printed in terminal
```

## 3. Installing AWS CLI

### Installation by Operating System

| OS | Command |
|---|---|
| **Windows** (PowerShell as Admin) | `choco install awscli` |
| **macOS** (Terminal) | `brew install awscli` |
| **Linux** | Download with `curl`, unzip, run install script |

### Linux Installation Commands

```bash
# Download the installer
curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o "awscliv2.zip"

# Unzip
unzip awscliv2.zip

# Run the installer
sudo ./aws/install
```

### Verify Installation

```bash
aws --version
# → aws-cli/2.x.x Python/3.x.x ...
```

## 5. Setting Up Authentication — IAM Access Keys

The CLI authenticates using **Access Keys** — not username and password. These are created from an IAM user.

### Step 1 — Create an IAM User for CLI Access

```
AWS Console → Services → IAM → Users → Create User

1. Username: cli-admin (or any meaningful name)
2. Access type: Programmatic access (CLI, SDK, API)
3. Permissions: Attach existing policy
   → For this course: AdministratorAccess
   → In production: use least-privilege policies (e.g., AmazonEC2FullAccess)
4. Click through to Create User
```

> ⚠️ **AdministratorAccess** gives complete control of your AWS account. Never share these credentials, commit them to version control, or expose them publicly.

### Step 2 — Generate Access Keys

```
IAM → Users → Click on your user
→ Security Credentials tab
→ Scroll to "Access Keys"
→ Create Access Key
→ Use case: Command Line Interface (CLI)
→ Check "I understand the risk"
→ Create Access Key
```

**You receive two values:**

| Key | Description | Visible Again? |
|---|---|---|
| **Access Key ID** | Like a username | ✅ Always visible |
| **Secret Access Key** | Like a password | ❌ Shown only ONCE — download immediately |

```
→ Download CSV file immediately
→ Store it securely — never share it
```

### Access Key Management

```
IAM → Users → Security Credentials → Access Keys
├── Activate / Deactivate individual keys
├── Delete a key
└── Create multiple keys (one user can have multiple)
```

---

## ⚠️ Critical Security Warning — Access Keys

> Access keys are **plain text credentials**. If exposed, attackers can take full control of your AWS account.

**Real-world consequences of leaked access keys:**
- Bots constantly scan public GitHub repositories for AWS keys
- Leaked keys are used to spin up **hundreds of EC2 instances for crypto mining**
- You can receive **massive AWS bills within hours**

**Rules to follow:**
- ❌ Never commit access keys to any repository (public or private)
- ❌ Never share access keys with anyone
- ❌ Never paste them in screenshots or recordings
- ✅ Download the CSV, store securely, use immediately
- ✅ Deactivate or delete keys when done
- ✅ Rotate keys regularly in production environments

## 6. Configuring AWS CLI

Run the following command in your terminal (Git Bash on Windows, Terminal on macOS/Linux):

```bash
aws configure
```

You will be prompted for four values:

```
AWS Access Key ID [None]: AKIAIOSFODNN7EXAMPLE
AWS Secret Access Key [None]: wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
Default region name [None]: us-east-1
Default output format [None]: json
```

| Field | Example | Notes |
|---|---|---|
| **Access Key ID** | From the CSV file | Paste carefully — no spaces |
| **Secret Access Key** | From the CSV file | Paste carefully — not visible again |
| **Default region** | `us-east-1` | Use the region code from AWS Console |
| **Output format** | `json` | Options: json, text, table |

### Where Configuration is Stored

After running `aws configure`, two files are created:

```
~/.aws/
├── config          → Stores region and output format
└── credentials     → Stores Access Key ID and Secret Access Key
```

You can manually edit these files with a text editor if you make a mistake:

```bash
# View the files
ls ~/.aws

# Edit config manually
vi ~/.aws/config

# Edit credentials manually
vi ~/.aws/credentials
```

## 7. Verifying the CLI Setup

Run this command to confirm your credentials are working:

```bash
aws sts get-caller-identity
```

**Successful output:**
```json
{
    "UserId": "AIDIOSFODNN7EXAMPLE",
    "Account": "123456789012",
    "Arn": "arn:aws:iam::123456789012:user/cli-admin"
}
```

> If you get an error, run `aws configure` again and re-enter the credentials carefully (copy-paste errors are the most common issue).

## 8. Common AWS CLI Commands

### EC2 — Describe Instances

```bash
aws ec2 describe-instances
```

Returns JSON output of all instances in the configured region:
- Architecture, instance type
- Volume and device details
- Public and private IP addresses
- Security group information
- AMI details

```bash
# Navigate output (less pager)
# Press Enter to scroll, Q to quit
```

---

### Key Pair — Create via CLI

```bash
aws ec2 create-key-pair \
  --key-name my-key-pair \
  --query 'KeyMaterial' \
  --output text > my-key-pair.pem
```

**What this does:**
- Creates a key pair in AWS (public key stored in AWS)
- Saves the **private key** to `my-key-pair.pem` on your machine

**Verify the file:**
```bash
cat my-key-pair.pem
# → -----BEGIN RSA PRIVATE KEY-----
#    MIIEowIBAAKCAQEA...
```

**Verify in AWS Console:**
```
EC2 → Network & Security → Key Pairs
→ Your new key pair is listed
```

---

### Security Group — Create and Add Rules

#### Step 1 — Get your current public IP

```bash
MY_IP=$(curl -s http://checkip.amazonaws.com)
echo $MY_IP
# → 203.0.113.45
```

#### Step 2 — Create the security group

```bash
aws ec2 create-security-group \
  --group-name my-sg \
  --description "My security group"
```

#### Step 3 — Add rule: SSH (port 22) from your IP

```bash
aws ec2 authorize-security-group-ingress \
  --group-name my-sg \
  --protocol tcp \
  --port 22 \
  --cidr $MY_IP/32
```

#### Step 4 — Add rule: HTTP (port 80) from anywhere

```bash
aws ec2 authorize-security-group-ingress \
  --group-name my-sg \
  --protocol tcp \
  --port 80 \
  --cidr 0.0.0.0/0
```

---

### EC2 — Launch an Instance

```bash
aws ec2 run-instances \
  --image-id ami-0c02fb55956c7d316 \
  --count 1 \
  --instance-type t2.micro \
  --key-name my-key-pair \
  --security-groups my-sg \
  --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=web02}]'
```

**Parameters:**
| Parameter | Description |
|---|---|
| `--image-id` | AMI ID (get from EC2 console or Amazon Q) |
| `--count` | Number of instances to launch |
| `--instance-type` | Instance size (t2.micro for free tier) |
| `--key-name` | Name of your key pair |
| `--security-groups` | Security group name |
| `--tag-specifications` | Tags to apply (Name, Project, etc.) |

**Verify in AWS Console:**
```
EC2 → Instances
→ web02 is running
→ Security tab shows: security group, key pair name
```

---

### EC2 — Terminate an Instance

```bash
# First, get the instance ID
aws ec2 describe-instances --query 'Reservations[*].Instances[*].InstanceId' --output text

# Terminate by instance ID
aws ec2 terminate-instances --instance-ids i-0abcd1234efgh5678
```

## 9. Amazon Q — AI Assistant for AWS CLI

**Amazon Q Developer** is AWS's built-in AI assistant — accessible directly in the AWS Console and as a VS Code plugin.

### What Amazon Q Can Do

| Use Case | Example |
|---|---|
| **CLI command generation** | "How do I create a key pair using AWS CLI?" |
| **Code assistance** | Suggests code completions in VS Code (like GitHub Copilot) |
| **Troubleshooting** | "Why is my EC2 instance unreachable?" |
| **AWS service guidance** | "What's the difference between S3 and EFS?" |

### Using Amazon Q for CLI Commands

Instead of memorizing complex commands, ask Amazon Q in plain English:

```
"How to create a key pair using AWS CLI"
→ Returns: aws ec2 create-key-pair --key-name my-key-pair ...

"Create security group with name my-sg with rule 22 from my IP and 80 from anywhere"
→ Returns: the full set of commands to create the group and add both rules

"Launch EC2 instance with Amazon Linux AMI, t2.micro, key pair my-key-pair,
 security group my-sg, name web02"
→ Returns: aws ec2 run-instances command with all parameters filled in
```

### Amazon Q vs. ChatGPT for AWS

| Aspect | Amazon Q | ChatGPT |
|---|---|---|
| **Speed** | Slower for chat | Faster |
| **AWS Precision** | Highest — built specifically for AWS | Good, but general purpose |
| **Code assistant** | ✅ Deep VS Code integration | ✅ General coding |
| **Best for** | Production AWS tasks, scripting | General questions |

> For AWS-specific tasks — especially scripting and automation — Amazon Q is the most precise tool available.

## 10. The Right Mindset for CLI

> **Know how to do things manually first, then learn to automate.**

This is the most important principle when learning the CLI:

```
Step 1: Learn to do it manually (AWS Console / Graphical)
        ↓
Step 2: Understand what the task does and why
        ↓
Step 3: Find the CLI command (documentation, Amazon Q, ChatGPT)
        ↓
Step 4: Understand the command before running it
        ↓
Step 5: Test it in a safe environment
        ↓
Step 6: Use it in scripts and automation
```

> If you don't understand security groups and you run an AWS CLI command to create one — you won't know what it's doing, why it might fail, or how to fix it. **Manual knowledge comes first.**

**Resources for finding CLI commands:**
- AWS CLI Documentation: `docs.aws.amazon.com/cli/latest/userguide`
- Command Reference: `awscli.amazonaws.com/v2/documentation/api/latest/index.html`
- Amazon Q (AWS Console AI assistant)
- ChatGPT / other AI tools
