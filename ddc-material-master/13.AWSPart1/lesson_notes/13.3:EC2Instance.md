# Amazon EC2 — Detailed Notes

---

## 1. What is EC2?

> **Amazon EC2 (Elastic Compute Cloud)** is a web service that provides **secure, resizable compute capacity in the cloud** — essentially virtual machines running in Amazon's data centers.

- One of the **most popular services** in AWS
- Allows you to easily **scale up or scale down** compute resources (RAM, CPU, network, storage)
- You pay **only for capacity you actually use**
- Reduces the time to boot new server instances to **minutes**
- Provides tools to **build failure-resilient applications**

### Benefits of EC2

| Benefit | Description |
|---|---|
| **Elastic Web-Scale Computing** | Scale capacity up or down in minutes |
| **Complete Control** | Full root/admin access to instances |
| **Flexible Cloud Hosting** | Wide variety of instance types and OS options |
| **Integrated** | Works seamlessly with S3, EFS, RDS, DynamoDB, Lambda, and more |
| **Reliable** | Proven, high-availability infrastructure |
| **Secure** | Deep integration with AWS security services |
| **Inexpensive** | Pay only for what you use |
| **Easy to Start** | Launch instances in minutes with the wizard |

## 2. EC2 Pricing Models

There are four ways to pay for EC2 instances:

### On-Demand (Used in this course)
- **Pay per hour** (or per second for some instance types)
- **No upfront payment, no long-term commitment**
- Best for:
    - Short-term, spiky, or unpredictable workloads
    - Applications being developed or tested for the first time
    - Users who prefer flexibility over cost savings

### Reserved Instances
- Reserve capacity for **1 to 3 years**
- **Up to 75% discount** compared to On-Demand pricing
- Also provides a **capacity reservation** in a specific AZ
- Best for:
    - Applications with **steady-state, predictable** usage
    - Workloads requiring reserved capacity
    - Long-term cost reduction

### Spot Instances
- **Bid on unused EC2 capacity** — up to **90% off** On-Demand pricing
- ⚠️ If someone outbids you, **your instance is terminated**
- Best for:
    - Flexible start/end time workloads
    - Applications viable only at very low compute prices
    - Batch processing, data analysis, large-scale additional capacity
- Tip: Use in combination with **Auto Scaling groups** to save money safely

### Dedicated Hosts
- A **physical EC2 server** dedicated entirely for your use
- Useful when you have **existing server-bound software licenses** (Windows Server, SQL Server, SUSE)
- Can be purchased On-Demand (hourly) or as a Reservation (**up to 70% off**)
- Most expensive option

### Pricing Comparison

| Model | Cost | Commitment | Best For |
|---|---|---|---|
| **On-Demand** | Highest per hour | None | Dev/test, unpredictable workloads |
| **Reserved** | Up to 75% off | 1–3 years | Steady, long-running applications |
| **Spot** | Up to 90% off | None (interruptible) | Flexible batch workloads |
| **Dedicated Host** | Very expensive | Optional (1–3 yr reservation) | Compliance, licensed software |

## 3. EC2 Instance Components

When launching an EC2 instance, you configure **6 key components**:

```
EC2 Instance Launch Wizard
│
├── 1. AMI           → What OS/software to run
├── 2. Instance Type → How much compute power
├── 3. EBS Storage   → Virtual hard disk(s)
├── 4. Tags          → Labels for organization & billing
├── 5. Security Group → Firewall rules (inbound/outbound)
└── 6. Key Pair      → SSH login credentials
```

---

### 3.1 AMI — Amazon Machine Image
- A **ready-made virtual machine template** — similar to Vagrant boxes
- Contains the OS and optionally pre-installed software
- Available from the **AWS Marketplace** (CentOS, Ubuntu, Amazon Linux, Windows, etc.)
- Every AMI comes with a base storage size:
    - Linux: typically **8 GB**
    - Windows: typically **30 GB**

### 3.2 Instance Type
- Defines the **compute resources** — CPU, RAM, network speed, storage speed
- Wide variety of families and sizes to choose from
- **Free Tier eligible:** `t2.micro` (1 vCPU, 1 GB RAM)

### 3.3 EBS — Elastic Block Store
- **Persistent block storage volumes** — virtual hard disks for your EC2 instance
- Used to store the **operating system** and **application data**
- Automatically **replicated within its Availability Zone** for high availability
- Key features: High performance, encryption, snapshots, elastic volumes
- ⚠️ EBS volumes **cannot be copied directly between AWS regions** — use snapshots instead
- You can add extra EBS volumes beyond the default AMI storage

### 3.4 Tags
- Simple **key-value pairs** attached to any AWS resource
- Examples: `Name = WebServer`, `Project = VProfile`, `Environment = Production`
- Very useful for **filtering resources** and **cost allocation in billing**
- No limit on number of tags per resource

### 3.5 Security Groups
> A security group acts as a **virtual firewall** for your EC2 instance, controlling **inbound and outbound traffic at the instance level**.

- You associate one or more security groups with an instance at launch
- Add **rules** to allow or block specific traffic types/ports/sources
- Rules are applied immediately to **all associated instances** when modified
- All rules from all associated security groups are evaluated together

**Common Security Group Rules:**

| Type | Protocol | Port | Source | Purpose |
|---|---|---|---|---|
| SSH | TCP | 22 | Your IP / 0.0.0.0/0 | Remote login (Linux) |
| RDP | TCP | 3389 | Your IP | Remote Desktop (Windows) |
| HTTP | TCP | 80 | 0.0.0.0/0 | Web server access |
| HTTPS | TCP | 443 | 0.0.0.0/0 | Secure web server |

### 3.6 Key Pairs
> EC2 uses **public-key cryptography** to encrypt/decrypt login information.

- A **key pair** = public key + private key
- **Public key** is injected into the EC2 instance at launch
- **Private key** (`.pem` file) is downloaded and kept by you — **never shared**

| OS | Login Method | Key Usage |
|---|---|---|
| **Linux** | SSH | Use private key to SSH in |
| **Windows** | RDP | Use private key to decrypt the admin password, then use RDP |

> ⚠️ **Save your `.pem` file securely** — AWS will not provide it again after download.

## 4. EC2 Instance Types

EC2 instances are organized into **5 families** based on use case:

### 4.1 General Purpose — `t2`, `m4`, `m3`

Balanced compute, memory, and networking — suitable for most applications.

**T2 — Burstable Performance**
- Receives CPU Credits continuously; accumulates credits when idle, uses them when active
- Best for: **web servers, developer environments, small databases**

| Model | vCPU | CPU Credits/hr | Memory (GiB) | Storage |
|---|---|---|---|---|
| t2.nano | 1 | 3 | 0.5 | EBS Only |
| t2.micro | 1 | 6 | 1 | EBS Only |
| t2.small | 1 | 12 | 2 | EBS Only |
| t2.medium | 2 | 24 | 4 | EBS Only |
| t2.large | 2 | 36 | 8 | EBS Only |
| t2.xlarge | 4 | 54 | 16 | EBS Only |
| t2.2xlarge | 8 | 81 | 32 | EBS Only |

**M4 — Latest General Purpose**

| Model | vCPU | Memory (GiB) | EBS Bandwidth (Mbps) |
|---|---|---|---|
| m4.large | 2 | 8 | 450 |
| m4.xlarge | 4 | 16 | 750 |
| m4.2xlarge | 8 | 32 | 1,000 |
| m4.4xlarge | 16 | 64 | 2,000 |
| m4.10xlarge | 40 | 160 | 4,000 |
| m4.16xlarge | 64 | 256 | 10,000 |

---

### 4.2 Compute Optimized — `c4`, `c3`

**Highest performing processors, lowest price/compute ratio** — best for CPU-intensive workloads.

**C4:**

| Model | vCPU | Memory (GiB) | EBS Bandwidth (Mbps) |
|---|---|---|---|
| c4.large | 2 | 3.75 | 500 |
| c4.xlarge | 4 | 7.5 | 750 |
| c4.2xlarge | 8 | 15 | 1,000 |
| c4.4xlarge | 16 | 30 | 2,000 |
| c4.8xlarge | 36 | 60 | 4,000 |

---

### 4.3 Memory Optimized — `x1`, `r4`, `r3`

Optimized for **large-scale, in-memory applications** — lowest price per GiB of RAM.

**X1 — Enterprise-class in-memory:**

| Model | vCPU | Memory (GiB) | SSD Storage (GB) |
|---|---|---|---|
| x1.16xlarge | 64 | 976 | 2 x 1,920 |
| x1.32xlarge | 128 | 1,952 | 2 x 1,920 |

**R4 — Memory-intensive applications:**

| Model | vCPU | Memory (GiB) | Networking |
|---|---|---|---|
| r4.large | 2 | 15.25 | Up to 10 Gbps |
| r4.xlarge | 4 | 30.5 | Up to 10 Gbps |
| r4.2xlarge | 8 | 61 | Up to 10 Gbps |
| r4.16xlarge | 64 | 488 | 20 Gbps |

---

### 4.4 Accelerated Computing — `p2`, `g2`, `f1`

GPU and FPGA-powered instances for graphics and hardware acceleration.

| Family | Use Case | Example |
|---|---|---|
| **P2** | Machine learning, HPC | p2.xlarge (1 GPU, 4 vCPU, 61 GiB) |
| **G2** | Graphics-intensive applications | g2.2xlarge (1 GPU, 8 vCPU) |
| **F1** | Custom hardware acceleration (FPGAs) | f1.2xlarge (1 FPGA, 8 vCPU) |

---

### 4.5 Storage Optimized — `i3`, `d2`

High I/O performance and dense local storage.

**I3 — NVMe SSD, ultra-low latency:**

| Model | vCPU | Memory (GiB) | NVMe Storage |
|---|---|---|---|
| i3.large | 2 | 15.25 | 0.475 TB |
| i3.2xlarge | 8 | 61 | 1.9 TB |
| i3.16xlarge | 64 | 488 | 15.2 TB |

**D2 — High disk throughput (HDD):**

| Model | vCPU | Memory (GiB) | HDD Storage |
|---|---|---|---|
| d2.xlarge | 4 | 30.5 | 6 TB (3 x 2000 GB) |
| d2.8xlarge | 36 | 244 | 48 TB (24 x 2000 GB) |

### Instance Family Summary

| Family | Types | Best For |
|---|---|---|
| **General Purpose** | t2, m4, m3 | Web servers, dev environments, small databases |
| **Compute Optimized** | c4, c3 | CPU-intensive batch processing, media encoding |
| **Memory Optimized** | x1, r4, r3 | In-memory databases, real-time analytics |
| **Accelerated Computing** | p2, g2, f1 | ML, graphics rendering, custom FPGA workloads |
| **Storage Optimized** | i3, d2 | NoSQL databases, data warehousing, log processing |

## 5. Creating an EC2 Instance — Step by Step

```
Step 1: Login to AWS Management Console

Step 2: Navigate to EC2 Dashboard
        → Click "Launch Instance"

Step 3: Choose an AMI
        → AWS Marketplace: CentOS, Ubuntu, Amazon Linux, Windows, etc.
        → Recommended for course: Amazon Linux 2023

Step 4: Choose Instance Type
        → Recommended (Free Tier): t2.micro
          (1 vCPU, 1 GiB RAM, EBS Only)
        → Click "Next"

Step 5: Configure Instance Details
        → Network, subnet, IAM role, user data scripts
        → Use default settings for basic setup

Step 6: Add Storage
        → Default EBS volume from AMI (8 GB for Linux)
        → Optionally add extra EBS volumes

Step 7: Add Tags
        → Key: Name | Value: MyWebServer
        → Add more tags as needed (Project, Environment, etc.)

Step 8: Configure Security Group
        → Create new or select existing
        → Add rules: SSH (port 22), HTTP (port 80), etc.

Step 9: Review and Launch
        → Review all settings
        → Click "Launch"

Step 10: Create/Select Key Pair
        → Select "Create a new key pair"
        → Give it a name (e.g., webloginkey)
        → Click "Download Key Pair" → saves as webloginkey.pem
        → ⚠️ Save this file securely — you cannot download it again!
        → Click "Launch Instances"
```

## 6. Connecting to an EC2 Instance via SSH (Linux/macOS)

### Problem: Unprotected Private Key File

When you first try to connect, you may see this error:

```
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
@         WARNING: UNPROTECTED PRIVATE KEY FILE!          @
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
Permissions 0644 for 'webloginkey.pem' are too open.
This private key will be ignored.
```

**Cause:** SSH requires that the private key file is readable **only by you** — not by group or others.

**Fix:**

```bash
chmod 400 webloginkey.pem
```

**Verify the fix:**

```bash
ls -l webloginkey.pem
# Expected output:
# -r--------@ 1 godfrey  staff  1678 Jun  8 21:06 webloginkey.pem
```

---

### SSH Connection Command

```bash
ssh -i webloginkey.pem ec2-user@<PUBLIC_IP>
```

**Example:**

```bash
ssh -i webloginkey.pem ec2-user@32.199.184.152
```

**Successful connection output:**

```
,     #_
~\_  ####_        Amazon Linux 2023
~~  \_#####\
~~     \###|
~~       \#/ ___   https://aws.amazon.com/linux/amazon-linux-2023
 ~~       V~' '->
  ~~~         /
   ~~._.   _/
       _/ _/
      _/m/'

[ec2-user@ip-172-31-23-229 ~]$
```

---

### Default Usernames by AMI Type

| AMI / OS | Default Username |

| Ubuntu | `ubuntu` |
| CentOS | `centos` |

## 7. Post-Login Verification Commands

Once logged in, run these commands to verify and explore your instance:

```bash
# Check who you are
whoami
# → ec2-user

# Switch to root
sudo -i
# Prompt changes to: [root@ip-172-31-23-229 ~]#

# Check OS version
cat /etc/os-release
# → NAME="Amazon Linux", VERSION="2023"

# Check public IP
curl ifconfig.me

# Check disk usage
df -h

# Check memory usage
free -h

# List running services
sudo systemctl list-units --type=service --state=running

# Update all packages
sudo dnf update -y

# Exit the instance
exit
```

## 8. Verifying a Web Server (Apache/httpd)

If Apache is installed on the instance, verify it is running:

```bash
# Check Apache service status
systemctl status httpd
# → Active: active (running)

# Test locally with curl
curl http://127.0.0.1
# → Returns: <html>...<p>It works!</p>...</html>

# Check running Apache processes
ps -ef | grep http

# Confirm Apache is listening on port 80
ss -tunlp | grep 3585
# → tcp LISTEN 0 511 *:80 *:*
```

**To test from the internet:**

```bash
# From your local machine (not SSH session)
curl http://32.199.184.152
# Or open http://32.199.184.152 in a browser
```

**If the site is not reachable from outside:**
Check the EC2 Security Group inbound rules — port 80 (HTTP) must allow `0.0.0.0/0`:

| Type | Protocol | Port | Source |
|---|---|---|---|
| HTTP | TCP | 80 | 0.0.0.0/0 |
| SSH | TCP | 22 | Your IP or 0.0.0.0/0 |
