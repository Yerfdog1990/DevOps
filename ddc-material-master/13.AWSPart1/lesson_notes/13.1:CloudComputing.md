## 1. Understanding Cloud Computing — From Scratch

### Start With a Data Center

Imagine a **data center** with hundreds or even thousands of computers and servers all running together — providing compute resources to an organization or its branches.

Now imagine those computers are **virtualized** — hypervisors are installed on them. A **virtualization team** creates virtual machines (VMs) and allocates them to the right individuals.

![img.png](img.png)

> The bigger the company, the **more administration** is required for the virtualized platform.

---

### Enter Cloud Computing

Cloud computing is essentially the **same virtualized platform**, but instead of contacting a team, you have:

- A **self-help portal** (website)
- A **command line**
- An **API**

...to access those virtual resources yourself, from anywhere.

![img_1.png](img_1.png)

> **Cloud Computing = Accessing your virtualized resources over the network — anytime, anywhere, through a self-service portal or API.**

---

## 2. Formal Definition

> **Cloud computing** is the **on-demand delivery** of compute power, database storage, applications, and other IT resources through a cloud services platform via the internet with **pay-as-you-go pricing**.

**Key aspects:**
- **On-demand** — get what you need, when you need it
- **Via the internet** — accessible from anywhere
- **Pay-as-you-go** — only pay for what you use; no upfront hardware procurement needed

---

## 3. Types of Cloud — Private, Public, Hybrid

![img_2.png](img_2.png)

### Private Cloud
- Cloud infrastructure provisioned for **exclusive use by a single organization**
- May be owned, managed, and operated by the organization itself, a third party, or a combination
- Can exist **on or off premises**
- Example: An organization sets up its own virtualized portal for internal employees only

### Public Cloud
- Cloud infrastructure provisioned for **open use by the general public**
- Anyone can sign up — just provide card details
- Owned, managed, and operated by a business, academic, or government organization
- **Exists on the premises of the cloud provider**
- Major examples: **AWS, Microsoft Azure, Google Cloud**

### Hybrid Cloud
- A **composition of two or more** distinct cloud infrastructures (private, community, or public)
- Each remains a unique entity but is **bound together by standardized or proprietary technology**
- Enables **data and application portability**
- Example: Cloud bursting — using public cloud to handle overflow load from a private cloud

### Summary Table

| Type | Who Can Use It | Managed By | Location |
|---|---|---|---|
| **Private** | Single organization only | Organization / third party / both | On or off premises |
| **Public** | General public | Cloud provider (AWS, Azure, GCP) | Cloud provider's premises |
| **Hybrid** | Organization (mixed use) | Both sides + integration layer | Across both environments |

## 5. Benefits of Cloud Computing

### Agility
- Very **easy and quick to get started**
- Just sign up with your card details and start creating compute resources immediately
- No waiting for hardware procurement, setup, or configuration

### Elasticity
- **Grow or shrink** your resources whenever you want, by however much you need
- Scale up for traffic spikes; scale down when demand drops
- No wasted resource sitting idle

### Cost Savings
- Since you can grow and shrink on demand, you also have **full control over cost**
- No large upfront capital investment in hardware
- Pay only for what you actually consume

### Go Global in Minutes
- One of the **most underrated benefits**
- Cloud providers like AWS have **global data centers** (regions and availability zones)
- You can deploy your application closer to your global audience in minutes — not months

### Additional Advantages

| Advantage | Description |
|---|---|
| **Easy Implementation** | Retain same apps and processes without dealing with backend technicalities |
| **Accessibility** | Access data anywhere, anytime — maximizes productivity and collaboration |
| **No Hardware Required** | No need for a physical storage center; everything hosted in the cloud |
| **Cost Per Head** | Overhead technology costs are minimized — free up resources for growth |
| **Flexible Growth** | Easily scalable — the system grows with the company |
| **Efficient Recovery** | Faster and more accurate retrieval of apps and data; minimal downtime |

---

## 6. Disadvantages of Cloud Computing

| Disadvantage | Description |
|---|---|
| **Loss of Control** | You hand over data to the provider; in-house IT staff may lose ability to handle issues independently |
| **Limited Features** | Some providers offer limited versions — not all features or customizations may be available |
| **Servers Still Needed** | You may have fewer servers to manage, but you can't eliminate all servers and staff entirely |
| **No Built-in Redundancy** | A cloud server is not automatically backed up — requires purchasing a separate redundancy plan |
| **Bandwidth Issues** | Packing too many resources into a small set of data centers can cause performance bottlenecks |

## 7. Cloud Service Models

Cloud computing services are delivered in three main models:

![img_3.png](img_3.png)

---

### 7.1 Infrastructure as a Service (IaaS)

- Provides the **basic building blocks** for cloud IT
- Access to: **networking features, virtual/dedicated computers, data storage**
- Gives the **highest level of flexibility and management control** over IT resources
- Most similar to traditional on-premises IT resources
- You manage: the **operating system** and everything above it
- Provider manages: the physical hardware and virtualization layer

**AWS Example:** **EC2 (Elastic Compute Cloud)**
- You create a virtual machine
- You choose the OS, configure it, manage it
- AWS handles the physical server underneath

**Other Examples:** Microsoft Azure, Google Compute Engine, Joyent

---

### 7.2 Platform as a Service (PaaS)

- Removes the need to manage **underlying infrastructure** (hardware and OS)
- You focus only on the **deployment and management of your applications**
- No need to worry about: resource procurement, capacity planning, patching, software maintenance
- Provider manages: hardware, OS, runtime environment

**AWS Example:** **RDS (Relational Database Service)**
- You need an Oracle database → just select it in AWS RDS
- AWS provisions everything — no need to create or manage a VM
- You focus on using the database, not maintaining it

**Other Examples:** AWS Elastic Beanstalk

---

### 7.3 Software as a Service (SaaS)

- A **completed product** that is run and managed entirely by the service provider
- You only need to think about **how you will use the software** — nothing else
- No concern about: maintenance, infrastructure, feature additions, server management

**Example:** Web-based email (Gmail)
- Send and receive email without managing email servers, OS updates, or infrastructure

**Other Examples:** Google Apps, Salesforce, Workday, Concur, Citrix, Cisco WebEx

---

### Service Model Comparison

| Model | You Manage | Provider Manages | AWS Example |
|---|---|---|---|
| **IaaS** | OS, Runtime, Apps, Data | Virtualization, Hardware, Network | EC2 |
| **PaaS** | Apps, Data | OS, Runtime, Infrastructure | RDS, Elastic Beanstalk |
| **SaaS** | Just use the software | Everything | N/A (third-party) |

## 8. AWS and Cloud Computing

AWS (Amazon Web Services) is the **leading provider of public cloud infrastructure**, and the platform used throughout this DevOps course.

### AWS Definition of Cloud Computing
> **On-demand delivery of IT resources over the internet with pay-as-you-go pricing.**

### Why AWS?
- No need to procure hardware
- Access any **computing power, storage, or databases** instantly
- Global infrastructure across multiple **regions and availability zones**
- All three service models available: IaaS (EC2), PaaS (RDS), SaaS
