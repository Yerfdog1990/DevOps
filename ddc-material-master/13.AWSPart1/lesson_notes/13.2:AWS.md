## 1. What is AWS?

## 3. Regions

A **Region** is a separate, isolated geographic area where AWS hosts its cloud computing resources.

### Key Facts About Regions
- Each region is **completely isolated** from the others and **runs independently**
- When you deploy a service, you **select a region** — your data stays in that region's data centers
- Regions are identified by codes (e.g., `us-east-1`, `ap-south-1`)

### Why Regions Matter

| Use Case | How Regions Help |
|---|---|
| **Catering global audience** | Deploy in regions closer to your users for lower latency |
| **Compliance / Data Residency** | Keep data within a specific country for regulatory requirements |
| **Disaster Recovery** | Replicate infrastructure across regions (must be set up manually) |
| **Geographic Expansion** | Use AWS global infrastructure instead of building your own data centers |

> **Important:** AWS does **NOT** replicate resources across regions automatically. It is the end user's responsibility to set up replication.

## 4. Availability Zones (AZs)

An **Availability Zone (AZ)** is an isolated location inside a region, made up of **one or more physical data centers**.

### Key Facts About AZs
- Each region has a **minimum of 2 AZs** (some have up to 6)
- AZs are identified by appending a letter to the region code
    - Example: `us-east-1` (region) → AZs: `us-east-1b`, `us-east-1c`, `us-east-1d`
- AZs within a region are **physically separated** but connected by low-latency links
- A single AZ = **cluster of multiple data centers**

### AZs and High Availability

```
                    REGION (e.g., us-east-1)
          ┌──────────────────────────────────────┐
          │                                      │
   ┌──────┴──────┐              ┌────────────────┴────┐
   │    AZ - 1a  │              │      AZ - 1b        │
   │             │              │                     │
   │ [Web Server]│              │  [Web Server]       │
   │ [Web Server]│              │  [Web Server]       │
   └─────────────┘              └─────────────────────┘

If AZ-1a goes down → AZ-1b keeps the application running
```

**Best Practice:** Always **distribute resources across multiple AZs** within a region so your application stays available even if one AZ goes completely offline.

> **Note:** AWS provides the infrastructure, but it is **your responsibility** to design and distribute your applications for high availability across AZs.

### When Launching an Instance
- You can **select a specific AZ** for your virtual machine (instance)
- Or you can **let AWS choose** the AZ automatically
- Designing across multiple AZs ensures traffic is also **distributed** across zones

## 5. Other Infrastructure Components

### Local Zones
- New type of data centers that place **compute, storage, and database services closer to large populations** (big cities)
- Designed for workloads requiring very low latency for end users

### Points of Presence / Edge Locations
- **Small data centers** compared to full AZs
- Used by **Amazon CloudFront** (AWS's Content Delivery Network)
- **Cache frequently accessed data** close to end users for faster delivery

### Ground Stations
- AWS infrastructure for satellite communication and data processing

## 7. IAM — Identity and Access Management

### What is IAM?

> **AWS IAM** is a web service that enables AWS customers to **manage users and user permissions** in AWS.

- Centrally manage **users, security credentials** (access keys), and **permissions**
- Controls which AWS resources each user can access
- Targeted at organizations with multiple users or systems using AWS

---

### Creating an IAM User — Step by Step

```
Step 1: Login to AWS Console
        → Services → IAM

Step 2: Select Users → Add User → Enter Username

Step 3: Choose Access Type
        ┌─────────────────────────────────────────────┐
        │ Programmatic Access                         │
        │ → Key-based access for AWS CLI              │
        ├─────────────────────────────────────────────┤
        │ AWS Management Console Access               │
        │ → Web browser login                         │
        │ → Choose: Autogenerated or Custom Password  │
        └─────────────────────────────────────────────┘

Step 4: Click "Next: Permissions"
        → Attach a Policy to the user

Step 5: Choose/Create Policy
        → Example: AdministratorAccess (full admin rights)
        → By default, IAM users have NO permissions

Step 6: Complete creation
        → Download the .csv file
        → Contains: credentials + console login URL
```

### IAM Permissions — Key Points

- By default, **IAM users have NO permissions** — they cannot create or modify EC2 resources or use the EC2 API/Console/CLI
- Permissions are granted by **attaching policies** to users or groups
- A policy **allows or denies** users the ability to perform specified tasks on specified resources
- AWS provides **predefined policies** (e.g., AdministratorAccess, ReadOnlyAccess) or you can **create custom policies**

---

### Setting Up MFA (Multi-Factor Authentication)

> **MFA** adds an **extra layer of protection** on top of your username and password.

**How MFA works:**
1. User enters **username and password** (Factor 1 — what they know)
2. User enters an **authentication code** from their MFA device (Factor 2 — what they have)

**MFA can be enabled for:**
- Your **root AWS account**
- Individual **IAM users**
- Also used to **control access to AWS service APIs**

### Setting Up MFA — Step by Step

```
Step 1: Click on Username in IAM
Step 2: Click on "Assigned MFA Device"
Step 3: Download Google Authenticator on your smartphone
Step 4: Open Google Authenticator → tap the "+" symbol
Step 5: Scan the barcode shown in AWS console
Step 6: Enter Auth Code 1 (first code from the app)
Step 7: Enter Auth Code 2 (second code from the app)
Step 8: MFA is now enabled ✅
```

## 8. Choosing a Region for This Course

When working on a project, you either:
- Are **told which region** to use (based on compliance or company policy)
- Or **choose based on** geographic proximity to users

### Recommendation for the Course
- Use a **US-based region** (e.g., `us-east-1` — N. Virginia)

- The course uses **AWS Free Tier** mostly, but some services may go above free tier
