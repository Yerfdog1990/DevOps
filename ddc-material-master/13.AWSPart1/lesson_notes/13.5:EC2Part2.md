# EC2 Part 2 — IPs, Elastic IP, Network Interfaces, Volumes & Instance Settings

---

## 1. Public IP vs. Private IP

Every EC2 instance gets both a **private IP** and a **public IP** when launched.

| IP Type | Behavior | Persistence |
|---|---|---|
| **Private IP** | Used for internal communication within AWS | ✅ Static — stays the same for the life of the instance |
| **Public IP** | Used for internet access | ❌ Dynamic — released when instance is stopped; a new IP is assigned on restart |

### Why the Dynamic Public IP Matters

```
Instance running  → Public IP: 54.210.10.5
Instance stopped  → Public IP: GONE (released back to AWS pool)
Instance started  → Public IP: 54.210.18.9  ← DIFFERENT IP
```

> In most production scenarios, this is **not a problem** because access is routed through a **load balancer** or other services — not directly to the instance IP. But if you need a stable public IP, use an **Elastic IP**.

## 2. Elastic IP — Static Public IP

An **Elastic IP** is a **static public IP address** you reserve from AWS — it stays assigned to you until you explicitly release it.

### Key Facts

| Fact | Detail |
|---|---|
| **Type** | Static public IPv4 address |
| **Limit** | 5 per AWS account (request more via AWS Support) |
| **Cost** | Not free — charges apply (negligible but present) |
| **Persistence** | Remains assigned even when the instance is stopped |
| **Portability** | Can be moved between instances or network interfaces |

> ⚠️ Always **release Elastic IPs** when no longer needed. Unused Elastic IPs still incur charges.

### Allocating and Associating an Elastic IP

```
Step 1: EC2 Dashboard → Network & Security → Elastic IPs
Step 2: Click "Allocate Elastic IP address"
Step 3: Select Region → Click "Allocate"
        → You receive a unique public IP

Step 4: Select the Elastic IP → Actions → "Associate Elastic IP address"
Step 5: Choose:
        ├── Instance → Select your instance
        └── Network Interface → Select a specific NIC
Step 6: Click "Associate"
Step 7: Go back to your instance → Details → Refresh
        → Elastic IP is now shown as the Public IP
```

### Releasing an Elastic IP (Important — Avoids Charges)

```
EC2 Dashboard → Network & Security → Elastic IPs
→ Select the Elastic IP
→ Actions → "Release Elastic IP address"
→ Click "Release"
```

> When you terminate an instance, the Elastic IP is **NOT automatically released** — you must release it manually.

## 3. Network Interfaces

### What is a Network Interface?
Every EC2 instance has at least one **network interface (NIC)** — the virtual equivalent of a physical network adapter (like a Wi-Fi or Ethernet adapter on your computer).

> All networking properties of an instance — **private IP, public IP, security groups, and Elastic IP** — are attached to the **network interface**, not directly to the instance.

### Key Facts About Network Interfaces

| Property | Detail |
|---|---|
| **Default NIC** | Every instance has one primary NIC at **device index 0** |
| **Primary NIC** | Cannot be detached — required for the instance to function |
| **Multiple NICs** | An instance can have multiple network interfaces |
| **Per-NIC settings** | Each NIC can have its own private IP, public IP, security group(s), and Elastic IP |

### Viewing Network Interfaces

```
EC2 Console → Select Instance → Networking tab
→ Scroll down to see the attached network interface(s)
→ Shows: Interface ID, Private IP, Public IP, Security Groups

OR:

EC2 Dashboard → Network & Security → Network Interfaces
→ Lists all network interfaces with their instance associations
→ You can create additional NICs and attach them to instances
```

### Common Error — Cannot Detach Primary NIC

```
Error: "The network interface at device index 0 and networkCard index 0
        cannot be detached."
```

**Cause:** The primary network interface (device index 0) is system-required. Every EC2 instance must always have at least one primary NIC — it cannot be removed while the instance exists.

**Resolution:** You cannot detach the primary NIC. Only secondary network interfaces (device index 1, 2, etc.) can be attached and detached freely.

## 4. EBS Volumes

### What is an EBS Volume?
Every EC2 instance has a **root EBS volume** (virtual hard disk) attached to it — this is where the operating system and data are stored.

### Default Volume Sizes by AMI

| AMI Type | Default Volume Size |
|---|---|
| Most Linux AMIs | 8 GB |
| Some larger AMIs | 20 GB, 30 GB, or 120 GB |
| Windows AMIs | 30 GB |

### Viewing Volumes

```
EC2 Console → Select Instance → Storage tab
→ See Volume ID and size

OR:

EC2 Dashboard → Elastic Block Store → Volumes
→ Lists all volumes with:
   - Volume ID
   - Size
   - Instance ID (shows which instance it's attached to)
   - Tags (e.g., the Name tag from the instance)
```

## 6. Instance Actions & Settings

After selecting a running instance, click **Actions** to explore available settings:

### Instance Settings

#### Change Instance Type (Scale Up / Scale Down)
> Cloud computing is **elastic** — you can resize your instance without replacing it.

```
Step 1: Stop the instance first (Instance State → Stop)
Step 2: Actions → Instance Settings → Change Instance Type
Step 3: Select the new type from the dropdown
        → A comparison table shows vCPU, RAM, and cost side-by-side
        Example: t2.micro (1 GB RAM) → t2.small (2 GB RAM)
Step 4: Apply change
Step 5: Start the instance (Instance State → Start)
```

> ⚠️ Changing to a larger instance type incurs **higher hourly charges**. Always resize back to free-tier eligible types when done learning.

#### Termination Protection
- Prevents **accidental deletion** of the instance
- Enabling it causes a `terminate` action to fail with an error

```
Enable:  Actions → Instance Settings → Change Termination Protection → Check → Save
Disable: Actions → Instance Settings → Change Termination Protection → Uncheck → Save
```

> Best practice: **Enable termination protection on production instances** to prevent accidental deletion.

---

### Networking Actions

| Action | Description |
|---|---|
| **Attach Network Interface** | Add a secondary NIC to the instance |
| **Detach Network Interface** | Remove a secondary NIC (primary NIC cannot be detached) |
| **Disassociate Elastic IP** | Remove the static IP from the instance |
| **Manage IP Addresses** | Add/remove private or public IPs on the NIC |

---

### Security Actions

#### Change Security Groups
- You can **replace** or **add multiple security groups** to an instance at any time
- Changes take effect immediately — no restart required

```
Actions → Security → Change Security Groups
→ Add or remove security groups from the dropdown
→ Save
```

---

### Other Important Actions

| Action | Description |
|---|---|
| **Modify IAM Role** | Assign/change permissions for the instance to access other AWS services |
| **Create Image (AMI)** | Snapshot the instance into a reusable AMI template |
| **Get System Log** | View boot/system logs for troubleshooting startup failures |
| **Get Instance Screenshot** | View a "screenshot" of the virtual monitor — useful when SSH is unavailable |

> **System Log** and **Instance Screenshot** are particularly useful when an instance won't boot or SSH is unreachable — equivalent to plugging a monitor into a physical server.

## 7. Terminating an Instance (Cleanup)

### With Termination Protection Enabled

```
Actions → Terminate Instance
→ Error: "The instance may not be terminated. Modify its
          'disableApiTermination' instance attribute and try again."
```

**Fix — Disable termination protection first:**

```
Step 1: Actions → Instance Settings → Change Termination Protection
Step 2: Uncheck "Enable" → Save
Step 3: Actions → Terminate Instance → Terminate → Confirm
```

### After Termination

- Instance moves to **terminated** state
- Terminated instance info is visible for **~2 hours**, then disappears
- ⚠️ Termination is **permanent** — it cannot be undone
- ⚠️ Any **Elastic IP** attached must be **released separately** — it is NOT automatically released

## 8. Complete Resource Cleanup Checklist

After finishing an exercise or project, always clean up:

```
Cleanup Checklist
├── ✅ Terminate EC2 instances
│       Actions → Terminate Instance
│       (Disable termination protection first if enabled)
│
├── ✅ Release Elastic IPs
│       Network & Security → Elastic IPs
│       → Select → Actions → Release Elastic IP address
│
├── ✅ Delete unused Key Pairs (optional)
│       Network & Security → Key Pairs → Delete
│
├── ✅ Delete unused Security Groups (optional)
│       Network & Security → Security Groups → Delete
│       (May need to detach network interfaces first)
│
└── ✅ Delete unused EBS Volumes (optional)
        Elastic Block Store → Volumes → Delete
        (Root volume is auto-deleted when instance terminates if
         "Delete on Termination" is enabled — check this at launch)
```
