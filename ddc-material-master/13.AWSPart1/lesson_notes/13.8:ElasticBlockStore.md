# AWS Elastic Block Store 

---

## What is EBS?

**Amazon Elastic Block Store (EBS)** provides persistent block storage volumes for EC2 instances — essentially virtual hard disks in the cloud. Think of an EBS volume the same way you think of a physical hard drive attached to a computer.

EBS gives you two main things:
- **EBS Volumes** — the virtual hard disk itself
- **Snapshots** — point-in-time backups of a volume

Key characteristics:
- Block-based storage (like a physical hard disk)
- Used to store the EC2 operating system (root volume) and application data
- Automatically replicated **within the same Availability Zone** for durability
- Can be attached, detached, and re-attached to instances
- Data persists independently of the instance lifecycle

> **Important:** EBS volumes cannot be directly copied across AWS regions. To use a volume in another region, you must create a snapshot and restore it there.

---

## EBS Volume Types

| Type | Technology | Use Case | Performance |
|---|---|---|---|
| **General Purpose (gp3 / gp2)** | SSD | Most workloads — web servers, dev environments, boot volumes | gp2: up to 16,000 IOPS; gp3: configurable |
| **Provisioned IOPS (io1 / io2)** | SSD | Large databases requiring consistent high performance | Up to 64,000 IOPS |
| **Throughput Optimized (st1)** | HDD | Big data, data warehouses, log processing | High throughput, sequential reads |
| **Cold HDD (sc1)** | HDD | Infrequently accessed data, file servers | Low cost, low IOPS |
| **Magnetic (Standard)** | Magnetic | Backups, archives — lowest cost | ~100 IOPS average, max 1 TB |

**AWS recommendation:** Use **General Purpose (gp3)** for most workloads — it offers the best balance of price and performance. Only choose other types when you have a specific requirement for very high IOPS (databases) or very low cost (archives).

---

## EBS Features

- **High Performance** — consistent, low-latency storage
- **High Availability** — automatically replicated within the Availability Zone
- **Encryption** — data at rest can be encrypted using AWS default keys or custom KMS keys
- **Snapshots** — backup the entire volume at any point in time
- **Elastic Volumes** — resize volumes or change type without stopping the instance
- **Access Management** — control who can create, attach, and manage volumes via IAM

> **KMS Keys Note:** The default AWS encryption key is free. Custom KMS keys have a monthly cost.

## Lab — Adding a 5 GB EBS Volume for Web Server Images

### Requirement

Host a web server on an EC2 instance. Store website images in a **separate 5 GB EBS volume** mounted at `/var/www/html/images`.

---

### Step 1 — Launch the EC2 Instance

Launch an Amazon Linux 2023 instance with a user data script that installs Apache and deploys a website:

```bash
#!/bin/bash
yum update -y
yum install -y httpd wget unzip

systemctl start httpd
systemctl enable httpd

cd /tmp
wget https://www.tooplate.com/zip-templates/2119_gymso_fitness.zip
unzip -o 2119_gymso_fitness.zip
cp -r 2119_gymso_fitness/* /var/www/html/
chown -R apache:apache /var/www/html
systemctl restart httpd
```

After launch, verify Apache is running:

```bash
sudo -i
systemctl status httpd
```

Check website files:

```bash
ls /var/www/html
ls /var/www/html/images
```

Check current disk layout:

```bash
fdisk -l
df -h
```

At this point you'll see only one disk (`/dev/xvda` — the 8 GB root volume):

```
Disk /dev/xvda: 8 GiB
  /dev/xvda1    8G  Linux filesystem
  /dev/xvda127  1M  BIOS boot
  /dev/xvda128 10M  EFI System
```

```
/dev/xvda1   8.0G  1.7G  6.3G  21%  /
```

---

### Step 2 — Create a New EBS Volume in AWS Console

1. Go to **EC2 → Volumes → Create Volume**
2. Set the configuration:
    - **Volume type:** gp3 (General Purpose SSD)
    - **Size:** 5 GB
    - **Availability Zone:** must match your instance's AZ (check under Instances → your instance)
3. Add a meaningful **Name tag** (e.g. `web01-dev-images-vol`)
4. Click **Create Volume**

The volume will show as **Available** (not attached to anything yet).

> **AZ matching is critical.** If your instance is in `us-east-1c`, the volume must also be in `us-east-1c`. A volume in a different AZ cannot be attached.

---

### Step 3 — Attach the Volume to the Instance

1. Select the new volume → **Actions → Attach Volume**
2. Select your instance from the dropdown
3. Set the device name (e.g. `/dev/sdf` — Linux will rename it to `/dev/xvdf` automatically)
4. Click **Attach Volume**

Volume state changes from **Available** to **In-use**.

---

### Step 4 — Verify the Volume is Visible in Linux

SSH into the instance and check:

```bash
fdisk -l
```

You should now see both disks:

```
Disk /dev/xvda: 8 GiB    ← root volume (existing)
Disk /dev/xvdf: 5 GiB    ← new volume (just attached)
```

Or use `lsblk` for a cleaner view:

```bash
lsblk
```

```
NAME    MAJ:MIN  SIZE TYPE MOUNTPOINT
xvda    202:0      8G disk
└─xvda1 202:1      8G part /
xvdf    202:80     5G disk          ← attached but no partition yet
```

---

### Step 5 — Create a Partition with `fdisk`

```bash
fdisk /dev/xvdf
```

Inside the fdisk utility:

| Command | Action |
|---|---|
| `m` | Show help menu |
| `p` | Print current partition table |
| `n` | Add a new partition |
| `w` | Write changes and exit |
| `q` | Quit without saving |

**Create the partition:**

```
Command (m for help): n
Partition type: p (primary)
Partition number: 1
First sector: [press Enter — accept default]
Last sector: [press Enter — use entire disk]
Command (m for help): w
```

> **Common mistake:** Do not type `c` or `w` at the "Last sector" prompt. Those are fdisk commands, not sector values. Just press **Enter** to use the entire disk.

Verify partition was created:

```bash
fdisk -l /dev/xvdf
```

```
Device     Boot  Start      End  Sectors Size Id Type
/dev/xvdf1        2048 10485759 10483712   5G 83 Linux
```

---

### Step 6 — Format the Partition

The new partition is raw — it has no filesystem. Format it with **ext4**:

```bash
mkfs.ext4 /dev/xvdf1
```

Output confirms success:

```
Creating filesystem with 1310464 4k blocks and 327680 inodes
Filesystem UUID: ca9849cf-1de3-4af5-9eca-2639f06381c0
```

> **Important:** Format `/dev/xvdf1` (the partition), not `/dev/xvdf` (the whole disk). Formatting the whole disk when a partition table exists will prompt a warning and should be answered **N**.

**Filesystem types:**

| Type | Best for |
|---|---|
| `ext4` | General purpose Linux filesystems |
| `xfs` | Large volumes, high performance (used by root in Amazon Linux) |
| `vfat` | USB drives, cross-platform compatibility |

---

### Step 7 — Back Up Existing Images Before Mounting

Mounting a filesystem on a directory that already has files will hide those files (they still exist on the root volume, but become inaccessible while the mount is active). Move them first:

```bash
mkdir /tmp/img-backup
mv /var/www/html/images/* /tmp/img-backup/
ls /var/www/html/images/    # should be empty
```

---

### Step 8 — Mount the Volume (Temporary)

```bash
mount /dev/xvdf1 /var/www/html/images/
```

Verify the mount:

```bash
df -h
```

```
/dev/xvdf1   4.9G   24K  4.6G   1%  /var/www/html/images
```

The new 5 GB volume is now mounted on the images directory.

---

### Step 9 — Restore Images to the New Volume

```bash
mv /tmp/img-backup/* /var/www/html/images/
ls /var/www/html/images/    # should show: class  hero-bg.jpg  team
systemctl restart httpd
```

Open the website in a browser — all images should load correctly, now served from the new EBS volume.

---

### Step 10 — Make the Mount Permanent (`/etc/fstab`)

The mount from Step 8 is temporary — it will be lost after reboot. To make it permanent, add an entry to `/etc/fstab`.

**Find the UUID of the partition** (recommended — more reliable than device name):

```bash
blkid /dev/xvdf1
```

```
/dev/xvdf1: UUID="ca9849cf-1de3-4af5-9eca-2639f06381c0" TYPE="ext4"
```

**Edit `/etc/fstab`:**

```bash
vi /etc/fstab
```

Add this line at the bottom:

```
UUID=ca9849cf-1de3-4af5-9eca-2639f06381c0   /var/www/html/images   ext4   defaults,nofail   0 2
```

Your complete `/etc/fstab` should look like:

```
UUID=5b3a24a5-c9d3-4d32-bb03-a87204afcc22   /              xfs    defaults,noatime                                                             1 1
UUID=3AA3-AF31                              /boot/efi      vfat   defaults,noatime,uid=0,gid=0,umask=0077,shortname=winnt,x-systemd.automount  0 2
UUID=ca9849cf-1de3-4af5-9eca-2639f06381c0   /var/www/html/images  ext4   defaults,nofail                                                      0 2
```

**Test the fstab entry without rebooting:**

```bash
umount /var/www/html/images
mount -a
df -h
```

You should see `/dev/xvdf1` mounted again. If `mount -a` returns no errors, the configuration is correct.

**fstab column guide:**

| Column | Value | Meaning |
|---|---|---|
| 1 | UUID=... | Identifies the filesystem |
| 2 | `/var/www/html/images` | Mount point directory |
| 3 | `ext4` | Filesystem type |
| 4 | `defaults,nofail` | Mount options — `nofail` prevents boot failure if volume is missing |
| 5 | `0` | Dump — 0 means disabled |
| 6 | `2` | fsck order — 2 means check after root filesystem |

> **Why use UUID instead of `/dev/xvdf1`?** Device names like `/dev/xvdf` can change after a reboot if multiple volumes are attached. UUIDs are stable and always point to the correct filesystem.

---

### Step 11 — Verify After Reboot

```bash
reboot
```

After reconnecting:

```bash
df -h
ls /var/www/html/images
```

Expected output:

```
/dev/xvdf1   4.9G   ...   ...   ...  /var/www/html/images
```

```
class  hero-bg.jpg  team
```

## Common Issues and Fixes

### SSH Connection Timeout

**Error:**
```
ssh: connect to host 18.215.178.243 port 22: Operation timed out
```

**Cause:** Your current IP address is not allowed in the Security Group inbound rules.

**Fix:**
1. Find your current public IP — search "what is my IP" in your browser
2. Go to **EC2 → Security Groups → select your group**
3. **Edit Inbound Rules → add or update the SSH rule:**
    - Type: SSH
    - Port: 22
    - Source: `your-current-ip/32`
4. Save — the fix takes effect immediately, no reboot required

> **Best practice:** Never use `0.0.0.0/0` for SSH. Always restrict to your specific IP address.

---

### Terminal Pastes `00~` or `01~` Before Commands

**Symptom:**
```
00~ssh -i web01.pem ec2-user@18.215.178.243
```

**Cause:** Your terminal has **bracketed paste mode** enabled. When you paste text, it wraps it in escape sequences (`00~` prefix and `01~` suffix) — these become part of the command.

**Fix (macOS Terminal or iTerm2):**
```bash
printf '\e[?2004l'
```
Or disable it permanently in your terminal settings.

**Workaround:** Type the command manually instead of pasting, or paste into a text editor first, clean it up, then paste into terminal.

---

### `fdisk n` says "All space for primary partitions is in use"

**Cause:** You accidentally wrote the partition table with only the prompts partially filled, but the partition already exists.

**Fix:** Type `p` to print and verify the partition exists, then `w` to save and exit. If the partition is correct, proceed to formatting. No need to run `fdisk` again.

---

### `mkfs.ext4 /dev/xvdf` Warns About Partition Table

**Symptom:**
```
Found a dos partition table in /dev/xvdf
Proceed anyway? (y,N)
```

**Cause:** You ran `mkfs` on the whole disk (`/dev/xvdf`) instead of the partition (`/dev/xvdf1`).

**Fix:** Answer `N` and run the correct command:

```bash
mkfs.ext4 /dev/xvdf1
```

---

### Volume Not Showing in `df -h` After Editing `fstab`

**Cause:** Adding a line to `/etc/fstab` doesn't automatically mount it — it only mounts on boot or when `mount -a` is run.

**Fix:**
```bash
mount -a
df -h
```

If `mount -a` gives no errors, the volume is now mounted and will survive reboots.

---

### `unmount` Command Not Found

**Cause:** The correct command is `umount`, not `unmount`.

```bash
# ❌ Wrong
unmount /var/www/html/images

# ✅ Correct
umount /var/www/html/images
```

---

### Volume Not Available After Reboot

**Cause:** The `/etc/fstab` entry has a typo (e.g. `UUiID` instead of `UUID`) or the UUID doesn't match the actual partition.

**Diagnosis:**
```bash
blkid /dev/xvdf1          # get the actual UUID
cat /etc/fstab            # verify the UUID matches
mount -a                  # test the fstab without rebooting
```

## Complete Command Reference

```bash
# Check disk and partition layout
fdisk -l
lsblk

# Check mounted filesystems and usage
df -h

# Create partition on new disk
fdisk /dev/xvdf

# Format partition as ext4
mkfs.ext4 /dev/xvdf1

# Get UUID of a partition
blkid /dev/xvdf1

# Mount temporarily
mount /dev/xvdf1 /var/www/html/images

# Unmount
umount /var/www/html/images

# Apply all /etc/fstab entries
mount -a

# Edit fstab for permanent mounts
vi /etc/fstab
```

## Summary

- An **EBS volume** is a virtual hard disk for EC2 — block-based, persistent, and AZ-specific
- EBS provides **volumes** (storage) and **snapshots** (backups)
- The **volume and instance must be in the same Availability Zone** to attach
- Use **gp3** (General Purpose SSD) for most workloads; choose provisioned IOPS for large databases
- The full workflow to add a new EBS volume: **Create → Attach → Partition → Format → Mount → Make Permanent**
- Always use **UUID** in `/etc/fstab` instead of device names — device names can change after reboots
- Add `nofail` to fstab options to prevent the instance from failing to boot if the volume is unavailable
- SSH timeouts are usually caused by **Security Group rules** blocking your current IP — update the inbound rule with your current IP
- `mount -a` reads and applies all `/etc/fstab` entries without rebooting — use it to test your fstab configuration
